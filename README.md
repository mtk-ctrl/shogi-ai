# 将棋AI開発

自作の将棋AIを、仕組みを理解しながら段階的に強化していくプロジェクトです。

## 目的

- 将棋AIが「局面を評価し、探索し、1手を決める」仕組みを実装を通じて理解する。
- 弱いAIから始め、改良ごとに対局結果を検証しながら強化する。
- ChatGPTを開発担当として最大限活用し、人にしかできない判断・実機操作・評価に人の作業を集中する。
- コードだけでなく「なぜその変更をしたか」「どの程度強くなったか」を記録し、後から読み返せる開発史を残す。

## 正本と保存方針

このプロジェクトの正本は **GitHub（このリポジトリ）** とする。

- ソースコード・設計・開発史：GitHub
- 小規模な棋譜・テストデータ：GitHub
- Google Drive：原則使用しない
- 大量の自己対局データや学習済みモデルは必要になった時点で別保存先を検討する

## 現在地

2026-10-05：**v0.0.19。通常`go`へ1～3手の攻守詰み補助を導入。自分の強制詰みを即決し、相手の短い強制詰みを許すroot候補を除外する。**

**v0.0.19通常仕上げ。** 時間制限付き通常`go`の総予算内で1～3手詰みを攻守とも確認する。50ms・200局のMateAssist ON/OFF比較は109勝85敗6分、得点率56.0%、違法手0。固定深度・nodes・ponder・infiniteは従来経路を維持する。5手・7手の通常対局組込みとAndroid/APKは今回の対象外。

- ルール層：やねうら王の合法手・局面管理・千日手等だけを使用
- 自作探索：可変深度αβ＋反復深化＋静止探索＋move ordering＋自作置換表
- 通常探索の末端で駒取り・成りを追加探索。王手中は玉移動・合駒を含む全応手を読む。非王手では追加8-plyを上限とする
- 静止探索は標準ON。`Quiescence=false`でv0.0.14と同じ固定末端評価へ戻せる。OFF時の同一49局面で手・評価値が全一致
- 同じCPU・1手50msでは得点率60%。固定深さ3では探索nodesが約24.1倍に増えるため、時間制限を明示して使う。棋力の評価は今回の短時間条件に限る
- 完了した各深さの評価値・詰み手数・読み筋をUSI出力。初回の探索が未完了なら合法手だけを返す
- movetime・残時間/秒読み・nodes・depthを実際に処理。思考中でもisready/stop/ponderhit/quitに応答
- 時間指定のないgoは既定3-ply。時計指定があれば予算内で最大64-plyまで反復深化
- 自作評価：駒得＋玉の守備＋攻撃圧力＋活動性＋駒の危険度
- 評価重みは **Safety=50 / Pressure=150 / Activity=150 / Danger=200**
- v0.0.13の採用試験では、c03対c07は **49勝51敗**でほぼ互角。旧重み100/100/100との100局ではc03が **62勝0分38敗、違法手0**
- 同採用試験でのc03の対旧重みnodesは **39,358,951 対 37,771,059（+4.2%）**、同一run内の平均応答は **114.737ms 対 120.427ms（約4.7%短縮）**。棋力がほぼ同等のc07より効率面を優先して採用
- move orderingは、TT/Experienceの既知手を除く通常ヒューリスティックで **王手 → 駒取り・取られそうな駒の退避・相手駒へ次の取りをかける手 → 成り → 静かな手** を優先
- 「取られそう」は飛車・角だけでなく全駒の利きで判定し、局面ごとの利き情報を再利用して判定コストを抑える
- v0.0.11との100局では **54勝46敗、違法手0**。探索nodesは約5.8%減少
- 同一10局の軽量化後比較では **2,922,325 nodes 対 3,345,756 nodes（約12.7%減）**、平均応答 **108.97ms 対 118.57ms（約8.1%短縮）**
- 歩・角・飛車のroot候補は成りを優先。銀・桂・香の不成、相手の合法な不成は維持
- 静止探索ONではスコア用TTは履歴を含むキーに統一し、静止探索内のスコアはTTへ保存しない。OFF時のみ従来の安全な浅い盤面共有を使う
- **Experience Cacheは標準ON**。前回以前に読んだ局面の最善手をmove-orderingヒントとして再利用する
- Experience Cacheは `usinewgame` をまたいで保持し、`shogi-ai-experience.bin` へ保存してエンジン再起動後にも再利用する
- 過去の評価値やBoundはまだ探索打切りに使わず、合法な手の読む順番だけへ利用する安全版
- 評価設定が変われば古いcacheを破棄し、千日手履歴がある局面では利用しない
- v0.0.11導入時の同一局面のwarm再探索で **nodes 52.3%削減・時間51.2%短縮**。20局の実戦形ON/OFF比較でも **nodes 23.3%削減、違法手0**
- 自動対局・評価ベンチは再現性のためExperience Cacheを標準OFFにし、cache効果を測る試験だけ明示的にONにする
- CIは、通常のコードpushで常時走るのは **Quick Strategy CI**。`Kifu Learning CI`は棋譜学習関連パスが変わった場合だけ自動実行する。旧採用版との対局、Experience Cache専用試験、Android/APK/Sanitizerは必要なときだけ手動実行する。
- v0.0.14は旧版との同一49局面で選択手が全一致。固定3-plyの応答コストは約25%増だが、初期局面100ms指定で4-ply完了・約90ms応答を確認。棋力向上は今後の時間制限付き比較で測る
- 静止探索の非王手orderingを軽量化。同一24局面のdepth 2で選択手24/24一致、nodes約57.7%減・応答時間約52.9%短縮。同じ50msの100局で **65勝20敗15分、得点率72.5%、違法手0**。
- 思考時間比較では、軽量化前v0.0.15で100msが50ms、250msが100ms、500msが250msにそれぞれ勝ち越し。少なくとも500msまでは追加の思考時間に棋力上の価値がある。秒単位の最適値は未確認。
- v0.0.16で自作の詰み専用探索を追加。攻め側は王手だけ、受け側は王手を外す全合法応手を読み、1・3・5手詰めを扱う。`go mate`から利用できる。
- v0.0.15軽量版の100局棋譜から、独立python-shogi探索で厳密な5手詰めを抽出し、1/3手では詰まないことと5手で詰むことを固定回帰テストにした。
- v0.0.19では1～3手の詰み探索をMateAssistとして時間制限付き通常`go`へ統合済み。5手・7手の通常対局への組込みは未採用で、条件付き導入を50ms比較で検討する。戦略比較は原則50msを使い、長時間化は500msまでは強くなる傾向を別記録として保持する。
- v0.0.17で詰み探索を軽量化。同一CPU・固定100問で3手中央値30.485ms→1.609ms（約18.95倍）、5手360.548ms→17.270ms（約20.88倍）。nodes中央値は同じ。
- 固定1,000問では3手・5手とも2秒以内に1,000/1,000局面でラベル手数以内の詰みを証明。3手中央値約1.500ms、5手約17.297ms。
- v0.0.18ではルール層からopaqueな`GeneratedMove`を受け取り、同じ局面の生成済み合法手を文字列化・再検索せず直接着手する。局面hashで古いtokenの誤使用を拒否する。
- 同一runnerの固定各1,000問では、v0.0.17比で3手中央値1.933ms→0.232ms（約8.34倍）、5手22.239ms→1.354ms（約16.43倍）。探索nodes中央値は3手26、5手352.5で不変。
- 7手へ探索上限を拡張し、固定100問を2秒上限で100/100正解・timeout 0。中央値8.663ms、平均27.724ms、p95 82.485ms、nodes中央値4,130。
- v0.0.19で時間制限付き通常`go`へ1～3手のMateAssistを導入。強制詰みを即決し、各root候補の着手後に相手の1～3手強制詰みが証明された候補を除外する。未証明・timeoutは除外しない。
- MateAssistの50ms・200局ON/OFF比較は **109勝85敗6分、得点率56.0%、違法手0**。呼出し13,218回の実測平均コストは約1.04ms。
- 次は詰み探索専用move ordering/TTで7手の裾を縮める。通常対局の5手・7手は終盤等の条件付きで攻守双方へ追加し、50ms比較で別途採否を決める。

## 当面の到達目標

1. 将棋ができる
2. 将棋らしく指せる
3. ユーザーに勝てる
4. 既存の将棋アプリに勝てる
5. 条件を固定したやねうら王に勝てる

v0.0.2で実機対局、v0.0.3で駒得、v0.0.4〜6で先読みとαβ、v0.0.7で手の並べ替え、v0.0.8で置換表、v0.0.9で成り方針、v0.0.10で説明可能な5本柱評価まで進んだ。v0.0.11では危険度200を採用し、過去の探索を次局・次回起動へ持ち越すExperience Cacheを導入した。v0.0.12では、王手の次に駒取り・危険駒の退避・相手駒への圧力を優先して読むことで、3-plyのままαβの枝刈り効率を改善した。v0.0.13ではSafety・Pressure・Activityを共同調整し、棋力と探索効率のバランスからc03（50/150/150/200）を採用した。v0.0.14では評価重みを維持し、評価値・読み筋の出力と、時間内で深く読む探索へ進んだ。v0.0.15では探索末端の駒取り・成り・王手回避を追加で読み、短い持ち時間でも取り返しを見落としにくくした。

実機で残る保存先はShogiDroid2/OEXの起動環境に依存するため、Pixelで実機確認する際に確認する。保存に失敗しても通常探索へ戻る設計なので、保存先の違いで対局不能にはならない。

## 開発の基本原則

1. 最初から最強AIを目指さず、仕組みが理解できる小さな実装から始める。
2. 一度に複数の要因を変えすぎず、何が効いたか分かるようにする。
3. 変更前後を同条件で自動対局し、強化を数字で確認する。
4. 人が手作業する必要のない部分はChatGPT・GitHub Actions等で自動化する。
5. 重要な判断、失敗、結果、次の仮説を `journal/` に残す。
