# v0.0.13：評価重み共同調整でc03を採用

2026-10-04、`EvalDanger=200` は固定したまま、残る `EvalSafety` / `EvalPressure` / `EvalActivity` を共同調整した。

## 最終候補

- c07：Safety=100 / Pressure=150 / Activity=200 / Danger=200
- c03：Safety=50 / Pressure=150 / Activity=150 / Danger=200

最終100局の直接対決（run `37199693903`）は、c07 51勝、c03 49勝、引き分け0、違法手0だった。棋力差はほぼ互角と扱う。

探索nodesは c07 26,056,595、c03 28,617,624 だったが、この比較は同一対局で両候補の局面系列が一致しないため、採用時の速度判断は各候補を同じ現行基準と対戦させた確認試験を重視した。

## 現行100/100/100との各100局確認

baselineは Safety=100 / Pressure=100 / Activity=100 / Danger=200。run `37199978761` で各候補を100局ずつ比較した。

| 候補 | 勝-分-敗 | 違法手 | 候補nodes / baseline | nodes差 | shard平均応答 候補 / baseline |
|---|---:|---:|---:|---:|---:|
| c07 | 63-1-36 | 0 | 40,802,226 / 35,315,617 | +15.5% | 104.591ms / 94.789ms |
| c03 | 62-0-38 | 0 | 39,358,951 / 37,771,059 | +4.2% | 114.737ms / 120.427ms |

GitHub-hosted runnerはshardごとにCPU条件が異なるため、c07の104.591msとc03の114.737msを直接比較しない。それぞれ同じrun内のbaselineとの比率を見る。

c07はbaselineより平均応答が約10.3%長く、nodesも15.5%増えた。一方c03はnodes増加を4.2%に抑えつつ、平均応答はbaselineより約4.7%短かった。

## 採用判断

c07とc03の直接対決は51-49でほぼ互角であり、現行基準に対する勝ち越しも63勝と62勝で大差がない。そこで棋力差を過大評価せず、探索効率が良いc03を正式採用する。

v0.0.13の標準評価重みは次のとおり。

- `EvalSafety=50`
- `EvalPressure=150`
- `EvalActivity=150`
- `EvalDanger=200`

評価重み以外の探索深さ、move ordering、TT、Experience Cacheの仕様はv0.0.12から変更しない。Android APK生成・Pixel/ShogiDroid2実機確認は通常仕上げには含めず、必要な節目で別途行う。

次の大きな探索強化は反復深化とする。
