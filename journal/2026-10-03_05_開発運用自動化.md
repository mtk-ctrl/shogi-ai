# 開発運用自動化・固定署名・自動対局

## 背景

戦略を少し変更するたびにPixelへAPKを入れ直し、ShogiDroid2で確認する運用では、今後の反復開発の負担が大きい。
そこで、日常的な比較はGitHub上で自動化し、Pixelでの実機確認は節目だけにする運用へ変更した。

## 固定署名

GitHub Actionsの通常debug署名は実行環境ごとに変わり得るため、Android側で上書き更新できない場合がある。
開発版だけはAndroid Open Source Projectの公開testkeyを特定コミットに固定して利用する。

- AOSP repository: `aosp-mirror/platform_build`
- revision: `045a3d6a3e359633a14853a5a5e1e4f2a11cbdae`
- certificate SHA-256: `A40DA80A59D170CAA950CF15C18C454D47A39B26989D8B640ECD745BA71BF5DC`
- 本番配布・Play Store公開には使用しない

鍵ファイルそのものは本リポジトリへ保存せず、CI時に固定コミットから取得し、証明書ハッシュを検証して一時的にPKCS12を生成する。

GitHub Actions run `37133036323` で、既存のルール・USI・境界・Sanitizer検証、Android ARM64ビルド、固定署名、署名証明書の照合、APK生成まで全て成功した。

生成物：`shogi-ai-v0.0.2-fixed-debug.apk`
Artifact ID：`11277398489`

従来版から固定署名版へ移る最初の1回だけは署名が異なるためアンインストールが必要である。
以後は同じApplication IDと固定署名を維持し、versionCodeを増やすことでAndroidの「更新」で上書きする。

## 自動対局ベンチマーク

`benchmarks/arena.py` を追加し、2つのUSIエンジンを自動対局させる仕組みを作成した。

- 先後を交互にする
- `python-shogi` で各着手の合法性を独立検証する
- 不正着手が1つでもあればCIを失敗させる
- 結果をJSONとテキストで保存する
- `benchmarks/baseline_ref.txt` に現在の比較基準コミットを固定する
- Push時は短い比較、必要時は手動実行で局数を増やす

ランダム戦略の比較を再現可能にするため、USIオプション `RandomSeed` を追加し、`usinewgame` でseedを再設定する。

GitHub Actions run `37133036452` で初回20局を完走した。

- 現行A：7勝
- 基準B：3勝
- 引分：10
- Aスコア：0.600
- 平均331.2手
- 違法手：0

現行版と基準版は実質的に同じランダム戦略であるため、この勝率は棋力向上の根拠として扱わない。
今回の意味は、自動対局・合法性検査・結果集計の一連が正常に動いたことの確認である。

## 今後の標準フロー

1. 戦略コードを変更する
2. ルール・USI・境界テストを自動実行する
3. 現在の採用版と新版を自動対局させる
4. 勝率、合法性、速度等を確認する
5. 採用・保留・撤回を判断する
6. 採用した節目版だけAPKを生成しPixelで実戦確認する
7. 人間は指し味・不自然な手など、自動評価しにくい部分を確認する

日常的な戦略開発でPixel操作を要求しない。実機確認は節目に限定する。
