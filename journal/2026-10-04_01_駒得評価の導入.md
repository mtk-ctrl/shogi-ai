# v0.0.3：駒得評価の導入

## 出発点と判断

オーナーから、固定署名版v0.0.2で約20手の実機対局が続いたとの報告を受けた。
README、開発方針、ロードマップ、ルール分離資料、開発運用、前回の記録を確認した。
実機で終局まで確認したとは扱わず、自動対局基盤を使ってPhase 2の駒価値へ進めると判断した。

仮説は「着手直後の駒得を比較するだけでもランダム版に勝ち越す」である。
先読み・位置評価・詰み探索を同時に入れず、この仮説だけを検証した。

## 変更

- 自作駒価値と評価関数を `engine/strategy/material.h` に追加
- 盤上と持ち駒を合算し、成り・取った成駒の不成化をルールAPI経由で反映
- 同点の手は既存のRandomSeed方針を維持して抽選
- ルール層、固定上流コミット、分離パッチは変更なし
- USI/OEX表示をv0.0.3、Android versionCodeを4に更新。署名とApplication IDは維持

比較プログラムも結果の検証に必要な範囲で改修した。旧版は連続王手の千日手を引分扱いし、
王手でない合法手なしも引分扱いしていた。また入玉宣言を無検証で受理していた。
これらを修正し、全棋譜・終局SFEN・seed・バイナリハッシュ・応答時間を保存するようにした。
比較対象は双方ともこの同じ判定方法で対局した。
旧基準のd8600b0はRandomSeed対応前だったため、今回の比較は対応後のbbce956に固定した。

## 100局の条件と結果

Linux x86_64、GCC 13.3.0、python-shogi 1.1.1。初期局面開始、先後50局ずつ、seed基点20261004。
各局400手で打切り。新版・旧版とも1手ごとの固定処理であり、厳密な持ち時間制ではない。
`go movetime 1` を送るが、時間超過負けにはしていない。停止監視は10秒。

| 項目 | 結果 |
|---|---:|
| 新版の勝ち | 92 |
| 新版の負け | 0 |
| 引分（400手打切り） | 8 |
| 新版が先手 | 45勝0敗5分 |
| 新版が後手 | 47勝0敗3分 |
| 勝率（勝ち数÷全局数） | 92% |
| 得点率（引分0.5点） | 96% |
| 違法手・不正宣言 | 0 |
| 平均手数 | 194.49 |
| 新版の平均応答時間 | 2.561ms |
| 旧版の平均応答時間 | 0.694ms |

勝因の内訳は詰み32局、王手ではない合法手なし60局。将棋では後者も指せない側の負けである。
時間は局面再現とUSI通信を含む、このホストでの測定でありPixelでの速度ではない。
全データは `benchmarks/results/2026-10-04_material-vs-random-100.json`。

## 検証

- 駒種・成駒・持ち駒、駒打ちで合計点が変わらないこと
- 先後とも角を歩より優先すること、USI本体にも新戦略が接続されていること
- 成り・不成のsearchmoves、同点抽選の再現性
- 候補評価後の盤面・手番・持ち駒・千日手履歴の復元
- 300手のUSI対局、ponder/stop/infinite、入力失敗後の復帰
- 上流の探索・評価・定跡等を取り込んでいないこと
- 対局判定側の詰み・4回目の同一局面・双方の連続王手・入玉の点数条件

ローカルのAddressSanitizer/UndefinedBehaviorSanitizerは成功。
この実行環境ではLeakSanitizerが `/proc` 読取り制限で終了したため、ローカルのみ漏れ検査を無効にして実行した。
CIの漏れ検査設定は変えず、通常のSanitizer検査を実行する。
ルール回帰（初期局面perft深さ1〜4、特殊ルール、10,537手の着手と全巻戻し）と独立実装との4,977局面照合も成功した。
保存した100局をルールコアへ全手再入力し、終局SFEN・勝敗判定がすべて一致することも確認した。
GitHub Actionsでも通常検証、戦略とルール双方のAddressSanitizer/UndefinedBehaviorSanitizer（漏れ検査を無効化せず実行）、Android ARM64ビルド、固定署名照合をすべて通過した。

## 採用判断と残る課題

100局でランダム版に明瞭な優位があり、Phase 2として採用する。
今回の値は最適化していない。持ち時間や対戦相手の違う棋力に一般化しない。
相手の取り返しはまだ読めず、飛車で毒歩を取る例はそのまま再現する。これを次の課題とする。

次は評価値を固定したまま、相手の応手まで読む2手minimaxと終局評価を追加する。
v0.0.3を比較基準として効果と速度を測定し、その後にαβで同じ答えを速く出す段階へ進む。
v0.0.3のPixel実機確認と実機での終局表示は未確認である。毎回のAPK導入を依頼せず、節目で指し味を確認する。
