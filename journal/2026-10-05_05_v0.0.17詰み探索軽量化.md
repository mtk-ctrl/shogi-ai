# v0.0.17 詰み探索軽量化

2026-10-05、v0.0.16で追加した1・3・5手詰め探索を、通常対局へ将来組み込める水準へ近づけるため軽量化した。同時に、やねうら王公式の大量詰将棋データから固定ベンチセットを作成した。

## 固定ベンチセット

やねうら王公式が公開する約500万局面のSFENから、3・5・7・9・11手を各1,000問、合計5,000問を固定抽出した。元ZIP約190MBは保存せず、抽出条件・元ZIPと各ファイルのSHA-256・seedを`benchmarks/tsume_dataset/manifest.json`へ残した。

抽出seedは`20261005`。今後、7/9/11手対応やDFPN等へ進んでも同じ問題を比較に使う。

## 重かった原因

v0.0.16の攻め側は、全合法手を生成し、静かな手も一度実際に指してから「王手か」を確認し、王手でなければundoしていた。詰み探索では攻め側は王手しか読む必要がないため、この処理が大きな無駄であった。

また、詰み探索が`legal_moves()`から得た手を`play()`へ渡すと、`play()`冒頭の`status()`が再び全合法手を生成して終局判定し、その後もう一度全合法手を走査して着手していた。

## 軽量化1：王手候補を着手前に絞る

ルール層へ`Position::checking_moves()`を追加した。やねうら王の合法手生成と`gives_check()`だけを利用して、合法かつ王手になる手だけをUSI文字列として戦略層へ返す。

戦略層はやねうら王のMove型を受け取らず、探索・評価ロジックも利用しないため、従来の「やねうら王はルール層だけ」という境界を維持している。

これにより、非王手を指して戻す処理を丸ごと削除した。

## 軽量化2：生成済み合法手の重複終局判定を省く

`Position::play_generated_legal()`を追加した。これは直前の`legal_moves()`または`checking_moves()`から得た手だけに使う内部高速経路である。

通常の`play()`は変更していない。高速経路でも全合法手から同じUSI手を照合する安全策は残し、`play()`冒頭の重複した`status()`走査だけを省いた。

一度、やねうら王の文字列→Move変換を直接使う案も試したが、`usi.cpp`側の実装をリンクする必要があり、ルール層だけを利用する現在の境界を広げるため採用しなかった。

## 同一CPU比較

GitHub Actions run `37247666278`で、旧v0.0.16 commit `1eb6b8ac...` と軽量版 commit `9c81e8e0...` を同じrunner上で比較した。各問題2秒上限、固定問題の先頭100問である。

### 3手詰め

- 旧：100/100、中央値30.485ms、p95 133.311ms、nodes中央値26
- 新：100/100、中央値1.609ms、p95 9.223ms、nodes中央値26
- 中央値で **約18.95倍高速**

nodes中央値が同じため、枝を恣意的に削ったのではなく、主に1局面あたりの無駄な処理を削った効果である。

### 5手詰め

- 旧：86/100、中央値360.548ms、p95 2000.228ms、nodes中央値345
- 新：100/100、中央値17.270ms、p95 302.351ms、nodes中央値345
- 中央値で **約20.88倍高速**

旧版で14問が2秒上限に達していたが、新版は100問すべて証明できた。

## 1,000問確認

各問題2秒上限で固定1,000問を確認した。

### 3手ラベル

- 指定手数以内に詰みを発見：1000/1000
- 3手で発見：999
- さらに短い詰み：1
- timeout：0
- 中央値：約1.500ms
- 平均：約2.437ms
- p95：約7.350ms

### 5手ラベル

- 指定手数以内に詰みを発見：1000/1000
- 5手で発見：998
- さらに短い詰み：2
- timeout：0
- 中央値：約17.297ms
- 平均：約48.822ms
- p95：約193.046ms

元データの説明ではN手集合はN-2手では詰まない生成条件とされているが、固定2,000問中3局面については自作エンジンだけでなく独立したpython-shogi 1.1.1探索でも同じ短い詰みを確認した（run `37247925516`）。このため、主指標は「ラベル手数以内に詰みを証明できた率」とし、指定手数ぴったりの件数は診断値として残す。

## 短時間予算

固定先頭100問で、軽量版に短い時間予算を与えた。

| 予算 | 3手ラベル | 5手ラベル |
|---:|---:|---:|
| 5ms | 87/100 | 20/100 |
| 10ms | 96/100 | 38/100 |
| 50ms | 100/100 | 74/100 |

3手詰めは通常対局中に数msの補助探索として使える可能性が高くなった。一方、5手詰めを毎手無条件に完全探索するのは、現在の通常探索50ms基準に対してまだ重い。5手は局面条件や残り時間を見て呼ぶ設計が妥当である。

## 通常探索への影響

今回、通常の`go`経路は変更していない。戦略比較は引き続き原則50msとし、`benchmarks/baseline_ref.txt`もv0.0.15軽量版のまま維持する。

したがって、v0.0.17では通常対局100局による棋力採用試験は行わない。次の通常対局への組込み時に、同じ50ms条件で旧版との対局を行う。

## 次

1. 通常探索へ1～3手詰めを数ms予算で補助的に組み込む候補を比較する
2. 5手詰めは「詰みの可能性が高い局面」のみ呼ぶ条件を検討する
3. 詰み専用のキャッシュや手順序を追加する
4. その後、固定7/9/11手問題で上限拡張を測る
5. 長手数で単純AND/OR探索の限界が来たら、自作DFPNへ進む
