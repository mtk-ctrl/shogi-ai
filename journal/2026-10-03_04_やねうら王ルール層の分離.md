# v0.0.2 やねうら王ルール層の分離

## 問題と目的

v0.0.1は毎回 `7g7f` を返す接続試験用実装で、二手目以降の対局ができなかった。
やねうら王のルールを利用し、思考部分を自作できる境界を作る。
オーナーの追加指示により、不成・千日手の処理も既存実装をそのまま借りる方針を確認した。

## 実装

- 上流の版と各使用ファイルのSHA-256を固定。
- 4つのC++実装からルール部分をビルドし、上流探索・評価・定跡・置換表をリンクしない。
- 上流との差分を条件付きコンパイルのパッチとして分離。
- 自作側に局面・合法手・指す・戻す・勝敗・入玉条件を提供。
- 履歴を含む複製と入力失敗時の局面保護を実装。
- ランダム選択を自作戦略の初期実装とし、USIから接続。
- Android OEXをv0.0.2に更新し、検証後にAPKを生成するCIへ変更。

設計と制限は `docs/07_ルール層の分離設計と検証.md` を参照。

## ローカル検証結果

| 確認 | 結果 |
|---|---|
| 初期局面からの全手順数 | 深さ1〜4：30、900、25,470、719,731に一致 |
| 代表的な特殊ルール | 不成、強制成り、二歩、行き所のない駒、打ち歩詰め、歩を動かす詰み、ピン、両王手を通過 |
| 局面更新 | 捕獲駒の成り解除、持ち駒、駒打ち、全手戻しを通過 |
| 千日手 | 4回出現のみ終局、20手周期の繰り返し、連続王手側の負け、複製・戻す時の履歴を通過 |
| 入玉・入力 | CSA27点宣言条件、不正入力時の局面保持を通過 |
| ランダム進行 | 固定seedで30局、合計10,537手を進め、全手を逆順に戻して各SFEN一致 |
| 独立実装との比較 | python-shogi 1.1.1と4,977局面で合法手集合・SFEN・王手判定が一致 |
| USI経由の連続着手 | 300手すべてを別実装で合法と確認 |
| 通信 | ponder・infinite・stop、searchmoves、入力エラー後の復帰を通過 |
| 分離境界 | 評価・探索・置換表・定跡・詰め探索・上流USI・null moveの実行シンボルなし |

メモリ・未定義動作検査にはAddressSanitizer/UndefinedBehaviorSanitizerを使用する。
ローカル環境はLeakSanitizerがプロセス情報を読めないため、ローカルだけリーク検査を無効化し、残りのAddressSanitizer/UndefinedBehaviorSanitizer検査は全て通過した。
GitHub Actionsではリーク検査を含む既定設定で再実行する。

## 判断と次の課題

ルール処理の独自再実装を避けた構成を採用する。全将棋局面の正しさを証明したものではなく、
代表ケース、広範な状態遷移、独立実装との比較で切り離しによる破損リスクを確認した。
強さの測定は未実施。今回の目的は、戦略を追加できる土台を作ることである。
Pixel/ShogiDroid2でのv0.0.2実機起動、千日手表示連携はまだ未確認。
次は自作の評価関数と探索を段階的に追加する。
