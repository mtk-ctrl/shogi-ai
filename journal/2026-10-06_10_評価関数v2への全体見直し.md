# 評価関数v2への全体見直し

## 発端

持ち駒の両取り・串刺し研究で、幾何的な手筋をmove orderingへ入れても400局で得点率51.625%に留まった。その後、相手の全合法応手を別途確認する「実効両取り」も試したが、200ms探索のnodesを大きく消費した。

議論を進める中で、個別手筋より上位の設計問題が明確になった。

**orderingで先に読ませても、時間内に利益実現まで読めなければ、葉局面の評価が駒得中心のままでは手筋の価値が最終判断に残らない。**

## 現行評価の構造上の確認

mainの`evaluation.h` / `evaluation_params.h` / `material.h`を確認した。

- Material: 歩100、香300、桂300、銀500、金600、角800、飛1000
- 非Material: Safety / Pressure / Activity / Danger
- 非Material合計は最後に`positional_cap=300`でclip

したがって、現在は多面的評価を実装済みではあるが、**非Materialの全価値を合わせても最大3歩分**という器になっている。

Influence branchとPotential Mobility branchも静的評価へ追加する正しい方向だが、同じglobal capの内側に入る。旧実験だけで「効き・潜在自由度に価値がない」とは結論できない。

一方、HandDropTactics branchの両取り・串刺しは静的評価を変更せずorderingのみであり、未実現のThreat価値そのものを測る実験にはなっていなかった。

## 新原則

1. 詰み・勝敗として証明できた結果だけを絶対優先する。
2. 非終局局面ではMaterialを含む各featureに恒久的な優先順位を置かず、重み付きで統合する。
3. 読みがそこで終了しても価値が残る概念は静的評価に持たせる。
4. move orderingは「どれを先に読むか」であり、局面評価の代用にしない。
5. qsearch・探索延長・AdaptiveLongThinkはhorizon対策であり、局面価値の代用にしない。
6. global positional cap 300を再検証する。
7. 過去のInfluence / Potential Mobility / HandDrop研究は破棄せず、v2で役割を正して再利用する。

## 次の順序

最初から多数のfeatureを同時実装しない。

1. 現行評価のcap飽和を計測する。
2. 現行4featureのままglobal capだけを300 / 450 / 600 / 実質無制限で比較する。
3. 両取り・串刺しを未実現`Threat`として静的評価へ追加する。
4. Influence / Potential Mobilityをv2統合器で再検証する。
5. Coordination、Hand Potential、Space等を順次追加する。
6. 固定weightが理解できた後で局面別weightへ進む。

検証は、feature unit test → horizon-retention → fixed-depth/node → 200ms AdaptiveLongThink OFF → 200ms正式条件ON → ablationの順を基本とする。

詳細は`docs/32_評価関数v2統合設計.md`を正本とする。
