# Book勝敗フィードバック学習

## 背景

やねうら王との正式棋力測定で、Book OFFのCoreは YaneuraOu Material Lv41（1,048 nodes）を100局得点率55.0%でClearした一方、gen3 Book ONではLv33（413 nodes）が最高Clearとなった。

Book自体には従来から `局面 × 指し手` ごとの勝・分・敗が保存されていたが、低勝率手への重み低下が弱く、例えば18局2勝16敗の手にも選択weight 212が残るなど、負けた定跡を十分に淘汰できていなかった。

Bookを捨てるのではなく、実際にBookを使った対局結果から弱い手を学習して改善する方式へ変更した。

## 実装

### 1. 実際にBookが選んだ手だけを記録

`benchmarks/book_feedback_arena.py` を追加した。

- A: 現行Book ON
- B: 同一エンジンのCore（Book OFF）
- Experience Cache: 両者OFF
- 同一50ms条件
- 先後交代
- `info string opening_book hit ...` を読み、Bookが実際に返した指し手だけを記録する

これにより、単に序盤で指された全手ではなく、Bookの意思決定にだけ勝敗を帰属できる。

### 2. ルール層で局面と勝敗を確定

`tools/book/extract_book_feedback.py` を追加した。

Bookヒットのあった棋譜と `game_id / ply / move` の対応を抽出し、既存の `tools/kifu/validate_games.cpp` で全棋譜を再生する。これにより各Book手について、

- Book手直前の `Position::hash_key()`
- 実際のBook手
- その手を指した側から見た最終結果（勝=1、分=0、負=-1）

をルール層から確定する。

### 3. 勝敗をBookへ戻す

`tools/book/apply_book_feedback.py` を追加した。

- 新しい実戦結果は既存統計より早く効くよう既定4倍で加算
- 得点率が低い手は選択weightを強く減衰
- 得点率が高い手はweightを増加
- 一晩の変動幅は通常 `0.50倍～1.35倍` に制限
- weight最低値は1として、弱い手も完全削除しない

弱い手を永久に捨てないのは、探索本体の強化後にその定跡の価値が変わった場合、低頻度の再探索から復活できる余地を残すためである。

### 4. Book再構築時も同じ重み付け

`tools/book/build_opening_book.py` も同じloss-awareな `quality_weight()` を利用するよう変更した。

今後大規模自己対局からBookを再構築しても、旧式の重み計算によって低勝率手が再び高頻度へ戻らない。

## CI

`.github/workflows/book-feedback-ci.yml` を追加した。

実行内容：

1. Python構文確認
2. 単体テスト `tests/test_book_feedback.py`
3. エンジン・棋譜validatorビルド
4. 4局Book-vs-Core実戦
5. Bookヒット抽出
6. ルール層再生
7. Book重み更新
8. 更新BookのUSI読込確認
9. Bookヒット件数と学習照合件数の完全一致確認

初回CI run `37300191107` は全工程成功した。

4局のsmoke testでは、

- Bookヒット: 4件
- 正常照合: 4件
- 未照合: 0
- 指し手不一致: 0
- 違法対局: 0
- 実際に更新されたBook項目: 3件

を確認した。

## 夜間自動学習

旧 `.github/workflows/nightly-self-play.yml` は廃止し、`.github/workflows/nightly-book-learning.yml` へ置き換えた。

従来と同じGitHub Actions枠の中で、単純なBook同士の自己対局ではなく、**Book ON対Core OFF** を回してBook改善へ直接利用する。

通常運用は、

- 04:47 JST開始
- 05:20 JSTまでBook-vs-Core対局
- 2レーン並列
- 対局後にBookヒット抽出・ルール検証・勝敗反映
- 違法0、20局以上、正しく照合できたBookヒット50件以上を自動更新の最低条件
- 実行途中にmainのBookが変わった場合は上書きしない

とした。

workflow変更時の短時間smoke run `37300407574` も全工程成功した。

結果：

- 70局
- Book 15勝 / 24分 / Core 31勝
- Book得点率 38.57%
- Bookヒット 270件
- 270/270件を正しく勝敗へ照合
- 未照合0
- 指し手不一致0
- 違法0
- 69個のBook項目を更新

この結果により、やねうら王戦だけでなく、同一探索本体を相手にした直接比較でも現行gen3 Bookが棋力を下げていることが確認できた。同時に、今回実装したフィードバック学習が低勝率手を実際に検出してweightを下げられることも確認できた。

例：

- `4g4f`: 今回10回、1勝2分7敗、最近得点率25.0%。weight 5,724 → 2,862
- `3c3d`: 今回19回、3勝8分8敗、最近得点率38.1%。weight 2,994 → 1,497
- `2h4h`: 今回4回、0勝0分4敗、最近得点率16.7%。weight 2,488 → 1,244

pushによるsmoke runではBookの自動昇格は行わず、候補生成・検証までとした。

## 既存統計のブートストラップ

現Bookが既に持っている過去W/D/Lも利用するため、`.github/workflows/book-reweight-bootstrap.yml` を追加した。

既存統計だけから全1,000 Book項目を新しいloss-aware式で再重み付けし、現Bookとの200局直接対決で得点率55%以上・違法0を満たした場合だけ自動採用する。基準を満たさなければ現Bookは変更せず、夜間のexact-hit学習だけを継続する。

## 方針

- Bookは捨てない。
- 「その序盤手が一般に良いか」ではなく、「自分の現在の探索本体と組み合わせて勝てたか」を学ぶ。
- 外部エンジンの評価値・PV・推奨手は教師にしない。
- やねうら王は引き続き外部棋力ベンチマークとして使い、Book改善後に同じ固定条件で再測定する。
- Bookの低勝率手は削除ではなく抑制し、将来の復活可能性を残す。
