# 2026-10-05 棋譜学習基盤

## 背景

詰将棋探索の改善と並行して進めやすい独立作業として、棋譜学習の前処理基盤を追加した。

開始時点で `main` は v0.0.17 だったが、作業中に v0.0.18 が main へ入ったため、作業ブランチ `feature/kifu-learning-foundation` を v0.0.18 の先頭へ追従させてから実装を継続した。

v0.0.18は詰み探索の直接着手高速化と7手対応であり、今回の棋譜基盤は探索本体を変更しない。

## 今回の目的

いきなり学習アルゴリズムを入れるのではなく、外部棋譜を安全に教師データへ変換できる再現可能な経路を作る。

必要条件は次のとおり。

1. 棋譜形式を機械的に読める
2. 同一棋譜を重複学習しない
3. 学習用と検証用を棋譜単位で分ける
4. 棋譜に書かれた全着手をルール層で再検証する
5. 各局面を将来のpolicy/value学習へ流用できる形で保存する
6. 詰み探索・通常探索・評価関数を変更しない

## 実装

### CSAパーサ

`tools/kifu/csa.py`

CSAをUSIへ正規化する。平手、駒落ち、任意局面、持ち駒、`00AL`、成り、駒打ち、複数棋譜を扱う。

CSA側では合法性の最終判断をしない。あくまで表記変換と局面記述の解釈に限定した。

### 正規化・重複排除

`tools/kifu/build_dataset.py`

初期SFENと全USI指し手列のSHA-256を棋譜fingerprintとする。

同一fingerprintは1局だけ残す。入力ファイル名や対局者名が違っても、同じ対局内容なら重複として扱う。

### train / validation / test 分割

fingerprintと固定saltのSHA-256から、棋譜単位で80/10/10へ決定的に分割する。

局面単位でランダム分割すると、同じ1局の前半がtrain、後半がvalidationへ入るなど情報漏洩が起こるため採用しない。

### ルール層検証

`tools/kifu/validate_games.cpp`

各局面で `Position::legal_moves()` を取得し、棋譜手が含まれることを確認してから再生する。

この検証器は `engine/rules/Position` だけを利用する。やねうら王の探索・評価・定跡・詰み探索は使わない。

### 教師サンプル出力

`tools/kifu/export_samples.py`

1局を1局面1行へ展開し、次を保存する。

- game_id
- split
- ply
- ルール層position hash
- SFEN
- 実戦棋譜の次手
- その局面の手番から見た最終勝敗

これにより、次段階で「実戦で選ばれた手」を教師にしたpolicy学習、勝敗を教師にしたvalue学習、既存特徴量の重み学習のいずれにも利用できる。

## CI

`.github/workflows/kifu-learning-ci.yml` を追加した。

確認項目：

- CSA表記変換
- 複数棋譜
- `00AL`
- fingerprintと固定分割
- 同一棋譜の重複排除
- C++ルール検証器のビルド
- 正常棋譜の全着手再生
- 意図的な違法手の拒否
- 1局面1サンプルへの展開
- 既存ルール／戦略境界検査

## 探索系との分離

今回変更する既存コードは `scripts/build.py` のビルド対象追加のみで、`engine/main.cpp`、`engine/strategy/**`、`engine/rules/**` は変更しない。

したがって、並行して進んでいる詰将棋・詰み探索改善との意味上の競合を避けられる。

## 次の段階

基盤完成後は、ライセンスと出所が確認できるCSA棋譜を小規模に取り込み、以下を計測する。

- 棋譜数
- 重複率
- 総局面数
- train / validation / test の局数と局面数
- 不正・未対応棋譜の割合
- 勝敗ラベル欠損率

その結果を見て、既存の説明可能な特徴量に対する教師あり学習へ進む。NNUEや大規模自己対局はまだ行わない。
