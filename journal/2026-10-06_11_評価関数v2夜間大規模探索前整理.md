# 評価関数v2 夜間大規模探索前の設計整理

日付: 2026-10-06

## 1. なぜv2が必要になったか

雲路は当初、駒得を「良い局面」の基準として実装した。これはランダム選択から脱する最初の評価軸として有効であり、その後の2-ply / 3-ply / αβ探索でも基盤になった。

一方、開発が進むにつれて次の違和感が明確になった。

- 両取り・串刺し等の手筋をmove orderingへ追加しても、読む順番が変わるだけで、利益実現まで読めなければ葉局面の評価値には残らない。
- Influence（効き）、Potential Mobility（将来の自由度）等は静的評価として研究したが、現行評価では非Material評価全体が`positional_cap=300`に制限されていた。
- 歩=100、銀=500、金=600、角=800、飛=1000のMaterial尺度に対し、玉安全・圧力・活動性・危険度等を全て合わせても最大300という構造は、結果としてMaterialを強く支配的にした。
- 200msのような有限時間探索では、「読む順番」だけを増やしても、最終的に探索が到達したMaterial利益を中心に選びやすい。

このため、個別featureを追加するだけではなく、評価・探索・orderingの責務を再設計する必要が生じた。

## 2. v2の原則

1. 証明された詰み・終局結果だけを通常評価より絶対優先する。
2. 非終局局面では、Material / Safety / Pressure / Activity / Danger / Influence / Potential Mobility / Coordination / Hand Potential / Threatを同じ総合評価の軸として扱う。
3. 「読みがそこで終了しても価値が残る」概念は静的評価に持たせる。
4. move orderingは探索効率化であり、局面価値の代用品にしない。
5. qsearch・探索延長・長考はhorizon対策であり、局面価値の代用品にしない。
6. 全非Material項目を一律に±300へ押し込むglobal capはv2の探索中は事実上外し、必要性を後から独立に調べる。
7. 固定重みは最終形ではない。将来は局面進行度に応じて重みを連続変化させる。ただし先に「各評価軸の基準的な強さ」を探索する。

## 3. 現在の10評価軸

夜間探索で同時に扱う軸は次の10個である。

1. Material（駒得）
2. Safety（玉の安全）
3. Pressure（相手玉への圧力）
4. Activity（現在の活動性）
5. Danger（取られやすさ・危険）
6. Influence（盤面の効き・支配）
7. Potential Mobility（将来の可動域）
8. Coordination（駒同士の連携）
9. Hand Potential（持ち駒の選択価値）
10. Threat（両取り・串刺し等の未実現利益）

Threatは「最後に両取りを指したから」という履歴依存ボーナスではなく、現在局面に存在する複数攻撃等から軽量に評価する。実際に駒を取れば、その価値はMaterialへ受け渡される。

## 4. ここまでの検証

### 持ち駒両取り・串刺し ordering

軽量な幾何判定をorderingだけへ入れた400局では得点率51.625%。大きな害はなかったが、「両取り自体の未実現価値」を評価した試験ではない。

### 実効両取りの全合法応手確認

候補の持ち駒打ちごとに相手の全合法応手を確認する方式を200msで試した。概念としては多くの見かけ上の両取りが反論で消えることを確認できたが、相手応手列挙が本来のαβ探索と重複し、探索nodesを約35%失うrunが続いた。したがって別ミニ探索方式は採用せず、静的Threatは軽量に、詳細反論は本探索に任せる方針とした。

### Potential Mobility

単独weight 50の100局確認では得点率40.5%で悪化した。ただし旧global cap、単独feature、固定weightという条件であり、他featureとの相互作用を含めたv2で再評価する。

### 3水準OA729予備探索

10軸を基準値の0.5倍 / 1倍 / 2倍で同時に振るstrength-3直交配列729設定を作成し、各設定2局（先後入替）、合計1,458局を200msで実施した。

実測:
- GitHub Actions全体: 約15分
- 対局部分: 約13分
- 27 shard、実際にはrunner上限により概ね20本前後が並列
- 全shard成功、違法手なし

全729設定平均のv2得点率は41.1%。主効果はMaterial 50%水準が明確に悪く、Influenceは低水準、Threatは中水準等が相対的に良かった。一方、2局/設定しかないため、相互作用モデルから90%超の推定値が出るなど個別設定予測には明らかにノイズが大きい。**この結果を採用決定や強い切捨てには使わない。**

この予備探索の価値は、
- 直交配列・並列実行・artifact集約が実運用可能と確認できたこと
- 相互作用が無視できないこと
- 0.5～2倍の範囲だけでは最適域探索として狭い可能性が高いこと
である。

## 5. なぜ探索範囲を広げるか

v2で追加した各featureの「基準値」はまだ仮置きである。

仮の中心値の0.5～2倍だけを試しても、真の最適が中心から5倍離れていれば見つからない。特にMaterialと他featureの相対比は、v1の歴史的経緯で決まったものであり、v2の設計原理から導かれた比率ではない。

したがって夜間本探索では、各軸を対数的な5水準

```text
0.2倍 / 0.5倍 / 1倍 / 2倍 / 5倍
```

で振る。

低水準と高水準の差は25倍であり、「ある分野を別分野の10倍程度重く見る」可能性を十分含む。完全OFFは別途ablationで確認する。

既存USI上限400では5倍水準を表現できない項目があるため、研究ブランチでは評価weightの許容上限を拡張する。ただしmate scoreとの安全距離を保つStaticLimitは維持する。

## 6. 5水準直交配列

完全総当たりは5^10 = 9,765,625設定であり、実戦対局で全て試すのは非現実的である。

そこで5水準・10因子について、5^5 = 3,125設定のstrength-3直交配列を使う。

この配列では、
- 任意の1因子の5水準が均等
- 任意の2因子の25組合せが均等
- 任意の3因子の125組合せが均等

になる。

したがって各軸の単独傾向だけでなく、Material×Threat、Safety×Pressure、Activity×Influence等の2因子相互作用、さらに主要な3因子相互作用まで、他因子が偏らない状態で観測できる。

## 7. 一晩の探索方針

目的は「一晩で最適値を断定すること」ではなく、**今後長期間切り捨てられる可能性がある方向を、十分な証拠なしに捨てず、v2候補を最終3案程度へ絞ること**である。

### Stage A: 広域探索

3,125設定を全て走らせる。

まず100msで各設定6局（先後3局ずつ）を実施する。合計18,750局。予備OA729の200ms実測速度から、同程度のrunner供給なら約80～100分を見込む。

同時に代表243設定を50ms・200msでも各6局再評価し、50/100/200msで主効果・順位傾向がどの程度一致するかを測る。

50ms結果だけで候補を切らない。100msを広域探索に使えるかは、200msとの相関を確認して判断する。

### Stage B: 200ms再評価

Stage Aから625候補程度を残し、200msで各12局程度を追加する。

残し方は単純な勝率順にしない。
- 推定上位
- 不確実性が大きく上振れ余地がある候補
- 各因子水準を代表する候補
- 強い2因子・3因子相互作用の領域
を混ぜる。

ある因子の特定水準を丸ごと消す場合は、主効果だけでなく、その水準を含む上位相互作用セルも不利であることを確認する。

### Stage C以降: 段階的増局

目安:
- 約125候補: 各40～50局
- 約25候補: 各150～200局
- 約9候補: 各400～500局
- 最終3候補: 必要なら各800～1,000局

予備OA729の実測では1,458局・200msが約13分で完了した。runner待ち・artifact・再試行を含めても、上記を一晩6時間前後で進めることを目標とする。6時間で証拠が足りなければ翌日日中へ継続し、時間目標のために乱暴に削らない。

## 8. 切捨て原則

今回切り捨てた方向は今後長く再検討されない可能性があるため、次を守る。

- 1設定の数局の勝敗だけで切らない。
- 低時間設定だけで切らない。
- marginalな主効果だけで切らず、相互作用を確認する。
- ある水準を完全に消すには、その水準の上位相互作用も弱いことを確認する。
- 不確実性の高い候補を一定数残す。
- 同系統の上位候補だけでなく、異なる「将棋観」の候補を残す。
- 最終3案は、単なる勝率1～3位ではなく、再現性・計算負荷・評価内訳・相互作用の安定性も見る。

## 9. エラー・中断対策

長時間runで「早い段階で止まっていたが朝まで気付かなかった」を避ける。

- 多数の独立shardへ分割する。
- `fail-fast: false`で1 shard失敗が他shardを即停止しないようにする。
- shard内は設定単位で結果を保存する。
- artifact uploadは`if: always()`で失敗時も可能な範囲を回収する。
- 各stageのanalysisで期待件数を機械確認する。
- 欠損があれば「成功」として先へ進まず、欠損shardを特定する。
- GitHub Actionsのcondition watchを今夜は1時間ごとに実行し、失敗・想定外キャンセル・長時間停滞・stage完了を通知する。
- stageごとにartifactを残し、後段が失敗しても前段結果を再利用できるようにする。

## 10. この探索の後

固定weightで3候補程度まで絞った後、局面進行度による可変weightへ進む。

「序盤・中盤・終盤」を手数だけで3分割するのではなく、駒交換、持ち駒、成り・敵陣侵入、玉への接触等から連続的な進行度を作り、5個程度の基準点を滑らかに補間する方式を第一候補とする。

したがって今回の夜間探索は、最終評価関数の完成ではなく、**可変weightモデルの基準となる10軸の相対尺度を安全に絞る工程**である。
