# 2026-10-05 自前棋譜から作る小規模定跡

## 目的

既成の定跡集、プロ棋譜、他エンジンの推奨手を使わず、shogi-ai自身の自己対局棋譜だけから序盤の小規模定跡を作り、通常対局で利用できるか確認した。

Experience Cacheは同一局面で過去の手を探索順の先頭へ置くだけであり、事前投入した自己棋譜580局の実験では50ms・100局が48勝4分48敗であった。今回は、序盤の十分に観測された局面について候補手そのものを選ぶ独立したOpening Bookとした。

## 実装

- `tools/book/import_arena_games.py`：`benchmarks/results` の自己対局だけを収集する。
- `tools/kifu/validate_games.cpp`：全手をルール層で再生し、局面ハッシュと勝敗ラベルを生成する。
- `tools/book/build_opening_book.py`：序盤20手以内を局面単位で集計する。
- `engine/strategy/opening_book.h`：読取専用の局面ハッシュ→候補手表を保持する。
- `engine/main.cpp`：通常`go`の合法手確定後、MateAssistと通常探索の前に定跡を照合する。

同一局面8回以上、候補手3回以上を条件とし、少数局の100%勝率を過信しないよう得点率を50%側へ平滑化した。最良候補との差0.12以内を最大3手残し、対局数の平方根と平滑化得点率から重みを作る。候補が複数ある場合は`RandomSeed`と局面ハッシュから再現可能な重み付き選択を行う。

定跡が見つからなければv0.0.19のMateAssist、反復深化、静止探索へそのまま移る。`go mate`では定跡を使わない。`go ponder`と`go infinite`も従来の停止処理を維持するため定跡即着手を行わない。

## USI動作確認

生成した定跡を指定し、初期局面から`go movetime 50`を送ったときに`opening_book hit`を経て即座に`bestmove`を返すことを確認した。

同じエンジンで`OpeningBook=false`にすると定跡ヒットせず、v0.0.19のMateAssistと通常探索へ戻ることも確認した。C++単体試験、Python生成試験、エンジンビルドを含めCIは全て通過した。

## 50ms・100局比較

GitHub Actions run `37270399469` で、同じv0.0.19バイナリを使い、Aだけ定跡ON、Bは定跡OFFとして比較した。Experience Cacheは双方OFF、`go movetime 50`、200手上限、先後50局ずつ、seed `2026100551`である。

結果：

- 定跡あり：45勝29分26敗
- 得点率：59.5%
- 違法手：0
- 平均手数：142.5手
- 定跡あり平均応答：42.711ms/手
- 定跡なし平均応答：45.268ms/手
- 平均応答時間：約5.6%減
- 定跡あり探索ノード：21,606,602
- 定跡なし探索ノード：23,467,653
- 探索ノード：約7.9%減

先後別では、定跡側が先手の50局は20勝16分14敗で得点率56.0%、後手の50局は25勝13分12敗で63.0%であった。少なくとも一方の手番だけによる結果ではない。

10局時点70.0%、20局57.5%、50局60.0%、75局60.0%、100局59.5%であり、終盤だけに偏って勝ち越した形でもない。

ただし100局の得点率の単純な95%近似区間は約51.4%～67.6%であり、恒久採用の棋力差を確定するには別seedでの再試験が望ましい。

## 注意点

自己対局だけから作ったため、人間の定跡とは違う手も強く残った。今回の100局で定跡側が先手を持ったときの初手は、`2h3h` 18局、`4i3h` 18局、`6i7h` 14局であった。一方、定跡なし側の先手初手は50局すべて`9g9f`であった。

これは違法手ではなく、自己対局の勝敗だけを見ると現在のshogi-aiに対して有利だった手である。しかし「一般に良い序盤」まで証明したものではない。現在版の癖や弱点を利用した自己対局内のメタ戦略を定跡化している可能性がある。

したがって現段階では、外部データを混ぜずに自前定跡の仕組みを成立させ、初回の自己対局では有望な結果が出たところまでを成果とする。mainへ即採用せず、別seedでの再現確認や将来の外部実戦を経て判断する。
