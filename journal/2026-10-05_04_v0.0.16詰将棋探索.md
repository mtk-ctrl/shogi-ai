# v0.0.16 詰将棋探索

2026-10-05、通常探索とは別に、自作の詰み専用探索を追加した。

## 方針

攻め側は王手になる合法手だけを探索し、受け側は王手を外す全合法応手を探索する。受け側で一つでも逃れられる手があれば強制詰みではない。すべての応手に対して詰ませられる場合だけ詰みとする。

やねうら王から使うのは従来どおりルール層だけであり、上流のmate solverは使わない。

## 実装

`engine/strategy/mate_search.h`を追加した。

- 1・3・5 plyを順に探索
- 上限5 ply
- 攻め側は王手だけ
- 受け側は玉逃げ、王手駒の捕獲、合駒等を含む全合法応手
- 攻め側は短い詰みを優先
- 受け側のPVは最も長く生き延びる応手を代表として返す
- `SearchControl`のstop、deadline、node limitに対応
- RAIIで探索途中の局面を必ず巻き戻す
- 千日手等の非詰み終局を詰みと誤認しない

USIの`go mate`にも接続し、エンジン表示をv0.0.16へ更新した。

5手以内に詰みを証明できなかった場合は、より長い詰みが存在する可能性があるため`checkmate nomate`とはせず`checkmate timeout`を返す。

通常の`go`にはまだ自動挿入していない。通常の50ms対局の探索経路はv0.0.15軽量版のまま維持する。

## 実戦から5手詰めを抽出

採用済みのv0.0.15軽量版50ms・100局結果から、python-shogiによる独立探索で厳密な5手詰めを探索した。

対象：game 0、ply 104。

```text
l3lk3/2g3n+P1/1p7/p2+R2P2/3p5/P1P1p4/2SPPP2L/5S3/+n+l1GKG1N1 b BGS6Prbsnp 105
```

独立側で、1手詰めなし、3手詰めなし、5手詰めありを確認した。

代表手順：

```text
2b3b 4a3b S*3c 3b4a G*4b
```

抽出用コードは`benchmarks/find_tsume5.py`へ保存した。

## テスト

`tests/mate_search_test.cpp`で次を確認した。

- 実戦由来局面は1 plyでは詰まない
- 同局面は3 plyでも詰まない
- 5 plyで強制詰みを発見する
- 先頭手は独立探索と同じ`2b3b`
- 最長防御をたどった途中局面は厳密な3手詰め
- 最後の攻め局面は1手詰め
- 攻め側のPV各手が実際に王手になっている
- PV終端が実際の詰み
- 詰みのない裸玉局面を5手以内の詰みと誤認しない
- stop済みではTimeout
- node limit到達でもNoMateではなくTimeout
- すべての探索後に盤面・履歴が復元される

USIテストでは、実戦由来の5手詰めに`go mate 5000`を送り5手の`checkmate`手順を返すこと、5手以内で証明できない局面ではグローバルな`nomate`を主張せず`checkmate timeout`を返すことを確認した。

既存の通常探索テスト、静止探索テスト、ルール層との境界検査もすべて成功した。

最終統合検証：GitHub Actions run `37244572304`、全step成功。

## 途中で分かったこと

既存の通常探索テストに「3手目の詰み」を確認する局面があったが、これは候補手を2手に限定した通常探索テストだった。盤面全体を詰み専用探索すると別の1手詰めが存在した。

専用探索側の誤りではなく、テストの前提が異なっていたため、詰将棋テストには独立探索で厳密な手数を確認した実戦局面を採用した。

## 思考時間の扱い

今後の戦略変更の自己対局は、開発速度を優先して原則50msを使う。

軽量化前v0.0.15で100ms>50ms、250ms>100ms、500ms>250msの傾向を確認しており、長く考えるほど少なくとも500msまでは強くなる可能性が高い。この結果は残すが、500ms以上の比較は後でまとめて行う。

詰み探索の通常対局への組込み効果も、最終的には50ms条件で比較して判断する。

## 次の課題

- 詰み専用探索を通常50ms探索へ組み込む方法を検討する
- 組込み前後を同じ50msで対局し、棋力改善を実証する
