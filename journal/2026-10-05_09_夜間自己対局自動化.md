# 夜間自己対局の自動化

## 目的

自己対局棋譜を人手なしで毎日継続的に蓄積する。固定局数ではなく夜間の計算時間を使い切る方式とし、開発中の探索・評価・定跡学習に再利用できる棋譜を増やす。

## 運用

- GitHub Actions `Nightly Self Play` を毎日 00:00 JST に起動する。
- scheduled run は 04:15 JST 以降に新しい20局バッチを開始しない。
- 04:15以降は各runnerの結果アップロード、全runnerの集約、学習用TSV生成に使い、05:00までの終了に余裕を持たせる。
- 思考条件は当面 `go movetime 50`、最大200 plyとする。
- 現行の `shogi-ai-book.tsv` を双方が使用し、ExperienceCacheは無効にして再現性を保つ。

## 並列化

private repository の標準 `ubuntu-latest` は2 vCPUであるため、4 runnerを並列起動し、各runner内でarenaを2 lane同時に回す。合計8 laneを並列実行する。

既存の2,000局実験は20 shard・最大10 runner並列で約45分だった。夜間運用ではrunner数だけを極端に増やすのではなく、1 runnerの2 vCPUを2 laneで使い切って、GitHub Actionsのrunner-minutes当たりの対局数を優先する。初回の実測局数を見てrunner数・停止時刻・batch sizeを調整する。

## 保存

- arena JSONの生棋譜：GitHub Actions artifact、14日保持。
- `all-games.tsv`：全対局のコンパクト棋譜。
- `learning-decisions.tsv`：重複を除いた決着局を既存の棋譜学習形式へ変換したもの。
- `summary.json` / `learning-report.json`：局数、違法手、平均手数、学習利用可能局数等。
- コンパクト成果物は90日保持する。

現時点では夜間棋譜から本番定跡を自動更新しない。棋譜蓄積と本番採用を分離し、学習・評価方法が固まってから昇格条件を設ける。

## コスト上の注意

このrepositoryはprivateであり、GitHub-hosted runnerはプランの無料枠を超えると課金対象になり得る。したがって、単純に20〜40 runnerへ増やすのではなく、まず4 runner × 2 laneで目標の約1万局/夜を狙う。初回実測で不足する場合は、局数とrunner-minutesの両方を見て増やす。

## 実装

- `.github/workflows/nightly-self-play.yml`
- 00:00 JST = 15:00 UTC のcronを設定。
- 手動実行時は短時間の検証ができる `duration_minutes` 入力を用意。
- 同じworkflowの重複夜間実行を防ぐconcurrency groupを設定。
