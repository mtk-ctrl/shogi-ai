# 雲路：研究専用ニューラルネットワーク（試験版）

## 目的と現行エンジンとの境界

既存のKUMOJIの評価関数・探索・指し手には**一切介入しない**独立研究装置。
機械学習で棋譜から「先手が勝つ確率」を予測し、雲路自身の静的評価を勝率へ換算した値と比較する。
大きな評価の食い違いを研究すべき局面として抽出する。NNの評価を正解扱いしたり、本体へ自動採用したりしない。

- NNはNumPyだけで実装した小型の1中間層ネットワーク（CPU向け、初版32ニューロン）。
- 入力はSFENの盤面、手番、持ち駒。出力は先手勝率 0～1。
- 学習目標は雲路自身の自己対局の最終勝敗（勝1、負0、千日手引分0.5）。局面単位の正解手ではない。
- 人間の他者棋譜や外部エンジンの評価値・推奨手・着手を教師にしない。
- まず**同じKUMOJIバイナリ同士**の自己対局結果のみを受け付ける。
- 局面知識の直接着手・探索・評価重みは変更しない。

## ディレクトリと出力

- `network.py`: 局面の数値化、NNの計算、学習、モデル保存
- `mark_selfplay.py`: 作成済みの同一バイナリ自己対局であることをSHA256で照合し、出所を明示
- `prepare.py`: 検証済み自己対局JSONからSFEN付き学習サンプルへ変換
- `train.py`: 棋譜単位で学習・検証・試験へ分離して学習、Brierスコア・評価差分を保存
- `tests/test_nn_research.py`: 棋譜の再生、出所確認、学習、保存・復元の一貫テスト

生成物（GitHubに大量コミットせず、Actions artifactへ保存）:
- `position-net-v1.npz`: 学習済みの研究用重み
- `report.json`: 学習条件、元データのハッシュ、分割別の予測精度
- `disagreements.csv`: 学習に使っていない試験局面で、NNと現行静的評価の勝率換算が食い違った例

## 実行

Python環境に `numpy` と `python-shogi==1.1.1` をインストールする。
まず動作試験:

```bash
python3 tests/test_nn_research.py
```

既存の `benchmarks/arena.py` で同一バイナリの自己対局を実行し、そのJSONを生成した場合:

```bash
python3 research/nn/mark_selfplay.py --input build/nn-raw.json --engine build/kumoji --output build/nn-verified.json
python3 research/nn/prepare.py --input build/nn-verified.json --output build/nn-samples.jsonl
python3 research/nn/train.py --input build/nn-samples.jsonl --output-dir build/nn-report
```

最終結果が未確定の `move_limit` 棋譜は勝敗教師に含めない。評価値が欠けた局面は学習できるが、静的評価との比較には使わない。
現在の評価値とNN出力の尺度は異なるため、雲路の静的評価値を**学習用の棋譜だけ**で候補温度から確率換算する。
報告書で比較するBrierスコアは小さいほど良い。学習用・検証用・試験用は棋譜単位で分離するが、別棋譜で同一局面が現れることがあるので重複数も報告する。
短い局数や類似局面が多い結果は棋力優越の根拠にはしない。

## 将来の拡張

1. 保存済みの自己対局・研究記録へ安全な出所確認付きで接続する。
2. 異なる初手・局面別で検証し、データの偏りを減らす。
3. 50分研究と比較し、食い違い局面の原因を分類する。
4. NNを対局中に使用する案は**別の候補**として実装・検証し、正式採用はオーナー判断とする。

仕様と採用の権限はR00/R10/R20/R25/R50を優先する。

## 実棋譜を使った初回研究

`.github/workflows/nn-real-study.yml` は、研究専用の再現可能な実行環境。
データReleaseの固定資産 `played-games-37671846680.jsonl.gz` と同manifestを取得し、内容ハッシュ・対局エンジン実体ハッシュ・全着手の合法性を確認する。
保存時期の古い同一エンジン自己対局を使うため、学習結果は**現行の雲路との棋力優劣ではない**。
8手ごとに学習局面を抽出し、現行の雲路の `eval` で同じ盤面の静的評価を再計算する。局面の重複を除いた別棋譜で予測精度を比較する。

初回は専用の依頼ファイル `.github/nn-research-request.json` の変更で明示的に起動し、結果は期限付きActions成果物として保存する。定期実行・モデルの自動採用はしない。

## 初回実データ学習後の過適合対策

初回run 38096038616では、旧版自己対局300局を読取り、291局を有効棋譜と判定。8手ごとに4,964局面を取得し、学習用3992・検証用155・試験用174局面を重複を除いて比較した。
初回NN（中間32、15回学習）は未知局面Brier 0.262935、雲路の静的評価を確率に換算した値は0.152012だった。NNに強さの証拠はない。
研究用 `tune.py` は中間層の大きさと学習回数を複数候補から**検証用データだけで選択**し、最後に試験用データを測定する。同じ過去の試験用棋譜は初回の報告で既に参照済みのため、追試は探索的比較に限り、未使用独立データでの確認が次の課題である。対局エンジンは変更しない。

## これまでの全対局記録を使う拡張実験

`research/nn/collect_history.py` はReleaseの長期保管済み実戦手に加え、GitHub Actionsに残る `played-move-archive-*` を全件探索し、原データハッシュ・エンジン実体ハッシュ・棋譜の合法性を確認する。**使用できる同一バイナリ同士の対局だけ**を勝敗予測の学習に使う。異なるエンジン世代同士、勝敗未確定、証明できない出所、期限切れ、旧形式リーグ戦などは件数または除外範囲を示し、すべてを学習したと誤認させない。

局単位の全実戦手を合法性検証し、学習用には1局から最大6局面を選ぶ。研究用に元データを書き換えない。比較対象の雲路静的評価は指定された実行時のエンジンで別途再計算する。学習・検証・試験は**ソースとなる対局実行単位**で分け、同じ盤面が分割間にまたがる場合は除外する。

`nn-history-study.yml` で一度実行できる。研究用モデルの正式エンジン組込み、他人の棋譜学習、外部AIの学習教師化、新しい対局の自動起動は行わない。元棋譜の長期保管と研究成果物の90日保存を混同しない。

## 実データの総点検に基づく異世代対局の扱い

2026-10-11 run 38097552337で標準アーカイブ18件と長期保管Releaseを検査し、4,604局を確認した。同一バイナリで勝敗教師にできたのは291局で、4,304局は**別世代の雲路同士**（Generic Engine Matchの両候補はいずれも本リポジトリのコードからビルド）だった。標準学習方式のみによる『過去全棋譜を使った学習』は成立せず、複数ソースrunの分割も不可能と判明した。

そこで `--include-mixed-versions` を**研究時にだけ明示**する場合、異世代同士の対局結果も『雲路内部の実戦結果』として勝敗予測の学習に含める。学習記録には `match_type=mixed_versions`、対局両者の実体ハッシュ、ソースrunを残し、同一版同士の結果と区別する。**異世代対局の勝敗は使用したエンジンの実力差を反映するため、同等棋力の自己対局から得た形勢の正解とはみなさない。** 研究モデルの実戦棋力向上も未証明である。将来、比較条件の揃った新規自己対局で別途検証する。

## 二つの評価方法の食い違いを長考研究へつなぐ

`research/nn/select_disagreements.py` は、学習済み研究用NNの**先手勝率**と、雲路の**新たに算定した静的評価点を学習用データで確率に換算した値**を比較し、差が大きい局面を抽出する。実戦棋譜の指し手履歴を丸ごと再現して整合性を確認する。出所ハッシュ・双方の評価値・比較条件を研究選定記録へ保存する。

局面の序中終判定は雲路既存の段階判定器（`scripts/build.py --phase-probe` が出す展開・戦闘・敵陣進出の3成分）から、現在採用されている係数・境界を正確に計算する。**30局面（序盤10・中盤10・終盤10）**を異なる棋譜・実行履歴へ分散し、採用済みの局面知識と取得できた過去研究対象を除外する。元から未使用の試験用runは今回の研究選抜に使用しない。局面の学習出所には雲路異世代同士の対局が含まれるため、評価差そのものはどちらが正しいかの根拠にはならない。

`research/nn/study_disagreements.py` は既存の`run_opening20.Usi`で着手履歴を復元し、10ランナーの上限で各局面50分の長考研究を実行する。全30件は3巡のマトリクスとなる。**現行雲路自身の長考も現行評価関数に依存しており、NNと独立した正解ではない。** 深い探索との符号一致・候補手・探索深さ・読み筋の変化を暫定記録するだけで、正解ラベルの自動生成、NNへの無審査教師追加、M型重みの変更、採用済み局面知識の自動更新は実施しない。

研究workflowは `.github/workflows/nn-disagreement-study.yml`。起動する場合は `.github/nn-disagreement-request.json` の明示的な更新、または手動起動を使う。成果物は候補30局面、実行原本（Releaseへ保存）、統合レポートであり、候補選定結果と長考研究結果を区別する。3段階目として、原因分析・パラメータ/NN再学習候補・未学習棋譜での検証を重ねて強化可能性を検討する。正式なエンジンへの採用はオーナーが判断する。

手動で候補選定スクリプトを使う場合は `python3 research/nn/select_disagreements.py --help`、長考研究は `python3 research/nn/study_disagreements.py --help` を参照する。
