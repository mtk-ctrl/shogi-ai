# 雲路：研究専用ニューラルネットワーク（試験版）

## 目的と現行エンジンとの境界

既存のKUMOJIの評価関数・探索・指し手には**一切介入しない**独立研究装置。
機械学習で棋譜から「先手が勝つ確率」を予測し、雲路自身の静的評価を勝率へ換算した値と比較する。
大きな評価の食い違いを研究すべき局面として抽出する。NNの評価を正解扱いしたり、本体へ自動採用したりしない。

- NNはNumPyだけで実装した小型の1中間層ネットワーク（CPU向け、初版32ニューロン）。
- 入力はSFENの盤面、手番、持ち駒。出力は先手勝率 0～1。
- 学習目標は雲路自身の自己対局の最終勝敗（勝1、負0、千日手引分0.5）。局面単位の正解手ではない。
- 人間の他者棋譜や外部エンジンの評価値・推奨手・着手を教師にしない。
- まず**同じKUMOJIバイナリ同士**の自己対局結果のみを受け付ける。
- 局面知識の直接着手・探索・評価重みは変更しない。

## ディレクトリと出力

- `network.py`: 局面の数値化、NNの計算、学習、モデル保存
- `mark_selfplay.py`: 作成済みの同一バイナリ自己対局であることをSHA256で照合し、出所を明示
- `prepare.py`: 検証済み自己対局JSONからSFEN付き学習サンプルへ変換
- `train.py`: 棋譜単位で学習・検証・試験へ分離して学習、Brierスコア・評価差分を保存
- `tests/test_nn_research.py`: 棋譜の再生、出所確認、学習、保存・復元の一貫テスト

生成物（GitHubに大量コミットせず、Actions artifactへ保存）:
- `position-net-v1.npz`: 学習済みの研究用重み
- `report.json`: 学習条件、元データのハッシュ、分割別の予測精度
- `disagreements.csv`: 学習に使っていない試験局面で、NNと現行静的評価の勝率換算が食い違った例

## 実行

Python環境に `numpy` と `python-shogi==1.1.1` をインストールする。
まず動作試験:

```bash
python3 tests/test_nn_research.py
```

既存の `benchmarks/arena.py` で同一バイナリの自己対局を実行し、そのJSONを生成した場合:

```bash
python3 research/nn/mark_selfplay.py --input build/nn-raw.json --engine build/kumoji --output build/nn-verified.json
python3 research/nn/prepare.py --input build/nn-verified.json --output build/nn-samples.jsonl
python3 research/nn/train.py --input build/nn-samples.jsonl --output-dir build/nn-report
```

最終結果が未確定の `move_limit` 棋譜は勝敗教師に含めない。評価値が欠けた局面は学習できるが、静的評価との比較には使わない。
現在の評価値とNN出力の尺度は異なるため、雲路の静的評価値を**学習用の棋譜だけ**で候補温度から確率換算する。
報告書で比較するBrierスコアは小さいほど良い。学習用・検証用・試験用は棋譜単位で分離するが、別棋譜で同一局面が現れることがあるので重複数も報告する。
短い局数や類似局面が多い結果は棋力優越の根拠にはしない。

## 将来の拡張

1. 保存済みの自己対局・研究記録へ安全な出所確認付きで接続する。
2. 異なる初手・局面別で検証し、データの偏りを減らす。
3. 50分研究と比較し、食い違い局面の原因を分類する。
4. NNを対局中に使用する案は**別の候補**として実装・検証し、正式採用はオーナー判断とする。

仕様と採用の権限はR00/R10/R20/R25/R50を優先する。

## 実棋譜を使った初回研究

`.github/workflows/nn-real-study.yml` は、研究専用の再現可能な実行環境。
データReleaseの固定資産 `played-games-37671846680.jsonl.gz` と同manifestを取得し、内容ハッシュ・対局エンジン実体ハッシュ・全着手の合法性を確認する。
保存時期の古い同一エンジン自己対局を使うため、学習結果は**現行の雲路との棋力優劣ではない**。
8手ごとに学習局面を抽出し、現行の雲路の `eval` で同じ盤面の静的評価を再計算する。局面の重複を除いた別棋譜で予測精度を比較する。

初回は専用の依頼ファイル `.github/nn-research-request.json` の変更で明示的に起動し、結果は期限付きActions成果物として保存する。定期実行・モデルの自動採用はしない。
