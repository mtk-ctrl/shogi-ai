# 20ランナーの自己対局・分析・学習循環

2026-10-22の「20ランナーをフルに使って効率的な学習ができるように作り変える」依頼への研究実装。正式エンジンの採用とは別。旧単機 `neural_loop.py` は小規模な再現用として残し、GitHubでの分散入口は `neural-distributed.yml` にする。

## 標準の1世代

| 工程 | 規模 | 分担 |
|---|---|---|
| 自己対局 | 100局、200ms＋条件付き長考、採用知識163件 | 先後2局を分割せず20枠へ配分。各4〜6局 |
| 局面選択 | 未研究の学習群40局面 | 元対局を分散し、過去世代と同一局面を除外 |
| 長考・反証 | 各10分＋50分、研究手が実戦手と異なれば双方の先を各10分 | 20ランナーが各2局面。通常の探索を全部使えば最長約160分＋準備 |
| 研究ネット学習 | 累積棋譜＋累積研究教師、幅128、20epoch | 集約した1モデルを1ジョブで更新 |
| 自作MCTS | 40局面×512回 | 20ランナーが各2局面 |
| NNUEへの学習 | 通常局面と研究教師を保持して20epoch、整数形式へ変換 | 1ジョブ。実エンジンと数値/読み込みを照合 |
| 予備評価 | 親と80局、200ms | 20ランナー×4局。得点率50%未満または不正/手数打切りがあれば不合格 |
| 本評価 | 親と1000局、必要なら固定基準とも別1000局 | 20ランナーに先後対を均等配分。予備評価とは独立seed |
| 保存・次世代 | 合格時だけ研究親更新、不合格でも学習器とデータを継承 | 原本・モデル・直近optimizerをReleaseへ保存、再取得SHA一致後に次世代へ |

本評価は固定局数・先後対・Hoeffding下限・予定全世代への補正を維持する。予備評価は足切り専用であり、予備の勝敗を本評価に足さず、途中勝率で早期採用しない。評価対局は学習データへ混ぜない。実戦棋譜は全着手を保存する。

40局面の追加50分枠を必ず要求する（既存の採用研究手による即決は新しい長考教師とせず除外する）。実測の分析比率は各工程の実時間から報告し、計画の65%を実績と表示しない。

## ランナーの利用

各世代開始時に所有者の参照可能なリポジトリの実行中Actionsを確認し、20枠から他の稼働ジョブを引いた空き枠を使用する。他の仕事を停止しない。各重い工程は最大20ジョブ、1ジョブ1対局lane/研究lane。長時間待機する管理ジョブを設けず、Actionsの依存関係で次工程を起動する。

ニューラルネットの勾配更新は単一学習ジョブ。これは20台の同期分散学習ではない。現行の小データ・CPUモデルでは、対局・長考・MCTSの分配を先に行う。学習時に19台へ同じ学習を複製せず、共通の学習状態を更新する。標準設定の学習時間は実測して報告する。

準備・集計・学習以外の分割可能な仕事に空き枠を使う設計であり、全工程を通じた常時20台稼働は保証しない。開始時の空き枠と、実際の同時稼働数は別々に記録する。

## 反映と継承

- 対局用NNUEの局面価値と、root・1手先の候補を読む順を学習する。
- 研究用の方策・価値ネットとNNUE重みは不合格でも次世代へ継承する。
- 過去の長考・MCTS教師を `research-replay.json` に保持し、通常棋譜とともに繰り返し学習する。同一元対局の研究例は1バッチ最大1件という既存の制限を維持する。
- 自己対局用の親は本評価合格時だけ更新する。正式main Engine・163件の採用知識・枝刈り/時間配分は自動変更しない。

## 起動と上限

`REQUEST.json` の `enabled` をtrueにした明示更新で研究ブランチ上から実行できる。コード変更だけでは研究を起動しない。手動入口 `workflow_dispatch` も定義するが、GitHubの仕様により既定ブランチへのworkflow登録前は使えない。研究段階では明示REQUEST更新を使う。

`parameters.mode=standard` は上表の既定値。`generations` は1〜3、既定3。1世代ごとの保存/検証が完了すると、同じActions内の次の再利用workflowへ自動移行し、予定世代数で終了する。チャットの開閉を進行条件にしない。無期限実行や未承認の定期起動はしない。

`mode=smoke` は20ランナー・40自己対局・20短時間分析・40評価対局・2世代・幅32/1epochの接続検証。予備評価を明示的に省略して本評価の配線を検査するが、研究親更新を強制的に禁止する。50分研究や棋力改善の証拠にはしない。

## 障害と再開

- 先後2局、完了した研究段階、学習epochでcheckpointを残す。失敗しても他の正常laneを中止しない。
- 成功/失敗のworker成果物にはタスク・世代・実モデルの識別と全ファイルSHAを付ける。集計時に欠落、混在、破損、先後不整合、条件違いを拒否する。
- GitHubの失敗ジョブ再実行では、当該ジョブの前回checkpointを復元し、完了済みの対局・研究段階を再利用する。探索木の途中は復元せず、その段階から読み直す。強制的なマシン消失でartifactも未保存なら、そのlaneの未保存部分は再計算する。
- 完了した世代は月別データReleaseに保存し、全パーツの再取得SHAを検証する。検証済み世代の全棋譜・研究記録・worker受領記録を保存した後、その世代の重複した一時受け渡しartifactを削除し、次世代が使う完了stateと保存証跡は残す。200MiBを超える圧縮データは分割する。全棋譜・候補NNUEと最新の学習optimizerを残し、PV・探索木を長期蓄積しない。
- 別runからは保存したmanifest名を `checkpoint` に指定する。計画と実装ハッシュを照合し、未完了の次世代から再開する。学習方式を変える場合は別計画として管理する。

## 検証

`python3 -m unittest discover -s tests -p test_neural_cluster.py`

先後対の20分割、ランナー数に依存しないseed、完了対の再利用、混在/破損/欠落の拒否、累積教師、既研究/評価群の除外、保存原本の全着手保持とSHAを検査する。実際の20ランナー実行結果はjournalへ追記する。
