# 自己対局学習の2周実行

2026-10-19、オーナーは「とりあえず２周させてみて。」と指示した。前回の停止を今回の2周の範囲で解除し、保存済み研究親G1・300局・次候補3案から再開する。

条件の正本は同じcommitの `PLAN.json`。1周は候補の事前検査、各100局の選別、最良1案の別seed1000局確認、研究親の更新判定、次の親同士300局と再学習である。確認へ進めない場合は親を保持する。2周で親を2回更新できるという意味ではない。最大3200新規局、2周とも進行条件に届かなければ最後の300局を省き、理由を残す。

固定Engineは正式v2.0.21のcommit 4448f40400a893feb3b4d79237111008026547da。200ms、条件付き長考、先読み、2スレッド、同一の採用知識163件を使用する。差分25/50/100%の3候補、選別50%以上、確認の全局と重複除外後の両方で概算95%下限50%超という既存基準を維持する。次周の比較相手と特徴計算に更新後の親を渡す。

初回の保存モデルは学習材料・分割・候補の整数設定を再現し、その凍結済み候補を使用する。CPUの数値還元による浮動小数末尾の差だけは1e-12以内で照合し、再計算したモデルと元モデルを両方保存する。元モデルの世代内分離を、世代間分離が済んでいたと扱わない。後続学習では過去の実戦記録から既知の完全棋譜と局面hashを除外し、検証に触れたデータを未使用へ戻さない。各群50局面に足りなければ材料不足を保存し、確認対局を起動しない。8局面の診断観測は学習ラベルに加えない。

全実戦手・終局・設定・実バイナリ・知識を検査し、月別データReleaseへ保存、再取得hashとAPI digestを照合する。操作意図→本体ID→監査と保存→判定の順にrevision付き台帳を追記する。返答不明な操作は再送しない。復旧しても保存済み本体を再利用し、予算とseedをリセットしない。2周分が終わるまで同じ制御runが次工程を担当し、ChatGPTの確認タスクから別に次世代を起動しない。

継続確認はR21どおり一回限りの終了予定で1本を更新する。正常な現在の工程に合わせてETAを見積もる。完了時は2回の判定、必要な次回用モデル、全保存記録を読み戻して報告し、タスクを停止する。正式mainのEngine、既定配点、版、知識、比較基準は今回更新しない。
