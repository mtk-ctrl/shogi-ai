# 自己対局を改善へ返す多世代循環

正式採用から独立した研究基盤。実装は`tools/research/postgame_runtime.py`、実働アダプターは`.github/scripts/run_postgame_spiral.py`、入口は`postgame-spiral.yml`。既存対局本体を変更/複製せず利用する。

1. 開始前に親Engine commit、採用知識hash、研究親の9軸、学習/検査条件、各世代の独立seed、世代上限/総局数上限をPLANへ凍結する。
2. 同じ親同士の原本を生成し、全実戦手・終局・設定・先後・長考上限・保存バイナリ/知識を検査して月別Releaseへ保存する。
3. 現在の研究親で再分析する。長い探索の方が同じ手を支持し、共通完了深さの対比較が成立し、現在の親がその手を選べず、静的順位も誤る例を評価学習へ渡す。勝敗の報酬は実際の着手前局面だけに属し、勝者の全手や仮想分岐へ正解を貼らない。
4. 同一局/局面/近似駒組みをまとめ、訓練/検証/未使用の台帳を世代間で保持する。同じ親の適格例は蓄積し、親更新後は旧特徴を無効化する。原本と選別研究は残す。未使用群の再利用・衝突は隔離する。
5. 事前固定の1候補を作る。9軸だけ親から最大±5%、学習率0.02/100epoch、報酬項0.1。32対比較・独立群8/4/4未満なら変更を作らない。
6. 実バイナリの無効時固定深さ一致・自作12取り合い回帰・未使用例での着手改善・200ms探索深さ合計90%以上を検査する。近似学習損失だけで対局へ進めない。不合格は正常な候補棄却、監査/保存の故障は停止とする。
7. 同じ正式条件で候補対親100局、得点率50%以上なら固定候補の200局を一度だけ行う。全手監査・完全棋譜重複感度・保存を照合し、両方の概算95%下限50%超で研究親を更新する。全棋譜が既存と重なれば検証不能として親を保持する。
8. 予算内なら次の研究親同士の自己対局へ戻り、尽きれば完了する。正式採用・main Engine・版・既定値・163件知識・baselineの更新は行わない。

原本と研究packageはRelease、操作台帳は連番JSON資産として追記する。操作ID・入力hash・APIの本体run IDを保存する。応答不明時は再送せず停止し、同じ本体の状態を確認して復旧する。途中の監査修正で対局をやり直さない。実行コード変更の無断継続も拒否し、調査した修正は明示repairと新しい監査codehashで記録する。

1つの手動run内で次工程まで継続するため、毎時の再開タスクを使わない。長時間実行を会話の外へ持ち越すときだけ、R21の同一一回限り確認タスクを実測終了見込みへ合わせる。内部CLIの既知run待機はGitHub APIの通常機能であり、ChatGPTの反復予定ではない。

通常比較まで接続している経路は評価学習と、下記の第2段階Bの研究知識である。知識だけのPLANは評価学習を行わず、検証/未使用群の候補評価も消費しない。新候補の正式採用は含めない。正しく動くことと強くなったことは別の検証であり、材料不足なら無理にモデルを作らない。

新PLANで`progress_policy: {schema: postgame-progress-policy-v1, max_stagnant_preparations: 2}`を固定すると、全選別例の理由、学習材料の観測割合、独立群の不足、元の局数/手数/再分析秒数を残す。不足が2回続けて減らなければ追加対局を止めて`research_review_required`とする。確認済みの改善手が学習群にある場合は、静的順位が正しくても知識検証待ちにできる。実行器が未接続ならその旨を保存し、評価候補も作れなかったまま次の原本を追加しない。学習/検証の分離、過去の履歴、既存の採否条件を保持する。[全14案と段階実装](../self-improvement-20261017/ROADMAP.md)。この制御は旧PLANに黙って適用しない。

第2段階Aとして、新PLANの`knowledge_policy`で固定する研究知識の準備を接続した。学習群の証拠と実バイナリを照合し、親の再確認・候補生成・実Engine検査・A/B別配布入力をprepareのpackageへ保存する。読取り専用検査は知識hash・元知識保持・配布情報を照合する。この第2段階A時点では100/200局dispatchと知識引継ぎが未接続だった。後続の段階Bの現在地は下節を参照する。詳細は[計画](../self-improvement-20261017/KNOWLEDGE_PLAN.md)。正式snapshotを候補へ置き換える方法は使わない。

実働検証は[2世代試験](spiral-auto-smoke-20261017-01/PLAN.md)と、そのRESULTS/measurementを参照する。


予算の終わった循環を、同じIDの上限増加で延長しない。次に明示起動するPLANの`predecessor_checkpoint`へ、完了台帳のRelease名/asset名/SHA256/bytesを固定できる。同じ研究親・学習アルゴリズムであること、前回seedとの非重複を検査して、適格例と分割/未使用台帳、全棋譜重複索引を引き継ぐ。新たな予算も開始前に固定し、古い未使用群を新規扱いへ戻さない。アルゴリズムを変えた旧特徴はそのまま渡さず、再分析が必要として拒否する。

## 研究待ち実行と知識だけの研究循環

新PLANの`followup_policy`は`postgame_followup.POLICY_FOLLOWUP`へ固定する。学習群の課題を元の実バイナリ/知識/全履歴で追加解析し、親ごとの再試行を防ぐ。元観測は保存し、追加で安定した研究手を確認できた場合だけ分割台帳を保持して準備し直す。

`candidate_kind=knowledge`は`knowledge_execution_policy`を固定した新PLANだけで利用する。既存研究pilotの`spiral_checkpoint`へ保存済み操作意図を渡し、元バイナリとA/B別snapshotを復元して既存arena/実戦手保存/終局再生を使う。Issue入力や汎用engine-matchを拡張しない。比較で追加知識の実使用が0なら確認へ進まず、確認失敗時も親を保持する。成功時だけ研究親の知識を引継ぎ、次のsourceは両者ともその知識を使う。正式採用は行わない。

[第2段階Bの実測](../self-improvement-20261017/FOLLOWUP_RESULTS.md)では、8件の追加解析を行ったが新規知識0だった。100/200局と研究親更新の分岐は合成検査、実Engine確認は短い配線試験まで。これを実際の知識更新・棋力向上の証拠にしない。

後続の[第3段階B](horizon-return-20261018-01/RESULTS.md)では、読み足し候補9局面から研究知識1件を作り、対象検査と実際の通常100局まで実行した。42勝57敗1分、新知識使用0回のため確認対局・研究親更新へ進まず終了し、保存と台帳の読み戻しまで成功した。知識を次世代へ更新した実績や棋力向上の証拠はまだない。

[第3段階C](practice-cycle-smoke-20261018-01/RESULTS.md)で、材料不足時の分岐練習を通常の世代制御へ接続した。別予算と親別完了IDを固定し、全履歴/群分離の監査を通った練習だけを再分析/知識候補の準備へ渡す。固定試験は3世代・実戦6局654手と自動練習8局128新規手、計40局面の再分析を実行し、練習2回/8局と停滞5回で正常停止した。更新0で全8工程の読戻しまで成功。次は局面段階・失敗型・過去の自作相手と保持問題の拡充であり、練習から有効知識を更新した研究親の循環と長期の棋力成長は未実証である。

[第4段階A](diverse-practice-20261018-01/RESULTS.md)では、学習用に残る原本から先後×序中終6局面を固定し、現行/攻め寄り/守り寄り設定を相手に30練習局450新規手を指した。全子孫の群確認後に8局面を再分析し、保持問題は前後12/12、更新0で保存/読戻しまで一致した。終盤の別分岐で詰まされた1課題・3観測を再確認待ちに残す。この段階は保存局面での固定試験であり、多様化選択を通常世代へ自動挿入する部分、過去版相手の復元、勝ち切り/受け切り率と棋力向上は未確認。次の第4段階Bで課題の現行200ms/詰み確認と世代制御への接続を扱う。
