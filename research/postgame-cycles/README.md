# 自己対局を改善へ返す多世代循環

正式採用から独立した研究基盤。実装は`tools/research/postgame_runtime.py`、実働アダプターは`.github/scripts/run_postgame_spiral.py`、入口は`postgame-spiral.yml`。既存対局本体を変更/複製せず利用する。

1. 開始前に親Engine commit、採用知識hash、研究親の9軸、学習/検査条件、各世代の独立seed、世代上限/総局数上限をPLANへ凍結する。
2. 同じ親同士の原本を生成し、全実戦手・終局・設定・先後・長考上限・保存バイナリ/知識を検査して月別Releaseへ保存する。
3. 現在の研究親で再分析する。長い探索の方が同じ手を支持し、共通完了深さの対比較が成立し、現在の親がその手を選べず、静的順位も誤る例を評価学習へ渡す。勝敗の報酬は実際の着手前局面だけに属し、勝者の全手や仮想分岐へ正解を貼らない。
4. 同一局/局面/近似駒組みをまとめ、訓練/検証/未使用の台帳を世代間で保持する。同じ親の適格例は蓄積し、親更新後は旧特徴を無効化する。原本と選別研究は残す。未使用群の再利用・衝突は隔離する。
5. 事前固定の1候補を作る。9軸だけ親から最大±5%、学習率0.02/100epoch、報酬項0.1。32対比較・独立群8/4/4未満なら変更を作らない。
6. 実バイナリの無効時固定深さ一致・自作12取り合い回帰・未使用例での着手改善・200ms探索深さ合計90%以上を検査する。近似学習損失だけで対局へ進めない。不合格は正常な候補棄却、監査/保存の故障は停止とする。
7. 同じ正式条件で候補対親100局、得点率50%以上なら固定候補の200局を一度だけ行う。全手監査・完全棋譜重複感度・保存を照合し、両方の概算95%下限50%超で研究親を更新する。全棋譜が既存と重なれば検証不能として親を保持する。
8. 予算内なら次の研究親同士の自己対局へ戻り、尽きれば完了する。正式採用・main Engine・版・既定値・163件知識・baselineの更新は行わない。

原本と研究packageはRelease、操作台帳は連番JSON資産として追記する。操作ID・入力hash・APIの本体run IDを保存する。応答不明時は再送せず停止し、同じ本体の状態を確認して復旧する。途中の監査修正で対局をやり直さない。実行コード変更の無断継続も拒否し、調査した修正は明示repairと新しい監査codehashで記録する。

1つの手動run内で次工程まで継続するため、毎時の再開タスクを使わない。長時間実行を会話の外へ持ち越すときだけ、R21の同一一回限り確認タスクを実測終了見込みへ合わせる。内部CLIの既知run待機はGitHub APIの通常機能であり、ChatGPTの反復予定ではない。

現在の自動経路は評価学習。局面知識候補の研究記録は保持するが、新規知識の自動実装/正式採用はこの経路に含めない。正しく動くことと強くなったことは別の検証であり、材料不足なら無理にモデルを作らない。

実働検証は[2世代試験](spiral-auto-smoke-20261017-01/PLAN.md)と、そのRESULTS/measurementを参照する。


予算の終わった循環を、同じIDの上限増加で延長しない。次に明示起動するPLANの`predecessor_checkpoint`へ、完了台帳のRelease名/asset名/SHA256/bytesを固定できる。同じ研究親・学習アルゴリズムであること、前回seedとの非重複を検査して、適格例と分割/未使用台帳、全棋譜重複索引を引き継ぐ。新たな予算も開始前に固定し、古い未使用群を新規扱いへ戻さない。アルゴリズムを変えた旧特徴はそのまま渡さず、再分析が必要として拒否する。
