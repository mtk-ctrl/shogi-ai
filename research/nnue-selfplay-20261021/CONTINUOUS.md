# 研究用ニューラル世代ループ

正式版の採否前に、対局→分析→学習→独立評価→研究親更新を接続する実装。既定の評価器と正式Engine名は変更しない。棋力向上は試験結果で別に判定する。

## 何が変わるか

- 配置・持ち駒・手番に加え、両玉の3×3領域と各駒の配置の関係を学ぶ43,346特徴。対局用は整数NNUE、探索中に差分accumulatorを維持する。旧KMNNUE01も読み込める。
- 初期NNUEには雲路自身の駒価値を2チャネルの事前知識として埋め込み、残りの多数の非線形特徴を学習する。既存エンジンを別途呼ぶ評価方式ではない。ランダム初期化の小型候補が通常対局で12戦全敗したため、駒得から毎回学び直す非効率を避ける改善を加えた。
- KMNNUE03は価値と14,256次元の着手方策を持つ。方策は合法手の探索順に使い、手を削除しない。`EvalNeuralPolicy=true`で有効。
- 研究用は2残差ブロックの方策・価値ネット。自前PUCTで異なる探索を行い、訪問分布と価値をNNUEへ蒸留する。ルールはnativeの`rules`照会で完全な着手履歴から判定し、千日手・連続王手・入玉を盤面だけで推定しない。
- 自己対局の完了探索値と終局結果で学習を立ち上げる。結果は局面価値の弱い観測であり「この手が正解」の断定には使わない。外部エンジンの教師・重みは使用しない。
- 初期予算は予備50ms、通常分析10分、重点分析50分、双方の候補の反証各10分。少なくとも1ケースには手の変更の有無に関わらず重点枠を割り当てる。反証結果も不確かな観測として保持する。
- 長考は完了した深度の最新値・各段階、学習はepoch境界の重み・Adam・乱数、比較は先後2局の組ごとに保存する。中断した探索木そのものを再開する機能ではない。
- 少数の長考教師を大量の通常局面に埋もれさせないため、学習バッチごとに研究教師を再抽出する。同じ元対局は1バッチに最大1件。長考で選んだ手を方策へ、局面評価を価値へ学習し、蒸留で薄めない。
- 元対局IDのハッシュで分割を固定し、新規対局を足しても所属が変わらない。同一盤面が別の群に現れたら全群から除外する。評価対局は学習へ流さない。
- 昇格は事前固定の局数、先後対のHoeffding下限、全予定世代と比較対象への多重比較補正を通過した場合だけ。200ms・最低200局・不正手/手数打切りゼロを必須とする。通常設定は1,000局。親と固定基準の双方を上回る。初期親が固定基準なら同じ比較を共用する。小標本や短時間の試験では昇格しない。
- 候補が負けてもループは次世代の自己対局と研究へ進む。対局用の親は合格時だけ更新する。研究中の学習器は不合格でも重みを引き継ぎ、学習を続ける。正式版の更新は別の採用判断。

## 実行

Python 3.11以降、C++17、numpy、python-shogi 1.1.1、PyTorchが必要。検証環境はPyTorch 2.14.1+cpu。GPUを必須にしない。

```sh
python3 -m pip install numpy python-shogi==1.1.1
python3 -m pip install torch==2.14.1+cpu --index-url https://download.pytorch.org/whl/cpu
python3 scripts/build.py --output build/shogi-ai
python3 tools/research/neural_loop.py \
  --archive-dir /absolute/path/to/verified-played-archive \
  --engine build/shogi-ai --knowledge position-knowledge-v1.tsv \
  --source-commit ACTUAL_40_HEX_BUILD_COMMIT \
  --output /absolute/path/to/durable-run \
  --generations 3 --selfplay-games 100 --match-games 1000 \
  --cases 4 --force-long-cases 1 --medium-ms 600000 \
  --long-ms 3000000 --branch-ms 600000 \
  --epochs 20 --width 128 --simulations 512
```

同一コマンド・同一保存先で再開する。検証済みの入力棋譜はrun内の`inputs/`にも複製し、取込元の一時フォルダが消えても再開できる。途中で入力・モデル・予算を変えたら同じrunを再利用せず、別runにする。`plan.json`に元原本・バイナリ・知識・初期親のSHA、予算を固定する。同時書込みはOSロックで防ぐ。障害は`state.json`に停止段階と理由を残し、再試行は最大3回。永久ループや不正入力の無視はしない。

出力の`gNNN/result.json`には完了した段階の累積実時間（中断段階の未記録時間を除く）、学習誤差、対局勝敗、昇格判断がある。`state.json`の`accepted`が研究親更新回数。`formal_engine_adopted`は常にfalse。計画上の時間配分を実績として表示しない。

短時間の配線試験では`--generations 3 --selfplay-games 2 --match-games 2 --cases 1 --medium-ms 100 --long-ms 200 --branch-ms 100 --epochs 2 --width 32 --simulations 16`等を明示する。これは棋力改善の証拠にならない。

## 保存と限界

実戦アーカイブは全着手を保持する。選択した少数の研究局面の値・根拠・root訪問分布と学習checkpointを別管理し、全候補PV・探索木は保存しない。出力先には永続ディスクを指定し、月別データReleaseへ保存後にSHAを再検証する。localで終了したこと、期限付きartifactが存在することを永続保存完了と報告しない。

大規模な分散GPU自己対局、持続的な自動クラウド再起動、ランナー間のオンライン共有、棋力上限の保証は含まない。まずCPUでも再開できる完結した研究ループを検証する。小データのモデルが強い既存評価器を直ちに上回るとは限らず、ゲートが通らないこと自体は異常終了ではない。
