# 強化ロードマップ

このロードマップは、強さだけを最短で追うのではなく、**何を追加すると、なぜ強くなるのか**を理解できる順番で進める。

## 現在のEngine基準

現在の正式Engine世代は **KUMOJI v2.0.0**。Evaluation-v2候補Bを正式採用しており、現行設定は `docs/33_v2.0.0世代基準.md`、正式な対局条件はR20を参照する。以下のv0.x系の数値・到達記録は開発史として読む。

# 当面の到達目標

## 目標1：将棋ができる

自作AIが将棋のルールに従い、スマホ上で対局を継続できる状態。

- ShogiDroid2から自作AIを呼び出せる
- USIで局面を受け取れる
- やねうら王のルール層から合法手を取得できる
- 反則手を指さず、成り・持ち駒・駒打ちを扱える

v0.0.2でPixel + ShogiDroid2上の約20手の継続対局を確認済み。終局までの実機確認は必要な節目で行う。

## 目標1.5：将棋らしく指せる

「将棋ができる」と「人に勝てる」の間の中間目標。

- ただで大駒を取られる手を減らす
- 取れる駒の価値を判断する
- 自分の玉がすぐ詰む手を避ける
- 1手詰めを見つける
- 相手からの1手詰めを避ける
- 3手目の詰みを読む
- 数手先を読んで手を選ぶ
- ランダムAIには安定して勝つ

v0.0.3で駒価値、v0.0.4で相手の1手先、v0.0.5でαβ探索、v0.0.6で3-ply、v0.0.7でmove orderingまで到達した。

## 目標2：ユーザーに勝てる

一度偶然勝つのではなく、実戦相手として継続的に上回れる状態を目指す。最初は1勝を節目とし、その後は10局程度で勝ち越しを確認する。勝敗だけでなく、不自然な手や序盤・中盤・終盤の弱点も改善材料にする。

## 目標3：既存の将棋アプリに勝てる

対戦対象のアプリ・レベル・持ち時間・先後・対局数を固定し、外部基準で棋力を測る。低いレベルから順に上げる。

## 目標4：やねうら王に勝てる

ルール層として利用しているやねうら王とは別に、完成した対戦エンジンとしてのやねうら王と対局する。

評価関数、バージョン、ハッシュ、スレッド、端末・CPU、持ち時間、先後、対局数を固定する。最初は条件を弱めたやねうら王への1勝を節目とし、その後に同条件での勝ち越しを目指す。

## Phase 4：αβ探索【達成】

v0.0.5で、v0.0.4と**同じ評価・同じ2-plyの答えを保ったまま**αβ探索へ置き換えた。

- 同一局面・同一seedの検証でv0.0.4と選択手が完全一致
- 100局の実戦局面では35,893,138局面のうち16,416,109局面だけを探索

詳細：`journal/2026-10-04_03_アルファベータ探索の導入.md`

## Phase 4.5：3-plyへ深化【達成】

v0.0.6で、評価関数はそのままに `自分 → 相手 → 自分` の3-plyへ探索を深くした。

- テスト専用の枝刈りなし3-ply minimaxと最善手を比較
- 固定2局面で69,748局面 → 21,285局面、約69.5%を枝刈りしながら答えは完全一致
- 通常探索で3手目の詰みを見つける固定テストを追加
- v0.0.5との100局：**99勝1敗0分、違法手0**
- 同一100局runの平均応答時間：13.676ms → 225.065ms、約16.5倍

- v0.0.6の100局探索ノード：131,661,844
- 3-ply末端だけで127,288,365局面を訪問

探索を1手深くする効果は非常に大きい一方、計算量も急増することが確認できた。**4-plyへ直進せず、3-plyを高速化してから次の深さへ進む。**

詳細：`docs/11_3手探索.md`、`journal/2026-10-04_04_3手探索の導入.md`

## Phase 5：実戦的な高速化

### 5A：手の並べ替え（move ordering）【達成】

v0.0.7で3-plyの深さ・駒価値・最善手の定義を変えず、読む順番だけを変更した。

優先順：

1. 王手
2. 高価値駒を取る手
3. 成る手
4. 相手の飛車・角の長い利きにさらされた自駒を動かす手
5. その他

並べ替え用の点数は局面評価には使わない。

固定4局面では、同じseedでv0.0.6と選択手を完全一致させながら52,114局面 → 13,594局面、**約73.9%削減**。

AMD EPYC 7763 / 2 vCPUでの10局スモークでは：

- 21,829,669局面 → 4,575,015局面、**約79.0%削減**
- 平均応答：286.292ms → 105.096ms、**約2.72倍高速化**
- 最大応答：7.44秒 → 1.68秒
- 違法手0

ここで、**同じ深さでも読む順番を工夫するだけで大きく高速化できる**ことを実測した。

詳細：`docs/12_手の並べ替え.md`、`journal/2026-10-04_05_手の並べ替え.md`

### 5B：置換表・反復深化・時間管理【実装】

v0.0.8で自作の固定サイズ置換表を導入し、思考ごとの世代更新と千日手履歴での無効化を実装した。v0.0.9はrootの歩・角・飛車の成り方針を追加した。v0.0.14で自作の可変深度αβ・反復深化・時間管理・思考中の停止処理を追加した。評価値と読み筋もUSIで送る。詳細は `docs/17_評価値表示と時間管理.md` を参照する。

## Phase 6：説明可能な特徴量評価【v0.0.10で実装】

駒得を基準に、玉周辺の守備配置、敵玉への実際の利き、大駒を含む有効な移動先、攻守と駒価値に基づく危険度を加えた。重複と過大評価を避ける上限を設け、各柱の内訳と調整パラメータを公開した。探索方式は変えていない。

詳しい計算式：[特徴量評価](14_特徴量評価.md)。結果・採否：[開発記録](../journal/2026-10-04_07_特徴量評価の導入.md)。

次の順序を基本とする。

1. 手動の初期重み：今回の出発点。最適値とは扱わない。
2. **1パラメータずつ自己対局で調整：v0.0.11〜v0.0.13で実施済み。** この4特徴の値はv1系の履歴である。現在はEvaluation-v2候補Bを採用しており、現行値は `docs/33_v2.0.0世代基準.md` を参照する。
3. 複数パラメータ最適化：個別感度を把握し、対局集合・停止基準を固めてからSPSA等へ進む。小標本への過適合と上限での飽和に注意する。
4. 反復深化・可変深度・時間管理：v0.0.14で実施済み。評価実験とは別変更として導入し、以後の時間制限付き探索の土台にしている。
5. 対局をまたぐ長期経験DB：今回の棋譜と固定問題で足りる段階では導入しない。評価版・探索条件を区別して蓄積する必要がある。
6. NNUE：人が設計した特徴量の限界と学習データの品質を把握してから検討する。

# 現在の評価原則

新しい研究候補の正式採用はオーナーが判断し、AIは検証結果・根拠・懸念と採用案を報告する。判断分担と採用後の反映手順はR10を正本とする。

正式な候補採否の対局条件・標本の扱いは `docs/rules/R20_対局・比較・統計.md` を正本とする。
100局はよく使う比較単位だが固定義務ではなく、スクリーニング、Diagnosis、固定深度回帰、外部Benchmarkは目的別条件を使う。
通常pushはR10どおり必要な軽量CIだけを行い、対局smokeを一律には自動実行しない。

記録するもの：

- 勝・敗・引分
- 得点率
- 違法手
- 1手あたり平均・最大応答時間
- 探索ノード数
- 枝刈り数・削減率
- 探索深さ
- GitHub ActionsのCPU条件
- 特徴的な勝ち方・負け方
- 必要な節目ではPixelでの指し味、温度、電池消費

少数局だけで採用判断をしない。ただし探索アルゴリズムの最適化では勝率よりも、**同一局面で答えが一致することと計算量の削減**を強い根拠とする。Pixel実機確認は、自動試験では確認できない節目だけ行う。

### 2026-10-05：v0.0.18 詰み探索の直接着手・7手対応

v0.0.17に残っていた「生成済み手をUSI文字列へ変換し、再度全合法手から探して着手する」処理と、詰み探索内の重複合法手生成を削除した。ルール層はopaqueな生成手tokenを返し、戦略層へやねうら王の探索型は公開しない。

同一runnerの固定3/5手各1,000問ではnodes中央値を変えず、中央値を3手約8.34倍、5手約16.43倍高速化した。固定7手100問も2秒上限で100/100正解したため、探索上限を7 plyへ拡張した。

次の順序は、(1)詰み探索専用move ordering、(2)詰み探索専用TT・同一局面重複削減、(3)固定7手で再評価、(4)9手へ拡張、(5)必要ならDFPN自作、である。通常`go`への組込みは別変更とし、1手50ms同条件対局で採用判断する。

詳細：[詰将棋探索](19_詰将棋探索.md)、[ベンチ](20_詰将棋ベンチマーク.md)、[v0.0.18開発記録](../journal/2026-10-05_06_v0.0.18詰み探索直接着手と7手対応.md)。

### 2026-10-05：v0.0.19 通常goへの攻守詰み補助

時間制限付き通常`go`の前段に1～3手のMateAssistを追加した。攻撃側はroot候補内の強制詰みを即決し、防御側は各候補を仮着手して相手の1～3手強制詰みが証明された候補だけを除外する。timeout・未証明は除外せず、全候補が詰む場合は元の候補集合へ戻す。

50ms、Experience Cache OFF、同一バイナリのON/OFFを別seedで100局ずつ比較し、合計200局でONが109勝85敗6分、得点率56.0%、違法手0。MateAssistの加重平均実測時間は約1.04ms/回だった。1回目45.5%、2回目66.5%と振れが大きいため増加量は精密に断定せず、固定攻守テストと合計結果を合わせて採用した。

通常`go`へ常時入れるのは1/3手までとし、5/7手は局面条件付きで攻守双方へ拡張する。詳細：[v0.0.19開発記録](../journal/2026-10-05_08_v0.0.19通常go詰み補助.md)。
