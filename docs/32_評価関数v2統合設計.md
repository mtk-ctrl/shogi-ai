# 評価関数v2 統合設計

## 0. 採用状況（2026-10-07）

本設計に基づくEvaluation-v2は、候補Bを**雲路 KUMOJI v2.0.0**の既定評価として正式採用した。

採用値は Material=100 / Safety=500 / Pressure=474 / Activity=150 / Danger=200 / Influence=19 / Potential=25 / Coordination=50 / HandPotential=60 / Threat=0 / PositionalCap=5000。

正式思考条件のB対C 1,000局は596勝22分382敗（B得点率60.7%）。やねうら王Material尺度はLv48 54.5%、Lv49 47.0%、Lv50 43.0%で、現行基準を「Lv49相当（互角帯Lv48～49）」とする。

以下の1～12節はv2を作った設計思想・検証標準として保持する。「現行評価」「今後」等の記述の一部は設計開始時点（2026-10-06）の文脈であり、採用後の現行値は `docs/33_v2.0.0世代基準.md` を正本とする。

## 1. 目的

雲路の評価・探索・move orderingを、2026-10-06時点の研究結果に基づいて再整理する。

これまで雲路は、駒得を基盤にSafety / Pressure / Activity / Dangerを追加し、その後Influence、Potential Mobility、持ち駒の両取り・串刺し等を研究してきた。

ここで明確になった問題は、個々のアイデアが悪いことではなく、**新しい将棋観をどこへ実装するか**である。

- orderingだけに入れた考え方は、読む順番を変えるだけであり、探索がその価値を実現するところまで届かなければ最終評価に残らない。
- 静的評価へ入れた特徴も、現行では全非Material項目が`positional_cap=300`に収められる。
- Materialは歩=100、銀=500、金=600、角=800、飛=1000であり、位置評価全部で最大300という構造は、結果としてMaterialを強く支配的にする。

v2では、**詰み・勝敗だけを絶対優先し、それ以外は複数の局面価値を重み付きで統合する**。

## 2. 優先関係

### 2.1 絶対優先するもの

ルール上または探索上、勝敗が証明された場合は通常の評価値を超えて扱う。

```text
勝ち（詰み・宣言勝ち等）
  >
非終局の総合評価
  >
負け（被詰み等）
```

短い詰みを長い詰みより好む、負けるなら長く抵抗する等の距離調整はこの終局層の中で扱う。

### 2.2 非終局では「最優先feature」を置かない

Material、Safety、Pressure、Danger、Influence、Coordination、Mobility、Threat等は、どれも局面によって価値が変わる。

したがって「駒得を最優先」「効きを最優先」「両取りを最優先」のような固定序列は作らない。各featureを同じ評価ベクトルへ載せ、重みと局面条件によって総合点を作る。

Materialは重要であり、点数尺度の基準にも使う。しかし、**他featureを最大3歩分に制限するための上位概念にはしない。**

## 3. 3つの責務を分離する

### A. Static Evaluation — その局面はどちらが良いか

探索がその局面で終了しても残るべき価値を表す。

例:
- Material
- King Safety
- Pressure
- Danger
- Influence
- Coordination
- Mobility / Potential Mobility
- Space
- Flexibility
- Hand Potential
- Threat（両取り・串刺し・未実現の戦術利益）

### B. Move Ordering — どの枝から読むか

同じ深さを完了したαβ探索の答えを変えるためではなく、同じ答えへ少ないnodes・短い時間で到達するために使う。

例:
- TT move
- previous iteration PV
- 王手
- captures
- promotion
- 軽量Threat signal
- 軽量Influence改善予測

**局面価値をordering点だけに持たせない。**

### C. Search Horizon Control — どこを追加で読むか

静的評価を置くには局面が不安定なときに追加探索する。

例:
- qsearchの駒取り・成り
- 王手中の全応手
- proven mate search
- 将来の限定的なthreat extension
- AdaptiveLongThink

評価featureをここだけに実装しても、「追加探索が間に合わなければ価値ゼロ」になるので注意する。

## 4. 評価ベクトル

初期のv2候補は、少なくとも次を独立内訳として保持する。

```text
Material
KingSafety
Pressure
Danger
Activity
Influence
Coordination
Mobility
PotentialMobility
Space
Flexibility
HandPotential
Threat
```

すべてを一度に本番実装する必要はない。未実装項目は0でよい。重要なのは、後から増やすfeatureがMaterialの従属補正ではなく、同じ統合器へ追加できる構造にすることである。

総合値の概念形は、

```text
StaticScore(s)
  = Σ phase_weight_i(s) × feature_i(s)
```

とする。

最初は固定weightで開始し、phase_weightは後段で導入する。

## 5. capの再設計

cap自体は悪くない。1つのfeatureが異常値で全体を支配するのを防ぐsoft capは必要になり得る。

問題は、**異なる意味を持つ全非Material特徴を最後にまとめて±300へ切ること**である。

v2では次を分ける。

- feature固有のsoft cap：暴走防止
- 総合StaticLimit：mate scoreと衝突しない安全限界
- global positional cap：原則として廃止または十分大きくし、必要性を実験で判断

最初の実験では現行4featureの計算式を変えず、`positional_cap`だけを 300 / 450 / 600 / 実質無制限で比較する。これにより「特徴の内容」ではなく「器の狭さ」だけを切り分ける。

## 6. Threat — 未実現の利益を局面価値にする

持ち駒の両取り研究で最も重要な変更点である。

### 6.1 orderingだけでは不十分

銀打ちで飛車と金を同時に狙っても、まだ駒を取っていない葉ではMaterialは増えない。orderingでその手を最初に読んでも、200ms内に利益実現まで読めなければ、最終評価へ両取り価値が残らない。

### 6.2 局面からThreatを評価する

両取りを「直前にこの手を指したから」という履歴依存の点ではなく、**現在盤面に存在する未解決の脅威**として評価する。

例:
- 1駒が複数の相手駒を攻撃している
- sliderの前後に高価値駒が並ぶ串刺し
- 王手への応手後にも駒取りが残る形
- 守備駒を動かしにくくする多重圧力

初期版では完全な合法応手全列挙を行わず、AttackMap、標的価値、攻撃駒の安全性、支え、最安攻撃/守備駒等から軽量に見積もる。

### 6.3 実現価値への受け渡し

Threatは永久ボーナスではない。

```text
両取り成立直後
Material 0 + Threat +X

相手が一方を逃がす
Material 0 + 残ったThreat +Y

実際にもう一方を取る
Material +実現利益
Threatは消滅または大幅減
```

この構造により、浅い探索では未実現価値を補い、深く読めた場合はMaterialへ自然に置き換わる。

二重計上を避けるため、Threatの係数は「期待される将来利益」の割引値として調整する。

## 7. 既存研究の読み替え

### Influence

Influence研究はorderingではなく静的評価へ実装されており、方向自体はv2と一致している。

ただし現行と同じ`positional_cap=300`の内側にあるため、旧実験の勝率だけで「効きに価値がない」とは結論しない。v2の器で再検証する。

### Potential Mobility

Potential Mobilityも静的評価として実装されているため、考え方は維持する。

これもglobal positional capの影響を受ける。固定局面でfeature値が正しくても最終totalで切られていないかを必ず記録する。

### Hand-drop fork / skewer

PR #5はordering専用である。400局51.625%という結果は「軽量orderingとして大きな害はなかった」という証拠として残すが、「両取り自体の局面価値」の検証にはなっていない。

v2では同じ幾何判定をThreat featureとして再利用し、orderingは補助用途にする。

### Legal-response full validation

相手の全合法応手を事前に列挙する実験は、200msで探索nodesを大きく失った。実効性の考え方は残すが、別のミニ探索を各候補へ行う方式は採用しない。

相手の最善反論の詳細は本来のαβ探索に任せ、静的Threatは軽量な割引推定に留める。

## 8. 検証標準

新featureは勝率だけで判断しない。

### Stage 1: Feature unit test

- 黒白反転で符号が反転する
- 良化/悪化の固定局面で期待方向に動く
- 既存featureとの二重計上を説明する
- cap前/後の値を記録する

### Stage 2: Horizon-retention test

「利益をまだ実現していない局面」を用意し、探索がそこで止まってもfeatureが価値を残すか確認する。

両取りなら、実際の駒取りまで読ませなくても両取り局面が非両取り局面より高くなることを確認する。

### Stage 3: Fixed-depth / fixed-node

時間揺らぎを排除して、評価の変更そのものが選択をどう変えたかを見る。

orderingだけを変えた試験では、同じ深さが完了すれば最終値・最善手が一致することを原則確認する。違うならordering以外の要因を疑う。

### Stage 4: 200ms controlled match

評価変更の純粋効果を測るときは、まずAdaptiveLongThinkをOFFにした同一200msで比較する。

評価値変更はAdaptiveLongThinkの発動条件自体を変え得るため、最初からONだけで比較すると「評価改善」と「時間配分変更」が混ざる。

### Stage 5: Product-condition match

最終採用前に、正式運用条件の200ms + AdaptiveLongThink ONでも比較する。

### Stage 6: Ablation / interaction

全部入りを基準に、

- all - Threat
- all - Influence
- all - PotentialMobility
- all - Safety

のように1軸ずつ外し、全体の中で寄与しているか測る。

単独で弱いfeatureでも他featureとの補完で効く場合があるため、単独試験と統合後ablationの両方を残す。

## 9. 次の実装順

### V2-0: 計測を強化

- positional_unclamped
- global cap適用量
- feature別weighted term
- feature別soft-cap飽和数
- Materialとの差

を対局ログへ残せるようにする。

### V2-1: global positional cap実験

現行4featureは変えず、300 / 450 / 600 / 実質無制限を比較する。

ここで「駒得中心性がcap由来か」を最初に検証する。

### V2-2: Threat feature

両取り・串刺しの未実現価値を静的評価へ追加する。最初は持ち駒打ち由来だけに限定せず、盤面上の多重攻撃として現在局面から算出する。

### V2-3: Influence / Potential Mobility再評価

既存研究コードをv2統合器へ移植し、旧global capの影響を除いて再検証する。

### V2-4: Coordination / Hand Potential / Space

一つずつfeatureとして追加し、unit test → horizon retention → fixed search → 200ms → ablationの順で評価する。

### V2-5: Phase-dependent weights

固定weightの相互作用が理解できてから、序盤・中盤・終盤、攻勢・守勢で重みを変える。

## 10. 採用基準

新しいfeatureは、次を満たすことを目標とする。

1. 機械的定義が明確である。
2. 固定局面で意図どおりの値を出す。
3. 読み切れない局面でも、その概念が本来持つ価値を静的評価に残せる。
4. 既存featureとの二重計上が説明できる。
5. 計算負荷を測定できる。
6. 200msで棋力を維持または改善する。
7. 全体統合後のablationでも存在価値を示す。

勝率が小標本で50%を割っただけで思想を捨てない。ただし、理屈が良いという理由だけで本番採用もしない。**featureの定義、評価への反映、探索との役割分担、実戦結果のどこに問題があるかを分解して判断する。**

## 11. 目指す最終形

```text
                ┌─ Mate / terminal proof ─→ 絶対優先
                │
Legal moves ─→ Search
                │
                ├─ Move ordering ───────→ 速く読む
                ├─ Horizon control ─────→ 必要な所を追加で読む
                │
                └─ Leaf position
                       ↓
                Evaluation Vector
                Material / Safety / Pressure / Danger
                Influence / Coordination / Mobility
                Potential / Space / Flexibility
                Hand Potential / Threat / ...
                       ↓
                weighted integration
                       ↓
                non-terminal position value
```

雲路が目指すのは「駒得を中心に、他の考え方を少し補正するAI」ではない。

**勝敗を最上位に置き、その下では複数の将棋観を同時に見て、局面全体として価値を判断し、その判断を探索で確かめるAI**である。


## 12. 2026-10-06 夜間探索への更新

初期v2設計では、まず固定weightを理解してからphase-dependent weightへ進む方針としていた。この方針は維持するが、固定weightの探索方法を更新する。

### 探索幅

初期の0.5倍 / 1倍 / 2倍の3水準は、仮置き中心値への依存が強すぎるため本探索には狭い。

夜間本探索では各軸を **0.2 / 0.5 / 1 / 2 / 5倍** の5水準で探索する。低端と高端で25倍の幅を持たせ、Materialと他featureの相対価値が10倍程度異なる可能性を排除しない。

### 直交配列

10因子5水準の完全総当たり9,765,625設定の代わりに、strength-3の5水準直交配列3,125設定を使う。任意の3因子までの水準組合せを均等に観測する。

### Multi-fidelity

100msを広域探索の中心に使い、代表設定を50ms / 200msで再評価する。低時間結果は候補削減の単独根拠にせず、200msとの相関を測った上で利用する。

### 段階的な切捨て

候補削減は勝率順だけで行わず、推定値、不確実性、因子水準のカバレッジ、強い相互作用領域を同時に残す。特定水準を長期的に捨てる場合は、その水準を含む有望な相互作用領域も弱いことを確認する。

詳細な経緯・夜間計画は `journal/2026-10-06_11_評価関数v2夜間大規模探索前整理.md` を参照する。
