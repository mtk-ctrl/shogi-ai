# 静止探索

## 目的

通常の探索を3手などで区切ると、「歩を取った直後」で評価し、その飛車を相手が取り返すところまで読まない場合がある。静止探索は、通常探索の末端で駒の取り合いや成りを追加で読む。

評価関数と重みはv0.0.14のまま。やねうら王からは従来のルール層だけを利用し、静止探索は自作する。

## 読む手と終了条件

| 局面 | 処理 |
|---|---|
| 終局済み | 千日手・連続王手・詰み等のルールによる点数を返す |
| 王手されていない | 現在の評価を基準に、合法な駒取り・成りを読む |
| 王手されている | 現在の評価だけで打ち切らず、玉の移動・合駒・駒取りを含む全合法応手を読む |
| 静止探索が8-plyに達し、王手されていない | 計算量の上限として現在の評価を返す |
| 全体で128-plyに達した未終局局面 | 今回の深さの探索を中断し、最後に完了した反復の結果を使用する |
| 時間・nodes・stopの上限 | 通常探索と同じ中断処理で盤面を戻し、最後の完了結果を返す |

王手されていないときの現在評価をstand patと呼ぶ。実際にパスを指すわけではなく、取り合いをこれ以上進めない場合の評価の基準にする。PVにはパスを入れない。手を動かさなければ有利でも、実際には動かすことで不利になる局面を完全に扱う仕組みではない。

捕獲される駒がない通常の王手や駒打ちは追加探索に含めない。ただし王手回避の駒打ちは含める。駒取りでない成りは含める。相手の合法な不成や、銀・桂・香の選択肢は引き続き残す。

8-plyは取り合いが必ず終わる保証ではない。王手中は8-plyを超えて応手を読むが、王手を抜けた時点で上限に達していれば静的評価へ戻る。上限で切った回数は`qlimit_leaves`で確認できる。

## 置換表とExperience Cache

静止探索を有効にすると通常の3-plyを超えて読むため、v0.0.14の「履歴に重複がなく、3-ply以内なら盤面キーだけでスコアを共有する」という条件を使えない。

静止探索ONでは、通常探索のスコア用TTは履歴を含むキーに統一する。静止探索そのものにはスコア用TTを使わず、深さや王手回避の延長が異なる結果の混同を防ぐ。正しさを優先した初期実装であり、TTの共有機会が減るコストがある。

Experience Cacheは従来どおり読む順番へのヒントだけに使う。静止探索内の結果は保存しない。探索方式の署名を更新し、ON/OFFも署名へ含めるため、v0.0.14や異なる設定の保存済みキャッシュを再利用しない。

## USIと比較

`Quiescence`はON/OFF比較用のcheck optionである。

```text
setoption name Quiescence value true
position startpos
go movetime 50
```

- `depth`：完了した通常探索の深さ。静止探索分を加算しない。
- `seldepth`：今回のgoで訪問した最大の深さ。静止探索を含む。
- `nodes`：通常探索と静止探索を合わせた訪問数。通常末端から静止探索へ移るだけでは二重に数えない。
- `qnodes`：静止探索内で処理した局面数。nodesの内数。
- `qcutoffs`：静止探索の枝刈り回数。従来の通常探索のcutoffsとは分ける。
- `pv`：選ばれた通常探索の手と、続く静止探索の読み筋。stand patやキャッシュのため途中までになる場合がある。

評価値は思考開始時の手番側を基準とする。詰み手数には静止探索で読んだ手も含め、連続王手による敗北を詰みとして表示しない。

## 検証方法

`tests/quiescence_test.cpp`では、枝刈り・TT・並べ替えのない独立minimaxと比較する。駒取り候補はUSI文字列の宛先判定を流用せず、着手前後の持ち駒の変化から判定する。先後の毒歩、王手中の静かな玉移動、合駒、駒取りでない成り、静止探索途中の中断、連続王手の終局を扱う。

`tests/test_search_usi.py`では、実際のUSI経由でON/OFFの切替、評価値・合法なPV、探索深さ、時計・nodes・stop・ponderhit・quitを確認する。

`benchmarks/compare_quiescence.py`は、既存棋譜から抽出した同一49局面を同じseed・通常深さ3・Experience OFFで読む。静止探索OFFとv0.0.14の一致、ONでの手の変化と探索量を測る。固定深さでは追加計算量が異なるため、棋力比較は別に同じCPU・1手あたり同じ時間の対局で行う。

`benchmarks/checkpointed_match.py`は1局ごとに棋譜・勝敗・探索統計・応答時間を保存する。同じ出力先を指定すると、実行ファイルのSHA-256と条件の一致を確認し、未完了の局から再開する。ExperienceはOFF、各局でエンジンを再起動し、先後を交互にする。中断前の不完全なログだけを正式な比較結果へ合算しない。

この実装は詰将棋専用探索ではない。次の改善候補は、静止探索のコスト削減と詰将棋専用探索である。
