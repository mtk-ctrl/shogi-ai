# v0.0.7 手の並べ替え（move ordering）

## 何を変えたか

v0.0.6では3-ply αβ探索まで進んだが、100局比較で平均225ms/手、最大6.71秒となり、4-plyへそのまま深くする前に高速化が必要になった。

v0.0.7では探索深さも評価関数も変えていない。変えたのは**合法手を読む順番だけ**である。

αβ探索は、良い手・厳しい手を先に読めるほど早く「残りは結果に影響しない」と判断できる。この性質を利用し、次の順で手を優先する。

1. 王手
2. 高価値駒を取る手（特に飛車・角）
3. 成る手
4. 相手の飛車・角の長い利きにさらされた自駒を動かす手
5. その他

この点数は最終局面評価には一切加えない。あくまで「先に読むか、後で読むか」を決めるためだけに使う。

## なぜ答えを変えないのか

すべての候補を同じ3-ply αβ探索で評価することはv0.0.6と同じである。

手の並べ替えによって変わるのは、αβが枝を切るタイミングだけである。最善値そのものは変えない。

また、rootで同点の最善手が複数ある場合は、並べ替え後の順序ではなく元の合法手順に戻してからseed付き乱数を使う。これにより、同じ局面・同じseedならv0.0.6と同じ手を選ぶようにした。

## 固定テスト

専用テストで次を確認した。

- 王手が静かな手より先に来る
- 飛車を取る手が歩を取る手より先に来る
- 同じ移動先なら成る手を先に読む
- 飛車・角の利きにさらされた高価値駒を動かす手を早く読む
- v0.0.6と同じseedで同じ手を選ぶ
- v0.0.6で読めていた3手目の詰みを維持する

同一4局面の比較では、v0.0.6の52,114局面に対しv0.0.7は13,594局面で同じ選択手を出した。約73.9%の局面を省略したことになる。

## 10局スモーク比較

修正版のGitHub Actions run `37167431095`、CPUはAMD EPYC 7763 / 2 vCPU。

| 項目 | v0.0.7 | v0.0.6 |
|---|---:|---:|
| 勝敗 | 6勝4敗 | 4勝6敗 |
| 探索ノード | 4,575,015 | 21,829,669 |
| 平均応答 | 105.096ms | 286.292ms |
| 最大応答 | 1,679.728ms | 7,435.315ms |

ノード数は約79.0%減、平均応答は約2.72倍高速、最大応答は約4.43倍短縮した。

10局の勝敗自体は採用根拠にしない。今回の変更は探索順だけなので、固定局面での選択手一致と探索量・時間の削減を重視する。

## 実装中に見つかったSnapshotの不整合

王手を軽量に判定するため`Snapshot`上の玉を参照したところ、自作APIの契約ではKing=8であるのに、やねうら王からの変換で玉だけ`raw_type_of()`の結果0が入っていたことが分かった。

これまでの駒得評価では玉の価値を0としていたため、探索結果には表面化していなかった。v0.0.7で`type_of(pc) == KING`の場合は明示的にkind 8へ変換するよう修正した。

これは将棋ルールの変更ではなく、自作の中立Snapshot表現を宣言済みの契約に合わせる修正である。

## 意味

v0.0.6では「深く読めば強くなるが、計算量が急増する」ことが見えた。

v0.0.7では、同じ3手読みでも**重要そうな枝から読むだけで、読む局面を約5分の1まで減らせる**ことが確認できた。

CPUを強くする前に探索順序を工夫することで、大きな速度差を作れる具体例になった。

次は、手の並べ替えをさらに改善するか、置換表・反復深化など、同じ局面を何度も読む無駄を減らす方法を検討する。そのうえで4-plyへ進む。
