# 詰将棋ベンチマーク

## 文書の適用範囲
固定問題集の再現手順とv0.0.17〜v0.0.18の性能履歴を収録する。通常対局の旧50ms条件・導入予定は当時の説明であり、正式比較はR20、現在のMateAssistと専用go mateは `docs/19_詰将棋探索.md` を参照する。

## 目的

詰み探索の改良を、数問の手作り局面ではなく固定問題集で比較する。

導入当時の通常戦略比較は1手50msを基準としていた。詰将棋ベンチは通常対局とは別に実行し、通常の各着手で5手詰めを毎回全探索することはしない。

## 元データ

やねうら王公式が2020年12月に公開した詰将棋約500万問を使用する。

- 3手詰め：約100万問
- 5手詰め：約100万問
- 7手詰め：約100万問
- 9手詰め：約100万問
- 11手詰め：約100万問
- SFEN形式
- 配布元では、N手詰め集合は生成時にN-2手で詰まないことを確認したデータと説明されている

公式配布ページ：`https://yaneuraou.yaneu.com/2020/12/25/christmas-present/`

巨大な元ZIPはリポジトリへ保存しない。

## 固定5,000問

開発時に毎回約500万問を処理する必要はないため、各手数から1,000問ずつ固定抽出し、`benchmarks/tsume_dataset/`へ保存する。

抽出条件：

- 3/5/7/9/11手 × 1,000問
- base seed = `20261005`
- 各手数ごとに `random.Random(base_seed + ply)` を使用
- 元ファイル内の行番号から1,000件をsampleし、元の行順に並べて保存
- 元ZIP・元ファイル・抽出ファイルのSHA-256は`manifest.json`へ記録

再生成は`benchmarks/prepare_tsume_benchmark.py`を用いる。

## 実行方法

エンジンをビルドした後、例として各手数100問を2秒上限で測る。

```bash
python3 benchmarks/tsume_benchmark.py \
  --engine build/engine \
  --dataset-dir benchmarks/tsume_dataset \
  --plies 3,5,7,9,11 \
  --limit 100 \
  --time-ms 2000 \
  --output benchmarks/results/tsume.json
```

GitHub Actionsでは`Tsume Benchmark`を手動実行できる。大量ベンチを通常pushごとには走らせない。

記録する主な値：

- ラベル手数以内に詰みを証明した数・率 (`solved_within_horizon` / `solve_rate`)
- ラベル手数ぴったりで発見した数
- ラベルより短く発見した数
- timeout / 現在の探索上限では未証明の問題数
- wall timeの中央値・平均・p95
- エンジン内部時間
- nodesの中央値・平均

## ラベルより短い3局面

固定3手1,000問のうち1局面、固定5手1,000問のうち2局面は、自作エンジンがラベルより短い詰みを発見した。

これら3局面は独立した`python-shogi 1.1.1`によるAND/OR詰み探索でも同じ短手数の詰みを確認した（Actions run `37247925516`）。したがって、軽量化による誤判定とは扱わない。

配布元の生成条件の説明とは少数の例外が生じているため、このベンチでは「指定手数ぴったり」ではなく**指定手数以内に詰みを証明できたか**を主指標とする。3局面のSFENと手順は`benchmarks/results/2026-10-05_tsume-light-v017-summary.json`へ保存した。

## v0.0.17軽量化結果

同一GitHub Actions runnerで、旧v0.0.16 commit `1eb6b8ac...` と軽量版 commit `9c81e8e0...` を固定先頭100問、各問題2秒上限で比較した（run `37247666278`）。

| ラベル | 旧中央値 | 新中央値 | 高速化 | 旧成功 | 新成功 |
|---|---:|---:|---:|---:|---:|
| 3手 | 30.485ms | 1.609ms | 約18.95倍 | 100/100 | 100/100 |
| 5手 | 360.548ms | 17.270ms | 約20.88倍 | 86/100 | 100/100 |

3手はnodes中央値26→26、5手は345→345である。主な改善は探索枝を削ったことではなく、非王手を一度指して戻す処理と、生成済み合法手の着手時に重複していた終局判定を省いたことによる。

固定1,000問では、2秒上限で3手ラベル・5手ラベルとも**1,000/1,000局面でラベル手数以内の詰みを証明**した。

- 3手：中央値約1.500ms、p95約7.350ms
- 5手：中央値約17.297ms、p95約193.046ms

詳細：`journal/2026-10-05_05_v0.0.17詰み探索軽量化.md`

## 短時間予算と通常対局

固定先頭100問で、軽量版の短時間予算は次の結果であった。

| 予算 | 3手ラベル | 5手ラベル |
|---:|---:|---:|
| 5ms | 87/100 | 20/100 |
| 10ms | 96/100 | 38/100 |
| 50ms | 100/100 | 74/100 |

この結果から、3手詰めは数msの補助探索として通常対局へ入れる候補になる。一方、5手詰めを通常の各着手で無条件に完全探索すると、現在の50ms通常探索に対してなお重い。

したがって、通常対局への組込みは次の順で検討する。

1. 1～3手詰めに小さい時間予算を与える案を比較する
2. 5手詰めは詰みの可能性が高い局面だけ呼ぶ
3. 専用探索にも明示的な時間予算を設ける
4. 同じ50ms条件の自己対局で棋力が上がる場合だけ通常`go`へ採用する
5. その後、7/9/11手、詰み専用キャッシュ、DFPN等へ進む

v0.0.17時点では通常`go`へ詰み探索を自動挿入していないため、通常対局の比較基準はv0.0.15軽量版を維持する。


## v0.0.18 直接着手fast path

v0.0.18は、探索枝を減らす前に1 nodeあたりの重複処理を削った。生成済み合法手をopaque tokenで直接着手し、攻め側の王手候補生成、受け側の全応手生成、反復判定を詰み探索向けに分離した。

GitHub Actions run `37261005652`でmain v0.0.17 (`1664195f...`) と候補版 (`1d35600c...`) を同一runner（AMD EPYC 7763、2 vCPU）上で固定3手・5手各1,000問、1問2秒上限で比較した。

| ラベル | v0.0.17中央値 | v0.0.18中央値 | 高速化 | v0.0.17 p95 | v0.0.18 p95 | v0.0.18成功 |
|---|---:|---:|---:|---:|---:|---:|
| 3手 | 1.933ms | 0.232ms | 約8.34倍 | 9.656ms | 0.492ms | 1000/1000 |
| 5手 | 22.239ms | 1.354ms | 約16.43倍 | 251.514ms | 8.887ms | 1000/1000 |

3手のnodes中央値は26→26、5手は352.5→352.5で変わらない。v0.0.17側で5手が1問timeoutしたのに対し、v0.0.18はtimeout 0だった。したがって「強い枝刈りで答えを変えた」のではなく、同じ探索木を大幅に安く処理できたと評価する。

### 7手への拡張

`MaxMatePly=7`へ拡張したcommit `6247c035...`を、run `37261344533`（AMD EPYC 9V45、2 vCPU）で固定7手先頭100問、1問2秒上限で測定した。

- 100/100正解、exact 100、timeout 0
- wall中央値 8.663ms
- wall平均 27.724ms
- wall p95 82.485ms
- nodes中央値 4,130
- nodes平均 9,170.06

100問中の最大は約749.7msで、7手は分布の裾がまだ長い。次は詰み探索専用move orderingと詰み探索専用TTでこの裾を縮め、その後9手へ拡張する。DFPNは単純AND/OR探索の改善余地を測った後に自作実装を検討する。

正式な集計値は`benchmarks/results/2026-10-05_tsume-fastpath-v018-summary.json`へ保存する。

## v0.0.19 通常go MateAssist 50ms比較

通常対局へ1/3手詰みを組み込む採用試験として、同一候補バイナリの`MateAssist=true/false`だけを切り替え、Experience Cache OFF、`go movetime 50`で別seedの100局を2回実施した。

| run | seed | ON勝 | OFF勝 | 引分 | ON得点率 | 違法手 |
|---|---:|---:|---:|---:|---:|---:|
| 1 | 20261005 | 45 | 54 | 1 | 45.5% | 0 |
| 2 | 20261006 | 64 | 31 | 5 | 66.5% | 0 |
| 合計 | — | **109** | **85** | **6** | **56.0%** | **0** |

ON側のMateAssist呼出しは合計13,218回、計測された補助探索時間は合計13,714msで加重平均約1.04ms/回。強制詰み即決は183回、防御側で相手の1/3手強制詰みを許すと証明したroot候補は合計41,794手だった。2本の勝率差が大きいため効果量を精密には断定しないが、合計で負け越さず、攻守の固定回帰も通過したためv0.0.19として採用する。

生データは`benchmarks/results/2026-10-05_v019-mate-assist-50ms-100games.json`と`...-run2.json`、runner情報は対応するhostファイルへ保存する。
