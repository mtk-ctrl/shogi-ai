# 定跡ファイル（やねうら王形式）の利用と作成

作成：2026-11-17（本人依頼「将棋AIで一般的に定跡がどう扱われ、どう保存・読み込みされているかを調べ、相掛かりなどの一般的な定跡を雲路に使わせ、同じように定跡を作れるようにする」）。

## 1. 将棋AIで一般的な定跡の扱い（調査の要約）

### 保存形式
| 形式 | 中身 | 主な利用 |
|---|---|---|
| やねうら王 `.db`（`#YANEURAOU-DB2016 1.00`） | テキスト。`sfen 盤面 手番 持ち駒 手数` の行のあとに、その局面の候補手を1行ずつ `指し手 相手の予想応手 評価値 深さ 出現回数` で並べる。局面はsfen順に整列 | 将棋AIの事実上の標準。水匠・たややん等の公開定跡もこの形式。将棋所・ShogiHome等のGUIも読める |
| やねうら王 `.ybb` | 大規模用のバイナリ版（32バイトの圧縮局面＋指し手） | 数GB級の定跡 |
| Apery形式 `.bin` | 局面ハッシュ（64bit）＋指し手＋回数＋評価値の固定長レコードを、ハッシュ順に整列。チェスのPolyglot形式と同じ発想 | Apery系 |

共通点：**「局面 → 候補手の一覧（回数・評価値つき）」の対応表**で、局面は手順ではなく盤面で引く（手順違いの合流も同じ局面として当たる）。整列しておき、二分探索で必要な局面だけ読む（やねうら王の `BookOnTheFly`）。

### 読み込み・選び方（やねうら王のエンジン設定）
- `BookFile`：使う定跡ファイル。`BookMoves`：何手目まで定跡を使うか（V1既定16）。
- `BookIgnoreRate`：一定確率で定跡を使わない。`BookEvalDiff` / `BookEvalBlackLimit` 等：第一候補との評価差や評価の下限で候補を絞る。`BookDepthLimit`：深さが足りない登録手を使わない。
- `ConsiderBookMoveCount`：出現回数に比例した確率で選ぶ。`NarrowBook`：出現10%未満の手を除く。`IgnoreBookPly`：手数を無視して盤面一致で当てる。`FlippedBook`：先後反転した局面も当てる。

### 作り方（一般的な3系統）
1. **棋譜から数える**：多数の棋譜の序盤を集計し、出現回数（と勝率）で手を選ぶ。チェスのPolyglotの `make-book`、将棋の初期の定跡はこれ。
2. **局面を深く読ませる**（やねうら王 `makebook think`）：定跡の各局面をエンジンで長時間読み、評価値・深さを書き込む。
3. **定跡木で評価を逆算する**（テラショック／ペタショック）：読んだ末端の評価を木の上へminimaxで伝え、根から最善の進行を選ぶ。千日手・合流も処理する。強豪ソフトの大会用定跡の主流。

主な出典：やねうら王wiki「定跡の作成」「思考エンジンオプション」、Polyglot book format、芝世弐「コンピュータ将棋における定跡生成法の一提案」（GPW2018）。

## 2. 雲路での実装（2026-11-17）

### 読み込み（エンジン）
- 実装：`engine/strategy/opening_book.h`（自作の読み込み器。やねうら王のコードは使わない）。`.db` 形式を読む。
- 局面は盤面・手番・持ち駒で引き、手数は無視（`IgnoreBookPly=true` 相当）。sfenはルール層で正規化するので持ち駒の書き順の違いも吸収する。
- USI設定：

| 設定 | 既定 | 意味 |
|---|---|---|
| `BookFile` | `<empty>`（使わない） | 定跡ファイルのパス。例 `books/aigakari.db` |
| `BookMoves` | 40 | この手数（初期局面からの通算）まで定跡を引く |
| `BookSelect` | `weighted` | `weighted`＝出現回数に比例して選ぶ／`best`＝回数最多（同数は評価値） |

- 優先順位：着手制限（`searchmoves`）＞無作為な初手（`OpeningRandomNonLance`）＞**定跡**＞採用済み研究手（局面知識）＞通常探索。定跡を使うときは `OpeningRandomNonLance=false` にする（Floodgateは既にfalse）。
- 定跡の手は合法手（成り強制の整理後の候補）に含まれる場合だけ指す。外れたら通常探索へ戻る。予想応手は `bestmove ... ponder` に出す。
- 出力：`info string book hit ply N move M count C eval E depth D candidates K select S`。読めないときは `info string book unavailable file F reason R` を出して定跡なしで指す。
- 既定は不使用のため、`BookFile` を指定しない限り現行の指し手は変わらない（深さ4の比較で一致を確認）。

### 作成（ツール）
`tools/book/make_book.py`：手順を1行1本で書いた定跡ソース（`.txt`）から `.db` を作る。

```
python3 tools/book/make_book.py books/aigakari.txt -o books/aigakari.db
# 雲路に各定跡手を読ませ、評価値・深さを記入（makebook think 相当）
python3 tools/book/make_book.py books/aigakari.txt -o books/aigakari.db --engine build/shogi-ai --think-ms 1000
```
- 定跡ソースの書き方：初期局面からのUSI手順を1行に1本。`#` 以降はコメント。手順上のすべての局面に次の手が登録されるので、雲路が先手でも後手でも使える。
- 出現回数＝その局面・手を通る行の数。分岐の比重は行の本数で決まる。
- 全手をpython-shogiで合法性検査し、違法手は行番号つきで止まる。既存の `.db` を入力に混ぜると合流（マージ）する。
- `--think-ms` は検算にも使える：最初の相掛かり案で、浮き飛車（▲2六飛）に△8六歩▲同歩△同飛と交換する手順を入れたところ、雲路が △同飛 を -4392 と判定し、6段目で飛車がぶつかり▲8六飛と取られる誤りが判明した。修正済み。

### 最初の定跡：相掛かり（`books/aigakari.txt` → `books/aigakari.db`）
26局面・29手。▲2六歩△8四歩▲2五歩△8五歩▲7八金△3二金▲2四歩△同歩▲同飛△2三歩から、
- ▲2八飛（引き飛車）→△8六歩▲同歩△同飛▲8七歩→△8二飛 または △8四飛（3本）
- ▲2六飛（浮き飛車）→△7二銀（1本）
- ▲7八金・△3二金を先に指す手順違い（本線へ合流）

評価値・深さは雲路1秒読みで記入済み（全手 ±150 以内）。

## 3. 境界と今後
- 出所：人間の一般的な序盤定跡（相掛かりの基本形）を本人の依頼で手入力したもの。特定の他人の棋譜・外部AIの評価やPVは使っていない。定跡ファイルとして指すことに限り、評価関数の学習教師にはしない（R50、2026-11-17本人指示）。
- 効果の測り方は `docs/40_Floodgate定跡の長期計画.md` のv3と同じく、雲路どうしではなく、その戦法を使う相手との実戦（Floodgate）で測る。Floodgateで `BookFile` を有効にするかは本人の判断。
- 今後の拡張候補：Floodgateの実戦から到達頻度の高い局面を定跡ソースへ追記、`--think-ms` の評価を木で逆算する（テラショック型）、局面知識（`position-knowledge-v1.tsv`）の序盤手順の `.db` への移し替え。
