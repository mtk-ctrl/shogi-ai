# 着手記録の保存

## 確定した範囲
2026-10-07のオーナー指示により、継続蓄積する基盤データは実際に指した手を対象にする。
通常対局で指さなかった候補手、候補比較表、PV、探索木を新たな長期保存対象にしない。
診断用の短期Raw Match RecordにPV等が含まれること自体は許容するが、継続蓄積する着手アーカイブへは持ち込まない。短期Rawの仕様は `docs/26_対局データ収集・分析・学習設計.md`、長期蓄積の正本は本Ruleとする。
過去の原記録をこの指示だけで破棄・書換えしない。
今後の概念構成は下記「局面知識への統合」に従う。知識版の正式採用・更新、研究手の直接利用基準はH10で引き続き検討する。

## 保存項目の決定
2026-10-07、今後の局面再利用、新旧版比較、原因手研究、自前定跡のため、容量を考慮した通常保存の設計を確定した。
全実戦手の原観測を保持し、共通情報の参照・棋譜からの復元・局単位の集約で重複を減らす。
詳細な粒度・形式・担当・検証条件は `docs/28_着手記録の保存仕様.md`。次のschema 2の設計であり、現行schema 1の実装完了と混同しない。

## 必要な記録
対局単位:
- source/run/gameの識別子、元データのハッシュ。
- 開始局面（省略時は標準初期局面であることをrunner仕様で確認）、先後、実戦の全指し手、勝敗、終局理由、最終局面。
- 両エンジンの実体ハッシュ、実際にbuildした確定commit、Engine世代・USI表示名・有効設定、持ち時間、seed。設定と実行環境は共通IDで参照し、毎手に繰り返さない。
- Book / ExperienceのON/OFF、使用資産の版・ハッシュ・初期状態、セッションと状態継承・リセットの事実、資産の復元可否。毎手・毎局の全資産コピーはしない。記録がなければ不明とする。

着手単位:
- 手数、手番、着手者、実際の指し手。
- 当時の探索評価（cp / mateを区別）、評価視点、上限・下限の区別。
- 完了した探索深さ、最大到達深さ、思考時間、ノード数。
- 手の選び方（通常探索・Book・詰み専用処理・fallback等）、評価の出所、長考の有無・理由、探索の終了・中断理由。
- 固定の探索条件は共通情報に置き、各手で変わる時計・go条件はその手に残す。
- TT / Experience等の利用統計・cutoff・静止探索統計は取得できるものを局単位に集約する。通常の長期記録へ毎手の詳細統計を必須にしない。
- 取得できなかった項目は欠損として残し、ゼロや推測値を補わない。

開始SFEN・実戦手順・先後割当から復元できる毎局面の盤面・手番・着手者・戦術事実は重複保存しない。評価視点の違いだけの数値も二重保存しない。
当時の評価は選ばれた実戦手と対応する結果として取得する。cp / mateや境界フラグの過去値を混入させず、判別不能な旧記録は曖昧として原観測を保持する。
静的評価と探索評価を混同しない。対局後の再解析は別記録とし、当時の評価値を上書きしない。
勝敗を、その着手の良さの確定ラベルにしない。

## 実装範囲
tools/records/archive_played_moves.pyは標準arena JSONの実戦手を圧縮JSONLへ変換する。
元データとの着手一致・手数一致を検査し、対局ID・出所・ハッシュ・欠損件数をmanifestへ残す。
2026-10-08、標準arenaと外部runnerの雲路側の読取りは、最新のscoreをcp/mateの種別・値・境界フラグごと一括更新するよう訂正した。旧形式のcp/mate混在行は原値を保持して `score_status=ambiguous` とし、欠損とは別件数でmanifestへ残す。行だけから後に出た評価を推測しない。旧記録で残留した境界フラグだけの問題は、cp/mateの混在検出だけでは判別できない。
この実装は新たなエンジン評価出力や未取得の資産ハッシュを生成しない。欠損解消は今後の収集改修で行う。

通常内部比較のengine-match.ymlは対局後にこの処理を呼び、着手アーカイブをartifactへ保存する。
探索中の処理を増やさない。位置指定runner・外部runner・保留中の夜間研究への自動接続は未実装である。

## 保存先と容量管理
通常実戦記録と研究記録の長期正本はGitHub Releasesのデータ用releaseを使う設計とする。製品Engineのreleaseとは区別する。
共通設定はID参照、同じhashの知識資産は一度だけ保存/参照し、研究の詳細は選んだ局面だけ別記録へ残す。
Actions artifactは一時受け渡しであり、期限付きである。圧縮保存だけで長期保存完了と報告しない。
実装済みの内部比較アーカイブは90日保存を要求する（repository側の許容設定に従う）。
期限前のReleasesへの自動移送は未実装である。実装されるまで保存期限をmanifestとともに確認する。
ソースリポジトリへ大量の対局データを継続commitしない。
容量台帳では通常棋譜・研究記録・知識資産・一時Rawを分け、物理的な使用bytesを記録する。初期設計の見直し目安は通常棋譜平均6KiB/局、一時artifact100MiB、長期累計1GiB（初回点検）とする。GitHubの無料枠・固定上限ではない。圧縮ファイルは256MiBを超える前に分割する。
目安超過時は増加原因と予測を報告し、保存方法を再検討する。累計点検は初回1GiB、以後5GiB・10GiB・倍増を初期目安とし、点検済みの同じ超過を毎run繰り返し通知しない。自動削除・保存打切り・実戦手や原評価の間引きは行わない。
長期移送・容量台帳は未実装であり、稼働確認前に現行保存期限を短縮しない。

## 長期蓄積と世代更新
対局量はオーナーが調整し、最大毎晩1万局程度を容量計画の想定とする。起動指示・最低局数にはしない。
1か月・半年以上の蓄積とEngine更新を前提に、全原記録・増分索引・対局用の知識候補を分ける。原記録の増加に比例して対局中の読込み量を増やさない。
月別releaseへrun/partを追記し、容量予測・分割検索・版ごとの再確認を設計する。詳細は `docs/29_着手データの長期運用と世代更新.md`。これらの収集・移送・索引は未実装である。
古い観測は保持し、新版の研究を追加する。旧版の深さ・点数を新版へ無条件に移植せず、知識の効果は固定した版で比較する。
局面知識の具体的な正式昇格・直接選択・自動反映はH10の保留を維持する。対局用候補を絞っても全実戦手・原評価の保存は間引かない。

## 活用の制約
着手だけの記録では探索木の途中からの完全再開はできない。
以前の有力手・深さを使った探索誘導、局面の再解析、新旧版比較はできる。
同じ盤面でも反復履歴・評価設定が異なる場合、古い評価値をそのまま探索打切りに使わない。
活用順と研究案はdocs/27_着手データ活用計画.mdを参照する。

## 局面知識への統合（2026-10-07本人承認）
今後はBook / Experienceの二分法を必須とせず、「対局記録・研究記録・局面知識」の構成で進める。
対局記録と研究記録は出所付きの原本として蓄積し、現在の雲路が対局に使う小さな派生資産を局面知識とする。対局由来/研究由来は属性で区別する。
外部AIとの対局で出た局面の雲路自身の探索結果も候補に含めるという2026-10-08の出所判断はR50を正本とする。この出所の許可を、候補の自動正式採用や旧Experienceの自動更新方式の確定へ広げない。
定跡は局面知識のうち序盤の連続手順・相手応手の分岐・適用条件・根拠を整理した部分とする。
最初の即活用経路は、条件の揃った過去の選択手を探索順へ使うmove_order_hintとして具体化する。根拠の深さ・時間・条件を保持し、今回の完了探索が最終手を決める。
確認済み研究の結論を着手判断へ使う経路も設ける方向だが、具体的な確認・変更条件と正式採用は未確定。長い時間や深さだけを正解証明にしない。
保存手順・生成器・loader・履歴照合・検証の実装仕様は `docs/35_局面知識の統合設計と即活用.md`。新アーカイブからの即活用経路は未実装である。
既存Book / Experienceのコード・資産・USI設定・過去記録は識別可能なまま保ち、名称変更だけで破棄・互換性破壊を行わない。
正式採用はR10、出所境界はR50、未決の更新・自動反映等はH10、夜間の再開はR30に従う。
