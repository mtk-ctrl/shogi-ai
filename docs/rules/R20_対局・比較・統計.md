# 対局・比較・統計

## 正式な候補採否
正式な候補採否を決める自己対局は、現行採用版と同条件で比較し、原則 `go movetime 200` + AdaptiveLongThink ON を使用する。

AdaptiveLongThinkは200ms時点で所定の発動条件を満たす場合に、同じ反復深化を最大1秒まで継続する。1局最大10回とする。

2026-10-08本人回答により、長考枠ごとの固定開始・期限手数を廃止する。24手以降、王手・評価急落・反復深化の変動・depth2未完了等の不安定・不足を優先し、残り枠を連続する自分の手番でも使えるようにする。

150手程度までの消化を目標とする。150手までの残りの自分の着手機会（現在の手番を含む）が残り長考回数以下になったら、安定局面でも残り枠を使う。安定局面でも使い切ることは本人の追加回答で確認済み。150手は先後合計のSFEN手数（ply）であり、自分だけの150手ではない。

短い対局、Book即決、証明した詰み、合法候補1手等では10回に達しないことがある。対象外の手で消化できなかった枠は、150手を過ぎても次の対象手で使い、最大10回を守る。仕様・例外・検証は `docs/36_v2.0.1長考配分.md`、本人原文と確認回答は確認記録の追加確認1を参照する。

## 明示的な例外
一般の200ms条件を次へ機械的に上書きしない。
- 高速スクリーニング・大量候補探索: 50〜100msを使用してよい。
- Diagnosis: shallow 50ms / deep 500ms等、その診断で固定した尺度を維持する。
- 外部Benchmark: R50および各Benchmark設計の固定条件を維持する。
- 固定深度回帰: 時間比較ではなく探索結果の回帰確認として扱う。

「新しい日時の文書に別の持ち時間がある」だけで一般条件変更とはみなさない。

## 比較の扱い
- 先後を可能な限り均衡させる。分割対局では各shardを同じ先後から始めず、全体の通し順で交互にする。偶数の総局数なら同数、奇数なら差1局以内を確保し、局数配分も最大差1局に保つ。
- 少数局だけで強化を断定しない。
- 勝敗だけでなく違法手、応答時間、探索量、必要に応じ95%区間等を確認する。
- EngineまたはExperienceを変更した場合、外部AIより先に現行採用版との比較を基本とする。
- Book / Experience のON/OFF、ファイル、初期状態は必ず条件として記録する。ただし今後の役割・更新方針はH10の保留を勝手に解消しない。

## 対局記録
標準runner経由の対局は、可能な範囲でRaw Match Recordを残す。
最低限、対局条件、両者の識別、結果、seed、手数、違法手、実行条件を再現できるようにする。
1手単位telemetryや原因帰属の詳細は `docs/26_対局データ収集・分析・学習設計.md` を参照する。

## 採用後
比較基準が更新される採用なら、通常仕上げ時に `benchmarks/baseline_ref.txt` を更新する。
