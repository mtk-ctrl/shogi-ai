# 対局・比較・統計

## 正式な候補採否
正式な候補採否を決める自己対局は、現行採用版と同条件で比較し、原則 `go movetime 200` + AdaptiveLongThink ON を使用する。

AdaptiveLongThinkは200ms時点で所定の発動条件を満たす場合に、同じ反復深化を最大1秒まで継続する。1局最大10回とする。

2026-10-08本人回答により、長考枠ごとの固定開始・期限手数を廃止する。24手以降、王手・評価急落・反復深化の変動・depth2未完了等の不安定・不足を優先し、残り枠を連続する自分の手番でも使えるようにする。

150手程度までの消化を目標とする。150手までの残りの自分の着手機会（現在の手番を含む）が残り長考回数以下になったら、安定局面でも残り枠を使う。安定局面でも使い切ることは本人の追加回答で確認済み。150手は先後合計のSFEN手数（ply）であり、自分だけの150手ではない。

短い対局、証明した詰み、合法候補1手等では10回に達しないことがある。対象外の手で消化できなかった枠は、150手を過ぎても次の対象手で使い、最大10回を守る。仕様・例外・検証は `docs/36_v2.0.1長考配分.md`、本人原文と確認回答は確認記録の追加確認1を参照する。

## 局面知識の常時利用
2026-10-08のオーナー指示により、**雲路が対局する場合は採用済みの局面知識データを毎回使用する**。通常の自己対局・内部比較・外部Benchmark・Floodgate等で `PositionKnowledge=true` を既定とし、同一比較では原則A/Bへ同じ採用済み局面知識データを渡す。

`research_decision` として採用済みの研究手は短い通常探索で再選択せず直接採用する。相手応手・実際の到達履歴が研究筋に一致する間は後続手も直接採用する。研究開始局面は駒配置・持ち駒・手番が一致すれば、研究時とは別手順からの到達でも直接採用する。研究読み筋の途中でその局面を独立して研究した採用手に一致した場合は、その局面を直接研究した結果を優先する。ただし、反復履歴のある局面・違法手・明示的な着手制限等では通常処理へ戻す。研究筋から外れた場合は通常探索へ戻る。旧研究の評価値を今回の探索値に偽装しない。`move_order_hint` は従来どおりrootの読む順番へ反映し、通常探索が最終着手を決める。採用済み局面知識データの正本・生成境界はR25と `docs/35_局面知識の統合設計と即活用.md` に従う。

局面知識を使わない条件を許すのは、局面知識そのものの有無比較、読込み・互換性・回帰の故障診断、過去版の厳密再現など、**使わないこと自体が実験条件のときだけ**とする。その場合は結果に明示する。通常対局で「指定を忘れた」「ファイルがない」を未使用扱いにしない。Actionsの標準内部比較は採用済み局面知識データが存在しなければ失敗させる。

利用確認では、ファイル名・内容ハッシュ・知識件数と、内部統計の `knowledge_probes / knowledge_hits / knowledge_promotions` を記録する。ユーザー向けには原則「局面知識の照会回数・一致回数・読み順を繰り上げた回数」と日本語で報告する。対象局面が現れず一致回数が0でも正常な場合はあるが、局面知識データ自体を読み込めていない対局を「局面知識使用済み」と扱わない。
## 明示的な例外
一般の200ms条件を次へ機械的に上書きしない。
- 高速スクリーニング・大量候補探索: 50〜100msを使用してよい。
- Diagnosis: shallow 50ms / deep 500ms等、その診断で固定した尺度を維持する。
- 外部Benchmark: R50および各Benchmark設計の固定条件を維持する。
- 固定深度回帰: 時間比較ではなく探索結果の回帰確認として扱う。

「新しい日時の文書に別の持ち時間がある」だけで一般条件変更とはみなさない。

## 比較の扱い
- 先後を可能な限り均衡させる。分割対局では各shardを同じ先後から始めず、全体の通し順で交互にする。偶数の総局数なら同数、奇数なら差1局以内を確保し、局数配分も最大差1局に保つ。
- 少数局だけで強化を断定しない。
- 勝敗だけでなく違法手、応答時間、探索量、必要に応じ95%区間等を確認する。
- Engineまたは局面知識を変更した場合、外部AIより先に現行採用版との比較を基本とする。

## 対局記録
標準runner経由の対局は、可能な範囲でRaw Match Recordを残す。
最低限、対局条件、両者の識別、結果、seed、手数、違法手、実行条件を再現できるようにする。
1手単位telemetryや原因帰属の詳細は `docs/26_対局データ収集・分析・学習設計.md` を参照する。

## 採用後
比較基準が更新される採用なら、通常仕上げ時に `benchmarks/baseline_ref.txt` を更新する。
