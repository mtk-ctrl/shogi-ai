# 自前棋譜から作る小規模定跡

## 目的

序盤の既知局面では、毎回同じ50ms探索を最初からやり直さず、自分のAIが過去に指した自己対局棋譜から候補手を選べるようにする。

外部の定跡集、プロ棋譜、他エンジンの評価値・推奨手は使用しない。材料は shogi-ai 自身の対局と、自分のBookを使った実戦結果である。

## 初期Bookの作り方

1. `tools/book/import_arena_games.py` が自己対局結果を集める。
2. 違法終了・引分・勝者不明を除外し、完全重複棋譜をSHA-256で除く。
3. `tools/kifu/validate_games.cpp` で全手を自分のルール層から再生する。
4. 序盤20手以内について、`Position::hash_key()` ごとに「その局面で指した手」と最終勝敗を集計する。
5. 同一局面が8回以上、候補手が3回以上現れたものを対象とする。
6. 勝率は少数局の100%を過信しないよう50%側へ平滑化する。
7. 最良候補との差が0.12以内の手を最大3手まで残す。
8. 選択重みは対局数だけでなく勝敗も見る。十分な対局数があるのに得点率が低い手は強く減衰させる。

定跡表には、局面ハッシュ、USI指し手、対局数、勝・分・敗、平滑化した得点率、選択用重みを保存する。

## 実戦での使い方

通常の `go` は次の順で処理する。

1. 終局・入玉宣言・合法手を確認する。
2. 定跡をONにしている場合、現在局面の `Position::hash_key()` を定跡表で引く。
3. 候補手があれば、その局面の候補から `RandomSeed` と重みに基づき再現可能な形で1手選び、そのまま `bestmove` を返す。
4. 候補がなければ v0.0.19 の MateAssist、反復深化、静止探索等へそのまま渡す。

`go mate` では定跡を使わない。`go ponder` と `go infinite` も停止処理の意味を変えないため定跡即着手を行わない。`searchmoves` が指定された場合は、その集合に含まれる定跡手だけを候補にする。

## Bookの勝敗フィードバック学習

Bookを固定物として扱わず、「実際にBookから選んだ手が、その対局で勝ち・引分・負けのどれにつながったか」を継続的に学習する。

夜間学習は **Book ON 対 Core（同一エンジン、Book OFF）** で行う。これにより、Bookが探索を省略して返した手に価値があったかを、同じ探索本体を基準に比較できる。

処理は次のとおり。

1. `benchmarks/book_feedback_arena.py` がBook ON側とCore側を先後交代で対局させる。
2. エンジンの `info string opening_book hit ...` を読み、**実際にBookが選択した手だけ**を `book_hits` として記録する。
3. `tools/book/extract_book_feedback.py` がBookヒットのあった棋譜と、`game_id / ply / move` の対応を抽出する。
4. `tools/kifu/validate_games.cpp` で棋譜をルール層から再生し、Book手を指す直前の局面ハッシュと、その手を指した側から見た最終勝敗を確定する。
5. `tools/book/apply_book_feedback.py` が、その `局面ハッシュ × Book手` にだけ新しい勝・分・敗を加える。
6. 最近の実戦結果は既存の古い統計より速く効かせるため、既定で4倍の重みを持つ疑似サンプルとして加算する。
7. 低得点率の手は選択重みを下げ、高得点率の手は上げる。ただし一晩で極端に変わらないよう、通常更新では1回あたり `0.50倍～1.35倍` に制限する。

弱い手はBookから削除しない。最低重みを1残してごく低頻度で再探索できるようにし、その後勝てるようになれば復活できる。これは探索本体が強化された結果、以前は悪かった定跡手の評価が将来変わる可能性を残すためである。

## 夜間自動学習

`.github/workflows/nightly-book-learning.yml` が毎日実行する。

- 04:47 JST開始
- 05:20 JSTを対局打切り目安とし、集計・検証を05:30頃までに終える
- GitHub Actions 1 runner内で2レーン並列
- 両者 `go movetime 50`
- Book側だけ `OpeningBook=true`
- Experience Cacheは両者OFF
- 違法対局0、20局以上、正しく照合できたBookヒット50件以上を自動反映の最低条件とする
- 実行中にmainのBookが別途更新された場合は上書きせず、自動反映を中止する

学習候補は必ずUSIで読み込み検証してから `shogi-ai-book.tsv` へ反映する。

## USI設定

- `OpeningBook`：定跡使用のON/OFF。既定値は `true`。
- `OpeningBookFile`：定跡TSV。既定値は `shogi-ai-book.tsv`。

ファイルが存在しない・読めない場合はエラー終了せず、従来探索へフォールバックする。

## Experience Cacheとの違い

Experience Cacheは同一局面で過去に良かった手を探索順の先頭へ置くためのヒントであり、最終的には探索を行う。

Opening Bookは序盤の十分に観測された局面について、候補手そのものを選び探索を省略する。用途を混ぜない。

## 外部エンジンとの関係

やねうら王などの外部エンジンは棋力測定には使うが、相手の評価値、PV、推奨手をBookの教師として取り込まない。Bookの学習信号は、shogi-ai自身がBookを選択して実際に得た最終勝敗である。

したがって、外部ベンチマークでBookの汎化性能を確認しつつ、学習そのものは自作戦略の範囲に保つ。

## 更新

大規模な自己対局からBookを再生成する場合も、`tools/book/build_opening_book.py` は勝敗を強く反映する共通の重み関数を使う。そのため、過去の低勝率手が旧式の重み計算で再び高頻度に戻ることは避ける。

定跡の採用・改善判断は、BookなしCoreとの同CPU・同持ち時間・先後交換の対局と、固定した外部ベンチマークの両方で追跡する。
