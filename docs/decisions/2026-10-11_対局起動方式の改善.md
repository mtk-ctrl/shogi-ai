# 対局起動方式の改善（2026-10-11）

## ユーザーの依頼
- ユーザーは将棋AI開発における安全性チェックによる停止が頻発する問題について改善方法を質問した。
- 続けて「具体的に改善できますか？」と依頼した。

## 今回の実装範囲
- 汎用対局 `engine-match.yml` は変更しない。
- リポジトリのソースファイルへ変更を加える必要のない通常対局の入口として、リポジトリ所有者が作成したIssue本文のJSONを検査して既存対局を起動する。
- 作成者・タイトル・要求項目・数値上限・エンジン参照・使用可能なUSIオプションを検査する。
- 所有者以外のIssue、予期しない実験条件を拒否し、GitHub Actionsの権限はread中心＋対局Workflow起動用actions:writeに限定する。
- 従来の `.github/match-request.json` による起動は維持する。
- 起動と実験結果保存・監視を混同せず、R20/R21/R25の条件を維持する。

## 根拠と制約
- 目的は、通常対局のたびにコード・Workflow・requestファイルを変更する作業を減らし、差分管理とトラブル原因の切り分けを容易にすること。
- ChatGPTまたはGitHub側の安全性チェックそのものを無効化・回避するものではない。Issue作成も通常の権限・安全性チェックの対象となる。
- GitHub Actions上での起動確認・テスト結果をもって初めて稼働を判断する。
- 新規エンジン候補の採用判断や夜間研究の再開権限には変更を加えない。
