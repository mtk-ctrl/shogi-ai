# 自動採用・自走・ランナー配分・人生帳の常時許可（2026-11-17 本人決定）

対象：雲路・深路の両方。同じ内容を深路 `docs/decisions/2026-11-17_自動採用と自走運用.md` にも置く。

## 本人の決定（2026-11-17 17:16 JST、Claudeとの会話）

本人原文の要旨：
- 「対現行最新版で+12以上、かつ違法手0なら、正式採用まで自動で実行し、事後報告」と決めます。
- 止めてほしい操作は、削除くらい。
- Floodgateは雲路も深路も常時対局を継続してほしい（そのまま）。
- ランナーの使い方はよく考えて時間効率が良くなるように工夫して。2ランナーは常にFloodgate用に空けておく。
- md・ルーター・ルールに記載し、人生帳へのアクセス許可も明記する。

背景：承認待ち（採用の実行待ち・「この方向で進めてよいですか？」）で研究が止まり続けていた。

## 1. 自動採用（雲路・深路共通）

- **条件**：現行の最新正式版を相手に、標準の比較条件（各プロジェクトの比較Ruleの時間・同一条件、原則108局＝54序盤×先後）で**勝敗差（勝ち−負け）が+12以上**、かつ**違法手0**（反則負け・不正な指し手・合法性検査の失敗が0）。
- **動作**：条件を満たしたら、本人の承認を待たずに**正式採用まで実行**し（重み・設定・版番号・現行仕様・判断記録の更新、採用CIの実行と読戻し確認）、**事後報告**する。
- **対象**：NNUE重みに限らず、探索・評価・時間管理などのエンジン変更も同じ条件で採用してよい。版番号の更新はR70／現行仕様の手順に従う。
- **基準未満の扱い（2026-11-17 19:09 本人訂正）**：勝敗差が+12未満でも**負け越していなければ（勝ち≧負け）、別シードで1回追試し、合算で判定する**（合算が+12以上かつ違法手0なら採用）。長い学習・生成のあとに、ブレだけで捨てるのは時間の損失になるため。**負け越した（負け>勝ち）なら追試せず不採用**として記録する。追試は1候補につき1回まで。合算でも+12未満なら不採用。
- **戻す**：本人が「戻して」と言えば、前の正式版へ戻す（旧版は削除せず保全済み）。
- これは、雲路R10「新しい研究候補はオーナーの判断なしに正式採用しない」（2026-10-07問8）と、深路F00/F20「NNUE重み以外の正式仕様変更は別途明示指示後」を、上の条件の範囲で置き換える。

## 2. 止めずに進める（自走）

- 本人に確認して止まるのは**削除を伴う操作**（ファイル・ブランチ・Release・run成果物・Driveファイル等の削除、履歴の書換え）だけ。それ以外は実行し、事後報告する。
- 「次は何をするか」はAIがROADMAP・判断記録・直近の結果から選び、実行する。方向が本当に割れる重大な分岐（プロジェクトの方針そのものを変えるもの）だけ、案を添えて質問し、その間も止めずに進められる工程を進める。
- 1工程を起動したら、その終了見込みに合わせて**単発の確認予約**を作ってから終える（F01）。予約が発火したら、結果確認→採用判定→次の工程の起動→次の予約、までを1回で行う。
- 課金（有料超過）を伴う操作は従来どおり行わない。

## 3. Floodgate（継続）

- 雲路（KUMOJI）・深路（FUKAJI）とも常時参加を続ける。止めるのは本人の指示があったときだけ。
- 各回の起動時に最新のmainをビルドする（雲路：`engine_ref`未指定ならmain、深路：`formal/model.json`の正式版）。**正式採用した新版は、次の回（最長約3.5時間後）から自動でFloodgateに使われる。** 実行中の回は途中で差し替えない。

## 4. ランナーの使い方（時間効率）

- 同時実行は両リポジトリ合計20台。**2台はFloodgate用に常に空ける**。研究・対局・生成・学習は合計18台まで。起動前に両リポジトリの実行中runを数える。
- **空き時間を作らない**：学習（1台で長時間）の間は、残りの台で次の周回の自己対局生成、もう一方のプロジェクトの比較対局などを並行させる。工程が終わるのを待って全台が空く時間を作らない。
- **1つのjobは60分以内に収める**：深路の学習は約68〜72分で3回続けて通信断になった（2026-11-17）。長い学習は分割・再開できる形にし、1jobを60分以内にする。
- **対局は1巡で終える**：比較対局は18台へ均等に割り、2巡目の待ちを作らない（108局＝18台×6局）。
- **優先順位**：Floodgate（2台固定）＞採用判定の比較対局＞次の周回のデータ生成・学習＞探索的な研究。雲路と深路で台数が足りないときは、採用判定に近い方を先にする。
- 失敗したjobを自動で何度も再試行しない。原因を調べ、直してから1回だけ再実行する。

## 5. 人生帳

- 人生帳（GitHub `mtk-ctrl/lifeplan`）への読み書き・閲覧サイトの公開は**常に許可**（2026-11-14・2026-11-17本人明言）。状況が変わったら毎回反映する。都度の許可確認はしない。
