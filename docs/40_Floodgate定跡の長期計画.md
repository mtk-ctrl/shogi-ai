# Floodgate定跡の長期計画（v2・草案・本人の承認待ち）

作成：2026-11-16。v1は「読む量」の計画で、読んだ結果を定跡にする方法がなかった（本人指摘）。v2で作り直した。承認前は既存の追加3局面以外を実行しない。

## 1. v1の欠陥
- 深く読んだ評価値で手を選ぶと、雲路の評価の癖（駒得の過大評価。実戦で序盤〜中盤+700〜+1200から崩れた）を定跡に焼き込む。
- 局面を闇雲に読んでも、「どの手を採るか」「どこまで広げるか」「正しかったか」を決める基準がなければ定跡にならない。

## 2. 定跡の定義
「雲路が実際に指して、中盤を無理なく戦える序盤の進行」を木で持ち、各局面に1手（自分の番）を定めたもの。**良さの基準は読みの評価値ではなく、その先を実際に指した勝敗**とする。評価値は候補を絞る道具にとどめる。

## 3. 仕組み（4段のパイプライン）
1. **候補の生成（安い）**：対象局面で60秒読みを行い、上位の候補手（評価差が小さいもの、2〜3手）を出す。評価値が深さで揺れる局面は印を付ける。
2. **勝敗での選別（本体）**：候補ごとに、その局面から雲路どうしで本番に近い持ち時間で対局する（先後入替・開始局面は同じ）。勝率の差が明らかな場合に採用。差が出ないものは、評価値と手の素直さ（駒損をしない・形が崩れない）で決める。「たまたま勝った」が疑われる接戦のときだけ追加で指す。
3. **木の広げ方**：自分の番は採用した1手。相手の番は、Floodgateの実戦で観測した手を頻度順に。観測のない手は雲路が有力とみる手を1〜2本。**広げる優先は「その局面に実戦で到達する回数」の多い順**。到達が1回以下の枝は広げない（深くなるほど当たらないため）。
4. **実戦での検証と再投入**：Floodgateのログから、定跡で指した局の勝敗・定跡を出た局面の評価・出口からの急落を毎日集計する。定跡を出た後に負けが集中する枝は、候補を入れ替えて2へ戻す。

## 4. 計算資源（本人案：区切って使う）
- 本人案どおり、**まず4ランナーに限定**して始める（Floodgate用2台とは別。R21の18台上限の内側）。効果が見えたら増やす。
- 見込み（P0で実測して直す）：1局3〜4分とすると、4台で1時間約60局、夜8時間で約500局。1つの比較に100局なら夜に約5件。数を絞るために、**実戦の到達回数が多い局面から**進める。
- Floodgateの実戦そのものも、毎日の検証データになる（追加費用なし）。

## 5. 段階
| 段階 | 内容 | 判定 |
|---|---|---|
| P0 方式の検証（まず1つ） | 飛先突き捨ての9手目（深読みでは分かった局面）で2を実際に回す。勝敗で選ぶ方式が深読みと同じ結論になるか、局数はいくつ必要か、1局の時間を実測 | 方式が機能し、局数と所要時間が見積もれる |
| P1 先手の最頻出ルート | 到達回数の多い先手の自分の2〜8手目を、1〜4で整える | 到達率・出口の質・急落局数 |
| P2 後手 | 相手の初手別に同様 | 同上 |
| P3 日次ループ化 | ログ集計→待ち行列→夜間の比較→追加TSV、を自動化 | 人手なしで回る |
| P4 整理 | 本人が効果を見て、正式層への昇格、163件・227局面の扱いを判断 | 本人の判断 |

P0の結果が悪ければ、定跡より中盤の評価の改善へ人手を回す。

## 6. 指標
定跡到達の手数、出口の質（5分読みとの差）、20手目までの急落局数、定跡を使った局の勝率（参考）。

## 7. 境界（R50）
雲路どうしの対局と、雲路が出た対局の局面だけを使う。外部AIの評価・PV・手は教師にしない。他人の棋譜は使わない。
