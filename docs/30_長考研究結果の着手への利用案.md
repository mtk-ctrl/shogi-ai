# 長考研究結果を着手判断へ使う案

## 状態と目的
2026-10-07、オーナーは重要局面の長時間研究を行う意向を示し、1時間の研究で選んだ手を単なる候補として渡しても200msでは同じ結論に届かないと指摘した。研究にかけた時間も渡す案が提示された。
本書はその課題を仕組みに落とした**検証用の提案**であり、採用済みのエンジン動作ではない。保存方針はR25、Book / Experienceの責任分担・昇格条件はH10に従う。長時間研究・比較対局・自動学習を起動する指示とは扱わない。

## 時間を渡す意味
指し手だけでなく、根拠となる完了結果と研究量を一緒に渡す。
ただし、エンジンは「1時間読んだ」と受け取っただけで判断を変えない。研究結果を利用する判定と、今回の探索で変更する判定を実装する必要がある。
時間は計算投資の情報であり、そのまま評価値への加点や正しさの確率に変換しない。CPU、探索条件、版、局面の難しさが違えば同じ時間でも意味が違う。深さ・ノード・完了状態・確認状態も合わせる。

## 渡す研究結果
| 情報 | 扱い |
|---|---|
| 局面と到達履歴 | 配置・持駒・手番を照合。開始SFEN＋到達手順とルール条件も参照 |
| 選ばれた研究手 | 最後の完了結果に対応する手。合法性を利用時にも確認 |
| 評価と出所 | cp/mate、視点、境界、評価が選択手に対応すること。欠損・曖昧は確定値にしない |
| 読みの量 | 完了depth、seldepth、nodes、エンジン報告時間と実測時間 |
| 長時間研究の時点 | 指定した時間上限、実際の総時間、採用した完了結果の時点を区別 |
| 条件 | 確定commit・実体hash・評価/探索設定、知識の設定・状態、研究条件 |
| 安定性 | 最終手を何回の完了反復で続けて選んだか、最後に手が変わった時点。観測できなければ不明 |
| 確認状態 | 未確認、条件付き確認済み、相違あり、適用外等。確認の対象版と根拠 |
| 出所 | research ID、元の対局・手数または個別研究依頼、研究結果hash、日時 |

「1時間で打切り、最後の深さを完了したのは45分時点」なら、1時間の全量をその完了結果の計算量と称しない。研究中の部分探索を完了深さへ足さない。
安定性は収集中に集計する小さな情報であり、通常対局の未着手候補・全PV・探索木の追加保存を必要としない。長時間かつ安定でも最善の証明とは扱わない。
研究結果はIDで共有し、毎対局へ研究全体を複製しない。

## 二つの利用方法を比較する
### A. 探索順だけに使う
通常の実戦記録や未確認の研究手は、先に読む材料として扱う。今回の完了探索結果が最終手を決める。
以前の長時間研究を再現する保証はなく、200msの浅い結論で別の手へ変わり得る。

### B. 条件付きで研究手を既定の着手にする
適用条件を満たす確認済み研究について、以前の深い結論を**今回の既定の着手**として置く案を検証する。
200msの探索で別の手が出ても、浅い評価だけではその研究手を変更しない。相違を記録し、後日の再研究へ回す。
研究手を使った場合は、今回200msでその手の深い良さを再発見したという説明にはしない。既にある研究結果を着手判断へ利用したという意味である。

これは探索木の再開や、旧評価を無条件に置換表へ投入する方法ではない。まずrootでの最終着手を決める処理として独立させる。
初回試作では利用者が指定した検証モードだけでBを有効にし、通常のエンジンの既定動作をいきなり変えない。

## 利用前の確認
1. 知識利用を許可された出所・目的か確認する。人間との対局の学習対象は `docs/rules/R50_外部AI・梯子・Floodgate.md`、未決の知識利用範囲はH10に従う。保存してあることだけで全件を学習資産へ採用しない。
2. 局面の配置・持駒・手番・ルールと、研究に対応する到達履歴を確認する。初回試作は研究と同じ履歴を対象にし、別手順への適用を広げない。
3. 対象エンジンcommit・有効設定と、記録された条件を照合する。可変知識の状態が照合できない場合はBを有効にしない。
4. 研究手の合法性、評価と手の対応、完了状態、確認状態を検査する。Book値、部分探索、境界値だけの記録を完全なroot比較と同一視しない。
5. 新版になったら無条件にBを継承せず、再確認する。それまでAまたは通常探索を使う。

確認済みとは「記録の取得に成功した」だけでなく、その対象条件への利用を検証した状態である。昇格に必要な具体的な研究量・比較・許容条件は今後決める。
研究時間が長いという一点で、自動的に確認済みへ昇格させない。

## 今回の探索で変更する条件の案
- 条件が違う・合法性が不成立: 研究結果の利用を始めず、通常探索へ戻す。
- 200msの完了結果が別の手を選び、研究より浅い: Bでは研究手を維持し、相違を再研究待ちへ残す。
- 同じ条件・同じ探索尺度で、研究と同等以上の深さまでroot全体の比較を完了した: 今回の結果へ更新することを検証する。旧研究は上書きしない。
- 明確な反証が得られた: 例えば自作の詰み処理で別の手の詰みを検証できた場合など、反証の内容を明示して変更を検証する。通常のmateスコア表示だけを詰みの証明と称しない。
- 観測や出力が曖昧: 不確実な値を比較して上書きしない。研究の利用条件自体が確認できない場合はBを開始しない。

深さの比較は同じ版・探索設定・ルール・制限下でのみ行う。同等以上のdepthは研究の正しさの証明ではなく、変更条件の検証案である。
1時間読んだ手を200msで絶対に変更できない制度にはせず、短い時間でも検証できる反証と、単なる浅い相違を区別する。
研究結果が誤っていた場合の影響、200msで見つけた改善を逃す頻度も比較対象にする。

## 対局記録を混ぜない
今回の着手が研究から決まったなら、decision sourceをresearchとし、採用したresearch ID・利用モード・変更/維持の理由を残す。
過去の研究の評価・depth・時間は研究IDから参照する。今回の探索のdepth・nodes・時間は別の観測である。
1時間の研究から直接手を選んだ回に、今回200msで深さ20を完了したような行を書かない。今回探索が選んだ別の手の評価を、採用した研究手の評価として結び付けない。
通常長期記録へ未採用の新候補を全保存する仕様にはしない。相違の発生と再研究対象の局面・条件だけを小さく記録する。研究モードでの別の観測は別研究結果として扱う。
保存項目の具体的な対応はdocs/28へ追加し、collectorのscoreとbestmoveの対応検査も改修する必要がある。

## 調査した実装と不足
調査時commit `19260291fa4248f0eafc9ec828c98256f2682181` の `engine/strategy/experience_cache.h` は手と深さのhintを保存し、評価・境界を返して探索を打ち切る仕組みではない。
`engine/strategy/iterative_search.h` はchooseごとの完了結果を保持し、完了反復の結果を採用する。過去の1時間研究をrootの既定着手として維持するBの判定は接続されていない。
したがって時間項目の保存だけでは今回の目的は実現しない。研究結果のloader、適用判定、最終着手の判定、出所を分けるtelemetryが必要になる。
既存Experienceの仕様を本書だけで変更しない。研究結果をどの知識資産へ載せるかはH10で別途決める。

## 検証する順番
同じ研究結果・エンジンを固定し、通常探索、A、Bを比較する。
- 研究手の選択率と、短い探索が別の手を出した率。
- 選択が分かれた局面を別の長考研究で調べる。研究手と同じことだけを正解としない。
- 勝敗・不確実性・総時間・違法手・研究参照の負担。
- 条件不一致、新版、欠損、曖昧な評価、深さ0、部分探索、反証、研究ファイル破損から通常探索へ戻ること。
- 当時の研究時間と今回の探索時間・評価が記録上で混ざらないこと。

通常の比較条件はR20に従う。1時間の研究は利用場面の例であり、今回実行していない。
本書は案の具体化まで。Bの採用条件、実装、比較結果は未確定である。

## 短時間で同じ判断へ届くよう本体を改善する
2026-10-07、オーナーは研究結果の再利用に加え、「渡された手と同じ判断を時間内にできるようにパラメータを調整すべき」と述べた。
研究済みの局面で結論を利用する経路と、評価・探索を改善して短時間でもその良さを捉える経路を設ける。前者の動作や候補パラメータの正式採用は、引き続き別の判断を要する。

### 改善の流れ
1. 同じ版・設定・局面・到達履歴で、短時間の選択手と長考の選択手が異なる研究対象を集める。長考手は暫定的な改善の目安とし、無条件の正解にはしない。
2. 選択された両方の手について、評価項目の内訳と、探索順・完了深さ・ノード等を調べる。短時間で読み切れなかった戦術なのか、局面価値の捉え方が弱いのか、探索順の問題なのかを研究する。内訳の差だけで原因を確定しない。
3. 評価が原因なら、既存項目の重み調整を候補にする。必要な意味が表現されていなければ特徴量や項目の定義も改善する。長考手を選ばせるためだけに無関係な加点を足さない。
4. 探索が原因なら、探索順・延長・削減等の候補を別に検討する。評価パラメータの調整だけであらゆる深い戦術を再現できると前提にしない。
5. 作成に使った局面と、未使用の検証局面を分ける。意味の共通する局面をまとめた場合も、ほぼ同一の局面が両集合へ漏れていないか確認する。
6. 現行版と候補版について、研究手への一致率、長考を参照した選択差、総時間、探索量、別局面での悪化を比較する。研究手を既定の着手にするBはこの評価ではOFFにし、候補版自身が時間内に選べたかを測る。
7. 固定200msの診断と、R20の正式な200ms＋AdaptiveLongThink条件の比較を区別する。棋力比較と診断結果を整理し、R10に従ってオーナーへ採否判断を提示する。

### 記録と限界
研究IDと対象版を付け、元の短時間手・長考手の観測は保持する。通常対局の全候補手を新たに長期保存する要件にはしない。
研究対象の合法な手が1つしかない局面や、点差がほとんどなく複数手が同等の局面は、完全一致率の意味を区別する。長考手と違うことだけを失敗にしない。
全体の評価内訳は選んだ研究局面だけでコード版付きにする。パラメータ候補・評価定義・探索変更・利用データ集合を識別し、何を変えた結果か分かる形にする。
過去の研究手に合うことは、未登場局面でも強くなることの保証ではない。独立した検証と比較対局で確認する。
今回確定したのはこの改善方向であり、具体的な重み・定義・探索変更の採用ではない。自動調整・比較・エンジン変更はまだ実行していない。
