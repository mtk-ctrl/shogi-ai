# 3手探索（3-ply）

## 何が増えたか

v0.0.5までは `自分 → 相手` の2-plyで評価していた。v0.0.6は、同じ駒得評価のまま `自分 → 相手 → 自分` の3-plyまで読む。

これにより、2-plyでは評価地点の外にあった「次の自分の取り返し」「次の自分の攻め」「3手目の詰み」が探索範囲に入る。

## 基本形

各自分手について、相手が最も嫌な応手を選ぶと仮定し、その応手に対して自分が最善の継続手を選ぶ。

```text
自分の候補手（最大化）
  └ 相手の応手（最小化）
      └ 自分の継続手（最大化）
          └ 駒得または終局結果を評価
```

勝敗が確定した局面は通常の駒得より優先する。

## αβ探索

全てを読む3-ply minimaxは急激に重くなるため、v0.0.5で導入したαβ探索を最初から使う。

相手側では、ある自分の候補手が現在の最善候補より確実に悪いと分かった時点で、その候補の残りの応手を読まない。

3手目の自分側では、既に相手が選べるより悪い応手が分かっているとき、その応手について残りの自分手を読まない。

固定2局面で枝刈りなし3-ply minimaxと比較し、選択手を完全一致させながら69,748局面から21,285局面へ削減した。

## 3手詰めとの関係

専用詰将棋探索を追加したわけではない。通常探索が3-plyになったことで、

```text
自分：王手
相手：唯一の逃げ
自分：詰み
```

という形を探索中に認識できるようになった。

固定テストでは `5c5b → K6a → G6b#` の強制手順を見つける。`go mate` は引き続き未実装である。

## 効果

v0.0.5との正式100局比較：

- v0.0.6：99勝1敗0分
- 違法手：0
- 平均手数：76.67手

評価関数・ルール層を変えず、探索深さだけを増やしたため、棋力向上の主因を深さの効果として観察できる。

## 代償

同じ100局run内の平均応答時間：

- v0.0.5：13.676ms/手
- v0.0.6：225.065ms/手
- 約16.5倍

v0.0.6の最大応答時間は6.71秒であった。

探索ノードの大部分は3-ply末端であり、4-plyへそのまま伸ばす前に高速化が必要である。

## 次

3-plyのまま**手の並べ替え（move ordering）**を導入する。

αβ探索は、良い手・悪い手を早く発見するとより多くの枝を切れる。探索結果を変えずに読む順番だけを改善し、ノード数と応答時間を減らせるかを測る。
