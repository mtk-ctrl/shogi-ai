# システム構成

## 全体像

```text
ChatGPT
  │  設計・コード・解析・GitHub更新
  ▼
GitHub（正本）
  │
  ├─ ソースコード
  ├─ Markdown資料
  ├─ テスト
  └─ 実験記録
  │
  ▼
Androidスマートフォン
  │
  ├─ ShogiDroid2（盤面・操作・検討GUI）
  │      │
  │      └─ USI
  │             │
  │             ▼
  │        自作将棋AIエンジン
  │
  └─ 必要に応じてTermux等（ビルド・実行補助）
```

## 各要素の役割

### ShogiDroid2

人が盤面を見て操作するためのGUI。将棋AIそのものではない。

主な役割は、

- 盤面表示
- 駒操作
- 対局管理
- 棋譜表示
- USIエンジンへの局面・思考要求の送信
- エンジンが返した着手の盤面反映

である。

### 自作将棋AIエンジン

盤面を受け取り、どの手を指すか決定する部分。

初期の追加計画には次があった。NNUEは将来候補であり、他の基本探索・評価は既に実装されている。現在の本体はmainの `engine/strategy/`、採用状態はREADMEとルーターから確認する。

- 合法手選択
- 局面評価
- minimax
- αβ探索
- 反復深化
- 置換表
- NNUE等

を挙げていた。

### USI

ShogiDroid2とAIエンジンをつなぐ通信規格。

GUIとAIを分離できるため、盤面アプリを作り直さずに思考部分だけ差し替えられる。

### GitHub

採用済み実装と保存された文書の正本はGitHubのmain。開発意図はユーザーとの会話で確定した内容を正とし、mdとの食い違いはR00・R70・R90に従って訂正する。

コードだけでなく、開発理由・実験結果・強化履歴も管理する。

### GitHub Actions

現在、

- ビルド
- 自動テスト
- Android向け成果物作成
- 対局結果の集計

を用途別workflowで扱う。内部比較の対局結果集計と着手アーカイブも実装済み。APK生成・比較対局・外部Benchmarkは必要時に明示起動し、夜間定期対局は停止中。起動条件の正本はR10・R15・R30・R60、実際のworkflow一覧は `.github/workflows/README.md` を参照する。

### Termux

Android上でLinux系コマンドやコンパイラを扱う必要が生じた場合の候補。

最初からユーザーがTermuxを操作することを前提にはしない。GitHub Actions等で代替できる部分は自動化する。

## データの流れ

対局時は概ね次の流れになる。

1. 人または相手AIがShogiDroid2上で着手する
2. ShogiDroid2が現在局面をUSI形式でエンジンへ渡す
3. エンジンが候補手を生成する
4. エンジンが候補手を評価・探索する
5. 最終的な1手を `bestmove` として返す
6. ShogiDroid2が盤面へ反映する
7. 棋譜・ログを必要に応じて保存し、強化検証に利用する

## 将来の発展

学習型AIへ進む場合は、対局用エンジンとは別に、

- 自己対局データ生成
- 学習プログラム
- GPU計算環境
- 学習済みモデル保存

が追加される。

この段階で初めて、GitHubだけでは扱いにくい巨大データ用ストレージを検討する。
