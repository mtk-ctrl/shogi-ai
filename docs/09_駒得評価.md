# 駒得評価（v0.0.3）

## 何を考えるようになったか

候補の合法手を1手ずつ試し、着手後の盤面と持ち駒を数える。
「自分の合計点 − 相手の合計点」が最も高い手を選び、同点だけランダムに選ぶ。
これは着手直後だけの比較であり、相手の応手は読まない。

| 駒 | 通常 | 成駒 |
|---|---:|---:|
| 歩 | 100 | 600 |
| 香 | 300 | 600 |
| 桂 | 300 | 600 |
| 銀 | 500 | 600 |
| 金 | 600 | ― |
| 角 | 800 | 1000 |
| 飛 | 1000 | 1200 |
| 玉 | 0 | ― |

持ち駒は通常の駒と同じ点数とする。玉は合法手では取れず、勝敗判定はルール層が担うため点数を付けない。
この表はロードマップの例を初期値にした自作の値であり、最適値の主張でも学習結果でもない。
成った歩・香・桂・銀は金と同点、馬・龍は元の駒に200を加える単純な仮定とした。

例えば歩を取ると、相手の盤上から100点が減り、自分の持ち駒に100点が増えるので差は200点よくなる。
と金を取ると相手の600点が減り、自分の持ち駒は歩100点になる。駒を打つだけなら持ち駒から盤へ移るだけで合計点は変わらない。

## コードの場所

- `engine/strategy/material.h`：駒価値、評価関数、1手比較
- `engine/strategy/random.h`：前段階の選択方法を保存
- `engine/rules/position.h`：既存のルール窓口。今回変更なし
- `tests/strategy_test.cpp`：駒得・後手の符号・成り・持ち駒・巻戻し・既知の弱点

評価関数は常に「先手 − 後手」を返す。選択時に着手前の手番に合わせて符号を変える。
候補を指すと手番が変わるため、そこで評価の向きを取り違えないことが必要である。
指した候補は毎回戻し、実局面も千日手の履歴も変更しない。

## まだできないこと

飛車で歩を取った後、その飛車が相手の飛車に取られる場合でも歩を取ってしまう。
この具体例はテストに固定してある。次段階で先読みを加えたとき、危険を避けられたかを確認するためである。

玉の安全・駒組み・1手詰めを評価項目にしていない。既に詰まれた局面はルール層で認識するが、
候補の評価に詰みの価値はまだ加えていない。ランダム版への勝ち越しは、人に勝てることや目標1.5達成を意味しない。

## 再現

```bash
python3 -m pip install python-shogi==1.1.1
python3 scripts/build.py
python3 scripts/build.py --strategy-test --output build/strategy-test
./build/strategy-test
python3 tests/test_usi.py build/shogi-ai
python3 tests/test_arena.py
python3 tests/check_boundary.py build/shogi-ai
python3 scripts/build.py --strategy-test --sanitize --output build/strategy-sanitized
./build/strategy-sanitized
```

比較相手は固定署名v0.0.2の `bbce956c8ec23f425adb497c5c8dc0a798b870d0` を別の作業場所でビルドする。

```bash
python3 benchmarks/arena.py --engine-a build/shogi-ai --engine-b BASELINE/build/shogi-ai \
  --games 100 --max-plies 400 --seed 20261004 --output build/material-vs-random-100.json
```

同じseedでもC++標準ライブラリなど実行環境が違うと同点選択の列が変わる場合がある。
JSONには実行ファイルのハッシュと全棋譜を残す。持ち時間と測定時間の扱いは `08_開発運用と評価フロー.md` を参照する。
