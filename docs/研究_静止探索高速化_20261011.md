# 静止探索効率化（2026-10-11、研究候補）

問題: 200ms探索の大半が静止探索に費やされ、通常探索の深さが十分に伸びない。
仮説: 静止探索の同一局面で、status()、legal_moves()、play()を経由した
合法手生成が重複し、無駄なCPU負担となる。

研究変更: repetition_status() を保持し、legal_moves() を1回にまとめて
終局・全合法手を判定。既に生成した着手は play_generated_legal() で適用。
探索する候補手、静止探索上限、王手回避、評価関数、枝刈り条件は変更しない。

比較: 研究手を無条件に指す局面知識を双方でOFFにし、正式版との間で
10局面200msと固定深さ1の一致確認を同一runnerで実施。
探索速度と棋力は別の指標であり、この比較だけで正式採用しない。
候補ブランチ以外のエンジン変更は行わない。

## 初回計測と第2案
最初に合法手文字列を全節点で一度だけ構築する案は、同一200ms×10局面で深さ合計24→22、探索ノード189113→121406と逆効果。各節点のスタンドパット/上限で即座に終了する場合にもUSI文字列を構築していたためと推定。
第2案では既存のstatus()の軽量な終局判定を残し、スタンドパット後に限りルール層のGeneratedMoveトークンを取得する。読み手/評価/枝刈りは不変のまま、各子着手にplay_generated_move()を用いて追加のLEGAL_ALL照合を削減する。

- 対照の固定commit: 2c0b2ccf2a7207672e913167cf49709940fd8686

- 現行の探索ノード計132,299→候補152,279（約+15.1%）、通常探索の完了深さ合計22→23。
- 選択手は9/10一致。違う1局面は深さが増えたM04（現行深さ1→候補2）であり、改善手かどうかは未判定。
- 4局面の固定深さ1で手・評価値・探索ノードが完全一致。探索・静止探索・USIの単体テスト成功。
- 第1案は同じ10局面を用いた別実行run 38095973628でノード189,113→121,406、深さ合計24→22に悪化し、撤回。

- 結論：第2案は速度改善の有望な候補だが、棋力向上は未検証。現行mainへの自動採用は禁止。新たな難局面での再現性と、同一条件の実戦対局を追加検証してオーナーへ採否提案する。
