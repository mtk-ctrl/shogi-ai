### 5本柱の分担

盤上座標はSnapshotの `(筋-1)*9 + 段`。各陣営の特徴を同じ式で数え、最後に先手分−後手分を取る。手番ボーナスは設けない。

| 柱 | 意味・具体的な数え方 | 初期点数 | 効く場面・副作用 | 固定テスト |
|---|---|---|---|---|
| 駒得 | 盤上の駒価値＋持駒価値。成駒価値は従来どおり | 歩100、香桂300、銀500、金600、角800、飛1000。成小駒600、馬1000、竜1200 | 全段階の基準。将来の損失はまだ確定損ではない | 既存の価値・持駒・成駒テスト |
| 玉安全 | 自玉8近傍にいる金・成小駒、銀、歩を数える。囲い名・筋・陣地に依存しない | 金型12、銀10、歩4。片側上限80 | 序中盤の守備配置。駒を玉に密集させる癖に注意。安全そのものの保証ではなく守備の構造 | 同じ駒を近傍と遠方へ配置、金銀歩以外は加点なし |
| 攻撃圧力 | 相手玉とその8近傍への非玉の利き。玉／駒のある近傍への利きと、空き近傍の退路制限を分ける。2枚目以降の安全な参加駒で協調を少量加点 | 玉への利き12、占有近傍1升6、空き近傍1升4、追加参加駒8。片側上限120 | 中終盤。単純な距離・王手回数は数えない。守られていない攻撃駒は協調加点対象外。持駒の打ち込みは未評価 | 利きが届く／届かない、単独接近、協調、玉を透過する退路の長い利き |
| 活動性 | 玉以外の駒の擬似移動先のうち空き升を数える。双方の玉近傍は除く。敵の安い駒に取られる升は除く（無被攻撃、または敵最小価値≧自駒価値） | 大駒2、その他1／升。1駒の有効升数は最大12。片側上限100 | 序中盤の通り。大駒の遊びは有効升数0〜1で自然に低評価。駒組み・前線参加の距離点は追加しない | 同じ大駒の開放／閉塞、玉の移動で活動性を稼がない、危険な移動先 |
| 危険度 | 玉以外の駒が敵の利きにある場合、無守備なら駒価値V、守備ありならmax(0,V−敵最安攻撃駒価値)を危険量とする。その合計の小部分のみ減点 | 危険量×1/8、片側上限160。玉の攻撃価値は通常駒より大きく扱う | 探索末端のただ取り・安い駒との交換に注意を向ける。等価以上の交換を守備付きなら罰しない。SEEではなく、ピン・多段交換・手番・駒打ちを完全には読まない | 高価値のただ取り、守備付き等価交換、守備付きでも歩で取られる飛車 |

### 重複を避けるための整理

- 敵の利きと退路制限は攻撃圧力だけで数える。玉安全には敵の利きを再度減点する項目を置かない。先手の攻撃圧力−後手の攻撃圧力で、自玉への攻めも既に減点される。
- 占有近傍と空き近傍は排他的。空き升は退路制限、占有升は守備駒への圧力として数える。玉が移動して空けることで開通する飛香角の射線も退路制限に含める。取って逃げる手やピン解除までは評価せず、合法な逃げ道の数とは呼ばない。
- 参加駒は「2枚以上で攻める」協調項。1枚で多数の升を利かせても参加数は1。玉を近づけても攻撃参加には含めない。攻撃されて無守備の駒は協調を稼げない。
- 玉周辺の空き升は活動性から除外し、攻撃圧力と重ねない。飛角の長い通りも同じ有効升数で表し、別の開放筋点・遊び駒罰は足さない。
- 駒得は現物の価値、危険度は将来失う可能性の小さな補正。捕獲後に消えた駒へ危険罰を残さない。成りやすさ・敵陣進出は成駒価値等との重複を避け、今回は見送る。

### 利きと計算量

Snapshotを1回走査し、各駒の短い利きと長い射線を列挙する。味方駒のある升にも利きを置き、そこで射線を止める。歩・香・桂は陣営に応じて前方を逆転。成歩香桂銀は金、馬は角＋縦横1升、竜は飛＋斜め1升。打ち駒とピンを含む合法手を評価内で生成し直さない。

共通のAttackMapに升別攻撃数・非玉攻撃数・最安攻撃駒価値・駒別到達先を保存し、各柱は独立関数で読む。王の奥へ伸びる射線だけは退路用の別マップへ保存し、通常の利きには混ぜない。サイズ固定、動的確保なし。合法手の裁定は引き続きルール層だけが行う。

### スケールと将来の調整

整数cp（歩100）。柱ごとの重みは百分率で、初期は各100%。片側の柱点を上限処理した後に先後差を取り、整数乗算／100。危険度の負号を含めた4補正の合計にも±300cpの対称上限を置く。柱単独の初期上限は歩0.8〜1.6枚相当。探索で読めた詰み±100,000,000は静的評価より常に優先する。静的評価全体にも十分離れた安全上限を置く。

パラメータは `evaluation_params.h` に集約し、既存の駒価値はmaterial.hを唯一の定義元に保つ。raw特徴、柱別点、補正前合計、制限適用差、合計を `EvaluationBreakdown` で取得する。`EvalProfile` と4柱のUSI重みで同一バイナリの異なる設定を対戦可能にする。arenaは設定を結果に保存する。SPSA/CMA-ESはまだ実装せず、整数範囲へ投影する外部調整器からこの入口を使える構造にする。

置換表はchoose()開始で必ず世代更新する。評価器は検索開始前に値として設定し、同期探索の途中には変更しない。前の評価パラメータの値は参照できない。異なる設定を同じインスタンスで交互に検索し、新規インスタンスの結果・探索統計と一致する回帰で検証する。

### 実装前自己レビュー

1. 玉安全と攻撃圧力を敵の利きの表裏として両方足す案は不採用。守備配置と敵の働きを分離した。
2. 合法手mobilityは高コストのため不採用。擬似利きはピンに弱いので補正を小さく抑える。
3. 近づくだけの参加点、囲い名、前進、成り可能数は不採用。実際の利きだけを使う。
4. 敵の利きがある駒を全て減点する案は不採用。守備と攻撃側価値で等価交換を区別する。
5. 「玉を危険にさらして歩を取らない」を常に保証する重みにはしない。読める詰みは終局判定で禁止されるが、3-ply外の詰みは残る限界として記録する。過大な安全点で駒得を壊すより、固定局面と棋譜で失敗を観測する。
6. 片側上限→差→対称上限の順を守り、180度回転＋色交換＋持駒交換で符号が厳密に反転する。手番変更だけでは静的評価は変えない。

## 検証結果

固定局面・全回帰・CIを通過。正式旧版との100局は72勝28敗、成り方針同一版とは77勝23敗、違法手0。1評価は約0.364μsから7.780μsへ増加した。2,664局面の分布、棋譜の癖、採否は[開発記録](../journal/2026-10-04_07_特徴量評価の導入.md)を参照。初期重みは正解でも学習結果でもない。

## 使い方と変更範囲

```text
setoption name EvalProfile value features
setoption name EvalSafety value 100
setoption name EvalPressure value 100
setoption name EvalActivity value 100
setoption name EvalDanger value 100
position startpos
eval
go
```

`eval` は現在局面の先手視点の内訳を返す診断コマンド。探索末端の最善値ではない。`EvalProfile=material` なら4補正を無効にして駒得のみへ戻る。重みは0〜400の整数（%）で、範囲外や数字の後ろに文字が付いた入力は採用しない。設定は同期探索の間にだけ変更される。

```bash
python3 benchmarks/arena.py --engine-a build/shogi-ai --engine-b build/shogi-ai \
  --options-a '{"EvalDanger":100}' --options-b '{"EvalDanger":75}' \
  --games 100 --output build/danger-100-vs-75.json
```

`BasicAlphaBeta3TT<Evaluator>` に評価器を値で渡す。旧 `AlphaBeta3TT` は駒得評価の別名として残し、既存の探索最適化回帰に使う。実運用は `FeatureAlphaBeta3TT`。探索本体の変更は末端で呼ぶ評価器と検査用最善値の保存に限り、3-ply、αβ条件、move ordering、TTヒット判定は同じである。

成り方針もv0.0.9と同じく、USI呼出側で「今回自分が実際に指すroot候補」に適用する。探索内部の相手手番と3手目の仮想継続は従来どおり全合法手を残す。明示的な `searchmoves` が不成だけを指定した場合はその指定を尊重する。銀・桂・香の不成は削らない。探索内部の自分手にも方針を広げる変更は、今回の評価比較とは分ける。

## 近似の限界

- 玉安全は守備配置の一要素であり、囲いの完全な堅さではない。味方の金銀がピンされている場合も守備として数える。
- 危険度は交換の簡易見積りであり、攻守の全手順を読むSEEではない。複数攻撃に守備1枚でも「守備あり」とするため、数の攻めを過小評価する場合がある。玉の守備も幾何的な利きであり、取り返しの合法性は探索に任せる。
- 退路制限は空き近傍に限る。敵駒を取って逃げる手、駒打ちによる王手、開き王手全般までは評価しない。
- 序中終盤の重み切替は導入しない。将棋では駒が取られても持駒として残るため、盤上の駒数だけで終盤度を推定すると歪む。現段階は全局面で共通の小さな補正とする。
- 大駒を取れるのに3-ply外で詰むような局面は、今回の静的特徴だけで必ず防げるとはしない。失敗局面を次段階の固定問題に追加する。
- `evaluate(snapshot, parameters)` のパラメータは検証済みを前提とする。実運用は `FeatureEvaluator` の生成時に検証し、末端ごとに同じ検証を繰り返さない。

## 検証方法の修正

旧3手詰めfixtureの比較候補 `9i8i` は、実際には `5c5b` と同じく3-ply内で勝てた。旧回帰の選択一致は乱数seedに依存していた。新評価のUSI回帰では、飛車の縦の支えを外す `5i4i` を非詰み候補にし、C++ではその候補の値が詰み値未満であることも確認する。旧評価・旧探索の回帰は引き続き残している。
