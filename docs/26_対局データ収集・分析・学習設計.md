# 対局データ収集・分析・学習設計

## 目的

KUMOJI の対局を勝敗確認だけで終わらせず、すべての対局を次の研究材料へ変換する。

1. **Raw Match Record** — 何が起きたかを再現可能な形で保存する
2. **Analysis / Diagnosis** — どこで、なぜ差が付いたかを切り分ける
3. **Learning Asset** — 再利用価値のある局面だけを問題集・経験・設計仮説へ送る
4. **Validation** — 学習や実装が本当に強さへつながったかを別対局で確認する

対局相手は教師ではない。自己対局、旧版、Challenger、外部AIのいずれも「観測対象・物差し」として扱い、相手の指し手をそのまま正解として模倣しない。

長期蓄積する基盤データの範囲は `docs/rules/R25_着手記録の保存.md` を正本とする。
本書のRaw Match Recordは診断用の短期原記録であり、PV等を含んでもよいが、R25の圧縮着手アーカイブには未着手候補・PV・探索木を持ち込まない。
局面知識の新候補を正式採用・自動更新する条件は、R10・R25に従い別途検証する。

## 1. 診断用の短期 Raw Match Record

benchmarks/arena.py と benchmarks/position_arena.py を標準対局ランナーとし、下記を自動保存することを目標にする。要求項目と実装済み項目を混同しない。

現状、arena.pyは実体ハッシュ・options・seed等と実戦手・探索観測を保存する。position_arena.pyは開始までの `opening_moves` と続きの実戦手・探索観測を保存するが、出力のEngineハッシュ・options・seed等は未収録であり、圧縮着手アーカイブへの自動接続も未実装である。R25のschema 2・確定build commit・資産の版/ハッシュ等も未実装部分を含む。

2026-10-08、複数info行のcp/mate・境界フラグの混在を訂正し、最新scoreの種別・値・境界をまとめて入れ替える。scoreのない統計行では評価を消さない。過去の混在行は原値を保持し、圧縮時に `ambiguous` として欠損と分けて数える。この訂正だけで過去の全記録・集計結果の検査が完了したとはしない。

- 開始局面
- 先後
- 全指し手

- 手数
- illegal の有無
- 最終局面
- 対局全体の wall time
- Engine別の集約探索統計

### 1手単位

- ply
- 手番
- どのEngineが指したか
- 指し手
- 王手中だったか
- 着手前の合法手数
- 駒取りか
- 成りか
- 持駒打ちか
- 着手後に王手を掛けたか
- live search の深さ / seldepth
- live search の score

### 外部AI対局の例外

benchmarks/external_match.py では、KUMOJI自身の盤面事実と対局時の探索記録だけを保存する。外部AI側のscore / PV /探索情報は従来どおり捨て、教師データにはしない。

外部AI対局は diagnosis の材料にはできるが、相手の指し手や評価値を局面知識や評価関数学習へ直接投入しない。

## 2. 全対局後に行う軽量分析

重い500ms再探索を全局面には掛けない。まず保存済みRaw Recordから安価に全局を走査する。

### A. Strength

- 勝敗
- paired score
- Elo estimate
- 先後差
- 開始局面別成績
- 局面知識の利用条件別
- 旧版 / Challenger / 外部benchmark別

### B. Evaluation trajectory

- Black基準評価値の推移
- 数手以内の大きな評価急変
- 有利から敗北 / 不利から勝利した surprise
- mate score出現地点
- move limit / repetitionへ向かった局面

異なるEngine同士の対局では、各Engine自身のlive scoreをそのまま隣接比較して因果推論しない。急変候補を見つけた後、固定Analyzerで再評価する。

### C. Search efficiency

- depth / seldepth
- nodes / time
- cutoffs
- TT hit率
- 局面知識の一致率
- qnodes
- 同等の結果を得るための探索量
- 特定局面で探索量だけ急増する箇所

### D. Tactical / terminal events

- 王手
- 駒取り
- 成り
- 詰み
- 詰み逃し候補
- 千日手
- 連続王手千日手
- 入玉宣言
- 200手等のmove-limit

## 3. 深掘りする局面の選び方

全局面を深く読むのではなく、情報価値が高い局面だけを選ぶ。

優先順位は次の通り。

1. **評価急変**
2. **deep lossが大きそうな着手**
3. **50ms / 500msでbestmoveが違う局面**
4. **50ms / 500msでscoreが大きく違う局面**
5. **大幅有利評価からの敗北 / 大幅不利評価からの勝利**
6. **静的評価と深い探索が矛盾する局面**
7. **同じ失敗型が複数局で再現する局面**
8. **旧版や既存知識と違うが深く読んでも悪くない独自手**
9. **局面概念を説明できない unknown**

選抜時は、単純な駒取り・成り・詰み直前など「大きく動いて当然」の局面だけが上位を占領しないようにする。

- start SFEN + move sequence でdedupe
- 同型パターン数を上限制御
- capture / promotion / terminal 近傍を別層化
- opening / middlegame / endgame を分散
- 情報価値（deep loss、disagreement、surprise、static-search gap）を優先

## 4. 原因帰属

評価が上がったことと「良い手を指した」ことは同義ではない。

短区間ごとに少なくとも以下へ分ける。

- **gainer-good-move** — 評価を得た側の好手
- **opponent-mistake** — 相手の悪手
- **mixed-good-move-and-opponent-mistake** — 両方
- **forced-concession-or-pressure** — その一手は悪くないが既に選択肢を奪われていた
- **static-overreaction / evaluation-candidate** — 静的評価側の問題
- **search-horizon-candidate** — 読みの浅さ・探索側の問題
- **near-terminal / mate** — 詰み近傍として別管理
- **unknown** — 現行概念では説明できない

deep loss は固定Champion Analyzerで、
「着手前500msの最善値」と「実戦手後500ms評価を着手者視点へ戻した値」の差で測る。

## 5. 何を分析し、何を学習資産へ送るか

### 5.1 評価関数の弱点

対象:
- 深い探索では悪いのに静的評価が高い
- 深い探索では良いのに静的評価が低い
- 同じ特徴で繰り返し誤る

見る軸:
- Material
- Safety
- Pressure
- Activity
- Danger
- Influence / Control
- Coordination
- Mobility / Freedom
- Space
- Shape / king form
- Phase
- promotion value
- bishop / rook line
- idle pieces
- attack-piece sufficiency

学習先:
- 日中のEngine仮説
- evaluation regression suite
- Position Bank

新しい評価概念を夜間処理が勝手に実装しない。

### 5.2 探索の弱点

対象:
- 50msでは悪手、500msでは修正
- PVが浅いときだけ誤る
- 詰み・駒取り・静止局面で誤る
- nodesを大量消費しても改善しない

見る軸:
- iterative deepening
- move ordering
- TT
- quiescence
- extensions
- mate assist / mate search
- repetition handling
- endgame search

学習先:
- Search Problem Suite
- 探索機能Challenger
- regression test

### 5.3 局面知識の再利用

以下は観測・診断する項目である。どの結果を局面知識候補へ加え、正式版へ採用するかはR10・R25に従って別途判断する。

対象:
- 同一または近い局面を再訪する
- 深い再探索でbestmoveが安定している
- warm時に探索を削減できる

見るもの:
- hit率
- bestmove一致
- nodes削減
- wall time削減
- 局面知識あり・なしの比較で実際の勝率が改善するか

nodesや時間が減っただけでは「強くなった」と判定しない。

### 5.4 序盤の局面知識

対象:
- 序盤の局面知識を参照した手
- 局面知識の対象から外れた局面
- 離脱時評価
- 離脱後数手の評価
- 最終勝敗

対象から外れた時点の評価・その後の評価・最終勝敗は分析候補として保持する。どの情報を局面知識の採否へ使うかは本書だけで自動確定しない。

### 5.5 戦略・形

対象:
- 角道・飛車道を開けない
- 取る駒がないと不要な歩を打つ
- 駒が働いていない
- 攻め駒不足
- 守りの効き不足
- 効きは多いが意味が薄い
- 自由度がない
- 空間を渡しすぎる
- 玉形が悪い
- 成りの価値を過小評価する

学習先:
- Influence / Coordination / Space 等の日中研究課題
- motif別Position Bank
- 同型局面のAblation比較

### 5.6 Novelty / Independence

対象:
- 既存の局面知識や旧版と異なる手
- 外部AIと異なる手
- ただし深い再探索でも悪くない手

見るもの:
- move一致率
- deep score
- 同種局面での再現性
- その後のpaired成績

「珍しい」だけで価値を与えない。強さを保った差だけを valuable novelty とする。

## 6. 保存先の役割分担

### Raw Game Artifact

目的:
- 完全再現
- 後日別の分析軸が増えても再解析可能

保持:
- 期限付きの一時artifactとし、保存日数は各workflowとrepository設定に従う
- 継続蓄積はR25のplayed-move archiveを使い、Raw全量を長期保存の正本にしない
- 重要な歴史的対局は、再現に必要なsummary・代表subset・manifestを別途永続化してよい

### Position Bank

目的:
- 情報価値の高い局面を長期保存
- 翌晩以降の再対局開始点

保存:
- dedupe済み
- 原因タグ
- phase
- static breakdown
- shallow / deep
- first_seen / last_used / use_count

### Problem Suite

目的:
- 同じ弱点が再発しないかを継続検査

分類例:
- evaluation
- search
- mate
- repetition
- mobility
- king safety
- influence
- promotion
- opening line
- unknown

一度解決しても削除せず、solved_by を残す。

### 局面知識候補

目的:
- 深く再解析して安定した指し手を「局面知識へ再利用する研究候補」として識別する

ここで付けるのは候補タグまでとする。研究局面集から正式な局面知識へ自動採用しない。
採用基準と保存方式はR10・R25・docs/35に従う。

### Daytime Research Backlog

目的:
- 対局で繰り返し観測されたが、現行評価概念では説明できない問題を人間と設計する

---

## 7. 学習の禁止事項

対局データから次を直接行わない。

- 勝った側の全指し手を正解にする
- 外部AIの指し手を教師ラベルにする
- 評価上昇した手を全部好手扱いする
- 敗局で参照した局面知識を一律に減点する
- 1回だけ出た局面で評価weightを変更する
- 局面知識による探索量削減を棋力向上と同一視する
- Nightly結果だけでmainへ自動昇格する

---

## 8. 標準フロー

今後の対局は原則として次の流れに統一する。

**Match**
→ 対局時の原記録保存
→ 軽量全局走査
→ 情報価値で候補選抜
→ 固定Championで50ms / 500ms再解析
→ 原因帰属
→ dedupe / 多様性制御
→ 研究局面集 / 問題局面集 / 局面知識候補 / 日中研究候補へ振分
→ 仮説実装
→ paired validation
→ 採否判断

この流れにより、「対局数を増やした」こと自体ではなく、対局から何を発見し、それが次の強化にどうつながったかを追跡可能にする。

## 2026-10-17：予算内の多世代自動実行

[多世代制御](../research/postgame-cycles/README.md)に、評価学習経路の実行アダプターを追加した。明示した凍結PLANから既存Generic Engine Matchを起動し、監査/保存、親設定での再分析、適格例の蓄積と1候補学習、実バイナリ検査、100/200局比較と重複感度、研究親の選択、次の原本まで1つの手動runで継続する。毎時scheduleや旧G1再起動は使わない。

材料不足/候補不合格は親保持して予算内の次世代へ進め、監査/保存/応答不明は停止する。操作意図をdispatch前に連番Release台帳へ保存し、受理された本体IDを照合する。次世代sourceは次世代用seedを使う。研究親が変われば旧特徴を混ぜず、分割/未使用台帳と原本を保持する。正式Engine/163件知識は自動更新しない。新規知識の汎用配布は対応外で、候補研究を保存する。

実働の範囲と結果は各凍結PLANのRESULTS/receiptを正本とする。制御の動作確認や合成候補の成功を棋力向上と報告しない。


多世代接続の実働結果：制御39021709686で2世代4局474手/16局面を自動処理し、材料不足/親保持のまま上限停止した。読取り専用39022564114で全原本/保存/分割履歴を読み戻し、receiptから最終台帳を完全再現。90検査合格。次の明示計画へ完了台帳をhash固定で渡せる。これは実装の動作確認であり、学習候補の棋力向上とは区別する。[実測](../research/postgame-cycles/spiral-auto-smoke-20261017-01/RESULTS.md)を参照する。

## 経験を複数の能力へ返す段階実装

本人の14案への継続依頼を受け、[実装順・具体案・成功条件](../research/self-improvement-20261017/ROADMAP.md)を整理した。第1段階は全選別例の追跡、材料発生率/独立群不足、履歴付き研究課題と停滞制御。新PLANで進捗条件を固定した場合、材料不足が改善しない同種対局を続けず研究見直しへ戻す。知識の課題を評価学習の可否と独立に保持するが、知識の配布や追加研究の実行器は後続段階である。候補の正式採用、外部AIを教師にしない出所、原記録の保存条件を維持する。
