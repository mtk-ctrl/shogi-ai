# 1局に5回だけ最大30秒を読む実験

## 検証すること

通常50msの雲路に、1局につき最大5回、1着手の合計上限30秒を与えると対局結果が変わるかを測る。現行main `8a750d9f90395b6f9a1cee49547b125c52a6f60b` の同一バイナリを両者に用い、評価・探索・Bookの内容は変更しない。

結果を見る前に、主比較をadaptive 20組40局、補助比較をscheduled 10組20局と決めた。補助比較は局面選択の感度を見る小標本であり、両方式の優劣を確定する用途ではない。

## 共通条件

- 通常 `go movetime 50`
- 延長側だけ1局最大5回、短時間探索と再探索を合わせて最大30秒
- OpeningBook ON / MateAssist ON / ExperienceCache OFF
- 先後交換。同じ組の2局ではBlack/Whiteのseedを共通にする
- 初期局面から対局。Bookを同じseedで選ぶが、序盤手順を強制固定しない
- 400手上限。千日手、連続王手、合法手、入玉宣言をArenaで独立検査
- 1対局workerにつきCPUを1個割当。探索を同一CPUへ重ねない
- 応答監視45秒。監視時間と実際の読み時間を区別する
- 両者の全着手・50msのprobe・反復深化の履歴・延長理由・30秒後の読みを保存

## 延長する局面

延長の開始目安を24、56、88、120、160手目に置く。5回を早い段階ですべて使わないための予約であり、最適な時間配分だと決めてはいない。将棋の手数は両者の着手を合計したplyで数える。

scheduledは開始目安以降の最初の候補局面で延長する。

adaptiveは開始目安以降、次のいずれかが生じたとき延長する。

1. 王手を受けている
2. 自分の前回の読みに比べ、自己視点評価が150以上下がった
3. 最後の2つの完成反復で評価が150以上変わった
4. 最後の2つの完成反復で第一候補が変わった
5. 通常の時間を使っても深さ2が完成しなかった
6. 54、86、118、158、198手目に達した（未使用分のfallback）

Bookの即決、既に詰み値が出た局面、合法手1個だけの局面では使用しない。短い対局では5回を使い切らない。評価急変は深さが異なる自己観測も含むため、悪手の証明ではない。

## 実装と限界

本番エンジンは変更せず、`benchmarks/bonus_time_match.py` が時間配分を行う。まず50msで試読し、延長条件が成立したら残りの時間を指定して同じ局面を再探索する。30秒に50msを足して使う方式ではない。

再探索は元の探索の継続ではない。探索のやり直し、MateAssistの再実行、同点候補を選ぶ乱数の追加消費を含む。この実験が測るのはその運用全体の効果であり、純粋な探索時間だけの因果効果ではない。本番に統合するときは同じ探索を継続する方式を別途比較する。

通信・OSスケジューリングにより壁時計は僅かに超過し得る。エンジンの10ms安全余裕を維持し、実測最大値を結果へ記載する。

## 集計

主指標はA（延長あり）の得点率。引分を0.5点とし、先後交換の2局を1組として95%区間を正規近似で求める。20組は精密な棋力差の測定には小さいため、率だけで結論を固定しない。先後別成績、延長回数、読みの深さ、指し手変更数、終局理由も併記する。

長く読んで別の手を選んだことや評価が上がったことだけでは改善と呼ばない。少数の代表局面は保存された短時間・長時間の読みを確認し、必要なら自作の固定Analyzerで追跡する。

## 途中Diagnosisを受けた探索的な追加比較

主比較中のpair-006-half-0では89手目の延長探索（depth5 / +3143）の後、91・93・95手目で深さ1未完成のfallbackが続き、104手目に負けた。5回中3回しか使っておらず、残る2回は120手目以降へ予約されていた。これは時間配分の不足を調べる候補であり、+3143が正しかったことや、その後のfallbackが敗因だったことを証明するものではない。

この1例から、予定のadaptive40局・scheduled20局は変更せず、emergency10組20局を探索的に追加することを決めた。emergency自身の結果を見る前にルールを決める。

- 王手中、または最後に値を得られた自己評価から150以上悪化した場合、手数予約を前倒しして使用する
- 少なくとも自分の2着手（4 ply）を空ける
- 値のないdepth0 fallbackの後も、最後に得た評価値を保持する
- その他の条件と1局5回・1着手30秒の上限は同じ
- この追加比較を事前固定した主比較と合算せず、独立して報告する

```bash
python3 benchmarks/bonus_time_match.py --engine build/shogi-ai --policy emergency --pairs 10 --workers 7 --output benchmarks/results/2026-10-06_bonus-time/emergency
```


## 実験結果（2026-10-06）

### 1. 事前固定した主比較: adaptive 20組40局

- 延長あり A: 21勝17敗2分
- 得点率: 55.0%
- 30秒枠の使用: 137回
- 30秒後に50ms時点と異なる着手を選んだ回数: 87回
- 指し手変更率: 63.5%

Interrupted WORK session で完走した集計値を回収した。WORK終了時にraw対局ファイル自体はGitHubへ保存されていなかったため、この40局については集計値のみを記録する。55%は改善方向だが40局では差を確定できない。

### 2. 補助比較: scheduled 10組20局

- 延長あり A: 11勝9敗
- 得点率: 55.0%

固定手数帯で5回を使う単純な方式でも同じ55%だった。標本が小さく、adaptiveがscheduledより優れているとは言えない。こちらもInterrupted WORK sessionから回収した集計値であり、raw対局ファイルはGitHubに残っていない。

### 3. 探索的追加比較: emergency 10組20局

GitHub Actions run `37411347463` で再現実行し、raw対局・summary・analysisをartifact `bonus-time-emergency-37411347463` として保存した。

- 延長あり A: 8勝10敗2分
- 得点率: 45.0%
- pair-normal 95%区間: 32.8%–57.2%
- 違法手: 0
- 30秒枠: 82回、1局平均4.1回
- 30秒後に着手変更: 37回（45.1%）
- 50ms probe平均深さ: 0.94
- 30秒探索平均深さ: 4.71
- 30秒探索時間: 平均29,990ms、最大29,992ms
- 終局: 詰み18局、千日手2局

30秒枠を使った理由は、王手18回、自己評価150以上悪化33回、反復深化内の評価急変1回、depth2未完了30回だった。危険局面で予約枠を前倒しする方式は、この20局では改善せず45%だった。

### 4. 解釈

30秒まで読むこと自体には明確な探索上の効果がある。50msではdepth0–1に留まる局面が非常に多い一方、30秒では主にdepth4–6まで到達し、実際に着手も多数変わった。

しかし、対局結果としては「1局5回30秒」をそのまま導入する根拠はまだない。adaptive 40局とscheduled 20局は55%、危険局面を前倒ししたemergency 20局は45%で、方式をまたいだ記述的合計は40勝36敗4分、得点率52.5%に留まる。emergencyは事前固定主比較とは別実験なので、52.5%を正式な単一検定値としては扱わない。

したがって現時点の結論は次のとおり。

1. **長考は探索深度と選択手を大きく変える。**
2. **今の探索・評価では、その変化が安定した勝率向上に変換されていない。**
3. **「危険そうな局面で30秒」は少なくとも現在の150cp低下・王手トリガーでは有効ではない。**
4. **本番への5回30秒枠の正式導入は保留する。**
5. 次に見るべき論点は時間そのものより、深く読んだときの手がなぜ勝率改善につながらないか、ならびに長考を使う局面の選別精度である。

なお、この実験ランナーは50ms探索を30秒探索へ継続せず再スタートする。そのため純粋な「同じ探索を29.95秒追加」の効果ではない。本番統合を検討する場合は、反復深化をそのまま継続する時間延長方式を別途実装して比較する。
