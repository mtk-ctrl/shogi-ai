# 多面的評価システム構想

## 位置付け

この文書は、`04_強化ロードマップ.md` の Phase 6「説明可能な特徴量評価」を発展させる構想資料である。構想時点の案を含み、この文書だけから現在の採用状態を判断しない。

構想開始時のv1系は、駒得を基準に玉の守り（Safety）・攻撃圧力（Pressure）・駒の活動（Activity）・駒の危険（Danger）の4補正を加える評価だった。現在の採用版はKUMOJI v2.0.4であり、v2.0.0で採用した評価関数v2の候補Bを維持している。現行の定義・採用値は `32_評価関数v2統合設計.md`、`33_v2.0.0世代基準.md` の評価プロファイルB、main実装を参照する。v2.0.1の時間配分の訂正は `36_v2.0.1長考配分.md` を参照する。

本構想の方向は、特徴量を単純に足し続けるのではなく、**候補手生成・探索順・探索・局面評価・局面別の重み付けを分離した「評価システム」へ拡張すること**である。再利用情報は現在、対局記録・研究記録・局面知識として扱う。以下の構想中の「定跡」は、現行では局面知識の序盤部分として読み替える。外部AIの利用はR50、採用・比較条件はR10・R20を優先する。

強い外部AIとの対局は棋力測定や弱点発見に使い、相手の評価値・PV・候補手を学習教師にしない。学習対象と利用境界はR50に従い、人間との対局はオーナー本人とのものだけを学習対象にする。自作AI自身の評価軸と経験から強化し、外部AIは基準・試験官として利用する。

## 1手を選ぶ全体フロー

1. **候補手を作る**
   - ルール層から合法手を取得する。
   - 定跡、MateAssist、王手、駒取り、成り、脅威への応手などは候補の優先情報として扱う。
   - 定跡は原則として「候補・優先度」を与える役割とし、将来は局面によって探索を併用できる構造を維持する。

2. **読む順番を決める**
   - TT、王手、駒取り、成り、history系情報などに加え、将来は効き・連携・自由度改善などの軽量な構造情報も move ordering に利用する。
   - ordering用の点数と局面評価値は分離する。

3. **探索する**
   - 反復深化、時間管理、αβ探索、置換表、静止探索、MateAssistを中心とする。
   - 手の良し悪しは「直後の見た目」ではなく、相手の最善応手を含めて比較する。

4. **葉局面を多面的に評価する**
   - 各特徴をいったん独立した値として算出する。
   - 内訳を保持し、どの特徴が評価を押し上げ・押し下げたか診断できる状態を維持する。

5. **局面に応じて統合する**
   - 序盤・中盤・終盤、攻勢・守勢、詰みに近い局面などで、同じ特徴でも重要度が異なる。
   - まずは人が追える明示的なルール・重みから始め、自己対局で検証したうえで段階的に自動調整へ進む。

## 今後増やす評価軸

### 1. Influence：効き・支配

既存の `AttackMap` を土台に、盤面全体の効きをより一般的な評価対象にする。

- 各マスに自分・相手が何枚効いているか
- どの種類・価値の駒が効いているか
- 効きの広さ
- 重要マスへの効き
- 敵陣・中央・玉周辺への効き
- 同一地点への効きの集中
- 攻めの効きと守りの効きを区別する

単純な「効いているマス数」だけでなく、局所的な数的優位と効きの質を扱う。

### 2. Coordination：駒の連携・形

駒同士の守り合い・攻めの協力関係を評価する。

- 金銀などが互いに守り合っているか
- 玉と守備駒が連結しているか
- 浮き駒・孤立駒があるか
- 攻撃駒が同じ地点・周辺地点へ協力しているか
- 重要駒に守備が集中しすぎ、別の箇所が薄くなっていないか

玉の守備は直近8マスだけで評価しない。直近8マスとその外周（概ね次の16マス）を別レイヤとして持ち、距離による重みの違いを設ける。また、守備価値は玉からの距離だけでなく、敵駒がどの側から到達できるか、大駒の射線が通るか、歩の衝突地点や侵入口がどこにあるかによって変える。

例えば居玉と、矢倉型で片側が構造的に閉じている局面では、同じ「玉周辺の守備駒数」でも意味が異なる。囲い名そのものを認識するのではなく、玉周辺の連結、外周の壁、開いている側面、敵攻撃駒の到達可能性を特徴量へ分解して機械判定する。

将来的には、駒をノード、効き・守備関係をエッジとする小さなグラフとして捉え、連結性や孤立を数値化する。Safety は主に「玉がどれだけ危険か」、Coordination は「守備駒同士がどう支え合っているか」を担当し、二重計上を避ける。

### 3. Space：空間支配

盤面をどちらが広く使えているかを見る。

- 自分だけが安全に使えるマス
- 相手だけが安全に使えるマス
- 前線や敵陣への進出余地
- 持ち駒を有効に打てる空間

将棋では持ち駒を盤上へ再投入できるため、チェス型の空間評価をそのまま使わず、「打てる空間」の価値を別に検討する。

### 4. Mobility / Freedom：自由度

現行Activityより広い概念として、将来の選択肢を評価する。

- 合法手数または軽量近似
- 有力な移動先の数
- 動けない・拘束された駒
- 大駒の通り
- 王の安全な逃げ道
- 将来成れる余地
- 持ち駒の有効な打ち場所

「現在何点得しているか」だけでなく、「次に選べる有力な選択肢をどれだけ持っているか」を見る。

### 5. Flexibility / Irreversibility：柔軟性・不可逆性

歩を突く、桂を跳ねる、駒を打つ、交換するなど、一度行うと元に戻しにくい決定を扱う。

- 手を指したことで消える有力な選択肢
- 形を決めすぎる手
- 持ち駒を盤上に固定することのコスト
- 交換によって局面の可能性が狭まるか広がるか

不可逆な手そのものを悪いとはしない。得られる利益との比較で扱う。

### 6. Local superiority：局所的な攻守の厚み

盤面全体の平均ではなく、戦いが起きている場所の密度を見る。

- 同一マス・近接マスへの攻撃枚数
- 攻撃駒と守備駒の局所的な価値合計
- 玉周辺の攻守比
- 攻め駒の集中と守備の分散

既存Pressureと重複しやすいため、追加時にはどの項目をPressure側から移すか明確にする。

## 評価値はベクトルとして保持する

内部では、最初から1個の総合点だけを作らず、例えば次のような内訳を保持する。

```text
Material       +120
KingSafety      -30
Pressure        +45
Danger          -10
Influence       +28
Coordination    +20
Space            +8
Mobility        +15
Flexibility      +6
```

最終的には探索が必要とする1個の数値へ統合するが、`EvaluationBreakdown` を拡張して各軸のraw値・重み適用後・上限適用後を確認できるようにする。

これにより、

- なぜその手を選んだか
- 新特徴が本当に棋力へ寄与したか
- 既存特徴と二重計上していないか
- 特定特徴の重みが暴走していないか

を追跡できる。

## 局面によって重みを変える

全局面を固定重みだけで評価し続けるのではなく、将来的には局面の性質を判定し、重みを変える。

例：

- 序盤：連携、自由度、空間、玉形を重視
- 中盤：駒得、効き、攻撃圧力、局所的な厚みを重視
- 守勢：玉安全、危険度、逃げ道、守備連携を重視
- 終盤：詰み・詰めろ・玉安全・手番速度を大幅に重視し、駒得の相対的重要度を下げる

最初から複雑な局面分類器を作らず、駒数、手数、玉周辺の攻撃密度、王手・詰み探索の状況など説明可能な指標から始める。

### 2026-10-08追加：局面進行度を数値化し、探索・評価・研究対象に共通利用する
オーナーの提案は、手数で序盤・中盤・終盤を固定分類するのではなく、盤上の駒と持ち駒、駒交換、攻守の接触、玉への脅威などから、その局面の進行段階を連続値として表すものである。初期設計では「進行度（0～100）」「詰みや強制手の切迫度（0～100）」「合法手・駒打ち等による読みの広がり（0～100）」を分けて診断する。重み・境界値は仮説であり実測比較前に採用値を確定しない。
進行度に応じて序盤の陣形・連携・自由度、中盤の攻守圧力・局所的優位、終盤の玉安全・詰めろ・手番の価値を滑らかに重み付けする。探索では序盤の詰み補助探索を機械的に毎回最大予算で実行せず、王手や玉への到達可能性など安価な事前判定で配分する。ただし実際に強制詰みが成立する例外局面を序盤という理由だけで無視しない。複雑度に応じて探索の配分も検討するが、現行200ms＋AdaptiveLongThinkとの比較は別変更として行う。
研究局面は再登場回数だけで選ばず、短時間と長時間での手の相違、損失の大きさ、再現性、研究結果の活用見込みと進行度によって優先する。最序盤の単純反復局面を高頻度という理由だけで大量研究しない。一方、重要な序盤分岐自体は排除しない。
実装順はまず進行度・切迫度・複雑度を表示するだけの診断から始め、次に詰み探索の配分、局面別評価重み、研究対象選別を個別に検証する。分類だけで強くなったと称さず、各差分を独立の比較で評価する。

## 同じ特徴を「どこで使うか」を管理する

特徴量を全部、最終評価の足し算へ入れない。

| 情報 | 主な役割 |
|---|---|
| 定跡 | 候補生成・優先度 |
| TT / history / killer等 | 探索効率 |
| 王手・詰み・駒取り | 戦術探索・探索延長・ordering |
| 駒得 | 静的評価の基準 |
| Safety / Danger | 静的評価、場合により探索延長判断 |
| Pressure / Influence | 静的評価、一部をorderingへ利用可能 |
| Coordination / Space / Mobility | 主に静的評価、軽量版はordering候補 |
| 自己対局の失敗履歴 | 重み調整、ordering改善、固定問題生成 |

同じ概念を複数箇所で使う場合は、目的を分け、同じ点数を重複加算しない。

## 自己対局から独自に強くなる仕組み

大量自己対局は勝率だけを見るのではなく、自作AI自身の弱点を抽出する材料にする。

### 敗局から問題集を作る

1. 自己対局を大量に行う。
2. 評価値が急落した局面、詰みを逃した局面、同じタイプの損失が発生した局面を抽出する。
3. その局面だけ通常より深く再探索する。
4. 実戦手と再探索手の差を記録する。
5. 類似した失敗を分類し、固定問題として蓄積する。
6. 評価・ordering・探索拡張のどこを直すべき問題か切り分ける。

これを「自分専用の問題集」として扱い、夜間自己対局の成果を翌日の改善候補へつなげる。

### 将来イベントの予測を補助課題にする

自己対局から自動的に正解を作れる予測課題も検討する。

- 数手以内に駒交換が起きるか
- 王手が発生するか
- 次に取られやすい駒は何か
- 成りが発生するか
- どちらの玉周辺の危険度が先に上がるか

これは直ちに最終評価へ加点するのではなく、局面理解用の補助特徴として精度を測ってから採用する。

## 強い外部AIの使い方

外部AIに引きずられないことと、外部基準で棋力を測ることを両立する。

基本方針：

- 外部AIとの対局は Elo 相当の外部棋力測定に使う。
- 自作AIと外部AIで候補手が大きく割れた局面を「要調査局面」として集める。
- 外部AIの指し手をそのまま正解として模倣する学習は行わない。現行の利用境界はR50に従う。
- 必要な場合は「外部AIが何を指したか」より、「自作AIの評価がどれだけ外れていたか」を診断に使う。
- 教師あり学習や知識蒸留は初期の将来案であり、採用済みの方式や外部AIの答えを取り込む許可ではない。学習対象はR50、方式の採用判断はR10に従う。

## 実装順

当面は次の順を候補とする。各段階は独立変更として比較する。

1. **Influence基盤**
   - 既存AttackMapを再利用・拡張し、升ごとの攻守枚数、効きの価値、支配差を診断できるようにする。
   - まず評価へ入れず、ログと固定テストで妥当性を確認する。

2. **Coordination**
   - 守り合い、浮き駒、玉と金銀の連結、攻撃駒の共同参加を数値化する。

3. **Space / Mobility**
   - 空間支配と自由度を分離して実装する。
   - 合法手生成を毎評価で呼ぶ高コスト設計は避け、AttackMapや軽量近似から始める。

4. **局面別重み**
   - 固定重みとのA/B比較ができるようにしたうえで、序中終盤・攻守による重み変更を導入する。

5. **自己対局の失敗局面マイニング**
   - 評価急落点・詰み逃し・繰り返す敗因を自動抽出し、固定問題化する。

6. **予測特徴・自動調整**
   - 十分なログが溜まった後、補助予測、SPSA等の重み最適化、局面別重みの学習を検討する。

## 採用判断

新しい評価軸は「それらしく見える」だけでは採用しない。

最低限、次を確認する。

- 固定局面で意図した方向に値が動く
- 180度回転＋色交換など既存の対称性を壊さない
- 既存特徴との二重計上を説明できる
- 1評価あたりの計算時間と探索ノード数への影響を測る
- 新特徴単体ON/OFFのablationを行う
- 同一CPU・同一持ち時間で100局以上、必要なら200局以上比較する
- 勝率だけでなく、特徴別内訳、典型的な改善局面・悪化局面を残す
- 探索改善と評価改善を同じ変更に混ぜない

## 目指す状態

最終的に一手を決める中心は探索である。

その周囲を、

```text
候補生成
  ↓
探索順
  ↓
反復深化・αβ・静止探索・詰み探索
  ↓
多面的な局面評価
  ↓
局面に応じた統合
  ↓
最善手
```

という構造にする。

駒得だけでも、特徴量の単純な足し算だけでもなく、**複数の将棋的な視点が役割分担し、その結果を探索が統合して一手を選ぶAI**を目指す。


### 2026-10-08：展開度を起点とする独立診断の候補実装

本人の提案：各駒が初期配置からどの程度離れたかを測る。本人は「よいと思います。進めてください」と応じ、検証母集団について「引き分けの局は省いてください」「入玉も」と明示した。

製品評価値・指し手は変更しない。独立した解析プログラムで①配置展開度（同種駒の初期位置への一対一最小距離対応、距離は最大5マスに制限）、②戦闘（持ち駒・敵駒への効き・双方の効きの交差）、③敵陣侵入と成駒、④玉への攻撃をそれぞれ0～100の試算値で記録する。重み・飽和係数・暫定総合進行度の係数は**初期仮説であり正式採用値ではない**。指標の内訳は保持する。現在の配置を測るので、移動後に戻った駒の過去の距離は加算しない。駒個体が持ち駒化し個体識別不能なため、駒種・色別の初期位置との対応を最小費用で割り当て、初期より同種駒数が増えた場合は余剰駒に上限距離を課す。

棋譜検証では、対局結果が引き分け・手数上限・千日手等で終わった局を**全局除外**する。また終了理由が入玉勝ち等の対局だけでなく、途中一度でも玉が敵陣3段に入った対局を**全局除外**する。通常の決着（詰み・投了等）で終わった合法棋譜のみを採用する。抽出条件を記録したうえで10手ごとの分布と局面差を比較する。既存のサンプルに旧版エンジンの対局を使う場合、正式現行版の棋力や現在の傾向を実測したとは扱わない。

独立プログラム：`tools/phase/phase_probe.cpp`、算定：`engine/strategy/phase_diagnostics.h`、棋譜分析：`tools/phase/analyze_games.py`。局面別の評価重み・詰み探索予算・研究優先順位は未変更。検証してから利用方法と係数を本人と決める。
