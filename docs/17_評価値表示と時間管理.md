# 評価値表示・反復深化・時間管理

## 出発点

v0.0.13のc03（Safety=50 / Pressure=150 / Activity=150 / Danger=200）を維持して、探索の深さと終了方法を改修した。やねうら王は従来どおりルール層だけに使う。

## 表示する評価値

`info depth 3 time 42 nodes 1234 score cp 120 pv 7g7f 3c3d 2g2f` の形式で、完了した探索の結果をGUIへ送る。

- `score cp`：思考開始時の手番側から見た点数。歩1枚を100とし、有利なら正、不利なら負。
- `score mate`：探索で確認できた詰み手数。自分が詰ませるなら正、詰まされるなら負。
- `depth`：全候補を読み終えた通常探索の深さ。半手（ply）単位。
- `pv`：最善と判断した読み筋。キャッシュからの復元では合法な途中までになる場合がある。
- `time`：このgoを受けてからの経過ミリ秒。深くなるたびに更新する。

`eval` の5本柱の内訳は従来どおり先手基準の静的評価である。先読み後のUSI scoreとは意味が異なり、内訳の合計を探索scoreとして表示しない。点数を勝率へ換算する機能はまだ設けない。

千日手による勝敗、王手でない合法手なしによる敗北などは、詰みとして表示しない。最初の深さを読み終える前に止まった場合は、合法手とdepth=0を返し、未確定のscoreを作らない。

## 反復深化

1-ply → 2-ply → 3-ply → … と順に読み、各深さが完了したときだけ最善手・評価・読み筋を更新する。4-ply以降は前回の最善手と内部局面の手を、次の探索の並べ替えに使う。3-plyまでは、浅い深さの読みを優先すると接触局面で探索が増える例があったため、v0.0.13の並べ替え順を維持する。

途中で停止した深さの部分結果は採用しない。着手はRAIIで戻し、中断しても盤面と千日手履歴を復元する。同点手の乱数は深さごとに余計に消費せず、同じseedを維持する。

旧固定3-ply実装は対照試験用に残す。今回の詰み点数には手数を含めるため、複数の詰みがあれば早い詰みを優先する。通常評価の同点規則は維持する。

## 探索条件

| 指定 | 動作 |
|---|---|
| `go depth N` | N-plyまで反復深化。上限64 |
| `go movetime N` | Nミリ秒から通信余裕を差し引いた時点で停止 |
| `go btime ... wtime ... byoyomi ...` | 手番側の残時間から予算を配分し、秒読みを加える |
| `go nodes N` | 探索ノード数を制限 |
| `go` | SearchDepth設定まで読む。既定3 |
| `go infinite` | stopまで継続。深さ上限に達した後もbestmoveは保留 |
| `go ponder` | 先読み。ponderhit前は時計を開始せずbestmoveを保留 |

複数の上限を指定した場合は、先に到達した上限で停止する。0ミリ秒を無制限として扱わない。

通常の時計予算の初期式は `残時間 / 30 + 秒読み + 加算時間×3/4`。movestogoの指定がある場合は30を置き換える。使用できる総時間を超えないようにし、最大10ms（小さな予算では10%）の余裕を引く。複雑な局面への追加配分は今後の改善課題である。

## 通信と中断

入力処理と探索を別スレッドにする。探索スレッドには局面を複製して渡し、同じPositionを複数スレッドから触らない。

- 思考中でもisreadyに応答する。
- stopで中断し、最後の完了結果を1回だけ返す。
- ponderhitで通常思考へ移り、時間予算を開始する。
- 新しいposition/goや設定変更では旧探索を停止・破棄してから処理する。
- quitや標準入力の終了でも探索スレッドを回収する。

## 千日手とキャッシュ

v0.0.15の静止探索ONでは、以下の浅い盤面共有条件を使わず、履歴を含むキーへ統一する。以下はv0.0.14および静止探索OFF時の方式である。詳細は[静止探索](18_静止探索.md)を参照する。

可変深度では探索中に繰り返しへ到達する機会が増える。盤面だけのキーで評価値を再利用すると、異なる履歴の千日手・連続王手を混同するおそれがある。

初期版は、入ってきた履歴に同一局面の重複がなく、探索の全体が3-ply以内なら、従来の盤面キーでスコアを共有する。この条件では、同じ手番の局面の再出現には少なくとも2-plyを要するため、3-plyの追加探索だけで4回目の出現には到達できない。

それ以外は、盤面の履歴全体を含めた64-bitキーを使う。同じ盤面でも異なる手順のスコアは共有しない。深い探索のTT共有機会は保守的な方式により減るため、今後、正しさを検証したうえで共有範囲を広げる。探索の各深さでTTの世代を更新し、浅い探索条件の値を深い探索へ流用しない。

前回反復の手・Experience Cacheは盤面キーによる並べ替えのヒントだけに使い、評価値の打切りには使わない。既に繰り返し履歴を含むrootではExperienceを無効化する。探索方式の署名を更新したので、v0.0.13の保存済みExperienceは今回の版で読み込まない。

## 比較と残る確認

旧比較プログラムの `go movetime 1` は、旧版では実際の1ms制限をしていなかった。新旧の条件がずれるため、比較の既定を `go depth 3` に変更した。時間制限の試験は `--go-command 'go movetime 100'` などを明示する。時間管理のない旧版との対局を、同じ時間制限の棋力比較とは扱わない。

USIの出力と応答は自動試験済み。Pixel/ShogiDroid2の画面表示は、ユーザーから実機確認の依頼があるときにAPKを作って確認する。

v0.0.15で[静止探索](18_静止探索.md)を導入し、駒の取り合いの途中で評価する問題を改善した。
